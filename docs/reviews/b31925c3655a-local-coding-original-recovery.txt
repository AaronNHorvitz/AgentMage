## Assessment

- **L1 repair (prior review).** `coding_cli_endpoint_transfer.rs:26-27` adds two checks:
  `symlink_metadata(root).is_dir()` (so a final-component symlink, a missing root or a non-directory
  refuses) and `canonicalize(root) == root` (ancestor symlinks, `.`/`..`, doubled or trailing
  slashes). Both run inside the existing loop, before `workflow::bounded`, so they come before
  `record::export_observed` and before the release confirmation.
  - The new regression asserts four things for 12 cases: no prompts, transcript beginning
    `Coding request failed` (no record emitted), events still 200 (run held) and
    `GET /v1/code/repository/apply` 428 (original apply unavailable).
  - My probe adds loops, dangling links, `/proc/self/root` and `..`. All of them refuse early.
  - Canonical roots also make the later `starts_with` overlap check sound against aliases.
  - Errors map to `Err(())`, with nothing panicking or leaked. The code reads no file contents and
    turns no alias into an accepted selection.
  - The comment, the guide and the evidence all describe the checks honestly as metadata-only and
    non-atomic. Native `verify_root` still runs before and after read consent.
- **L2 repair.** The new test is real end to end. For each review service (strict and checked),
  after decline-2 (read) and decline-3 (apply), it does the following:
  1. Drives `original` and compares the output with the server's exact `GET` state.
  2. Checks `pending`/`latest`.
  3. After a read decline only, runs `original-prepare` and requires exactly one `read <repo> <tree>`
     prompt.
  4. Runs `original-apply` (one exact `apply-original <sha>` prompt and a `write_preview` transcript)
     or `original-deny` (no prompt).
  5. Asserts `latest.outcome` (`committed`/`denied`) and `available_paths` (empty after commit,
     retained after deny).
  6. Requires a repeated `original-apply` to refuse with no prompt and an unchanged state.
  7. Shows events and release still 409 (no run restoration), the sentinels preserved and no
     upstream connection.

  That covers all 8 combinations claimed. The guide's new recovery text matches this behaviour.

- **Honesty and labelling.** The evidence states the limits accurately: synthetic creation

## Findings

No critical, high or medium findings.

- **L1 (low, ordering residual):** `platforms/local-api/src/coding_cli_endpoint_transfer.rs:15-38`
  and `:59-77`.
  - Problem: a canonical, existing directory that is not the held root (for example a mistyped
    sibling checkout) still passes preflight. Release is then offered and performed, and only the
    post-release `verify_root` refuses it. Reproduced above (`other`).
  - Impact: limited. The record was already emitted to stdout, the review service retains the
    owner, nothing is written, and the standalone commands now tested recover the transfer. But the
    process-held events and model ports are dropped for input that is wrong.
  - Why the client cannot catch it today: before release the client has no root identity to check
    against. `GET /v1/code/repository/apply` returns 428, and `checked_selection` carries no root
    digests.
  - Fix: expose the held repository and worktree root digests before release, for example in the
    endpoint selection or a control-only status. Then run `LinuxCodingReadScope::verify_root` on
    both arguments before `record::export_observed` and the release confirmation, and add the
    wrong-canonical-directory case to the invalid-input test.
  - Severity: same-row backlog.
- **L2 (low, usability/docs):** the refusal is a bare `Coding request failed`, with no reason and no
  way to tell an alias apart from other refusals.
  - On Fedora Kinoite, `/home` is a symlink to `var/home`, so the natural spelling of a home-directory
    checkout is non-canonical. It now refuses before release, which is correct and consistent with the
    launch-time canonical-root rule.
  - Neither `docs/guides/coding-original-apply.md:159-163` nor the standalone `original-apply` text
    tells the user to pass the canonical path.
  - Fix: add one guide sentence such as "pass the output of `realpath`; `/home/...` on Kinoite
    must be given as `/var/home/...`". Optionally print a fixed, content-free reason such as
    `root must be an existing canonical directory`.
  - Severity: same-row backlog.
- Carried forward unchanged: the base review's L1/L2 (extraction-refusal coverage) and earlier L3
  (combined native model-edit/test transfer). These remain same-row backlog.
- Out of scope (backlog, pre-existing since 2026-09-21, not in this diff):
  `docs/guides/codex-coding-implementation-brief.md` and several planning files name the external
  implementing tool. It is not branding or a product comparison in this increment, but it should be
  checked against the public-release naming rule before any release.
