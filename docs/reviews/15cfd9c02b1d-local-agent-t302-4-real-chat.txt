**L2 (low, measurement honesty): the first-text time hides reasoning generation.**
Location: `docs/evidence/t302-4-real-local-chat-2026-11-03.md:69` and `:75`; `platforms/linux-inference/src/local_chat.rs:403`.

- The model log shows turn 1 at 63 prompt tokens and 155 generated tokens (about 4.0 s of eval). The visible answer
  is 5 bytes. The decoder forwards only `delta.content`, so reasoning deltas are dropped silently.
- The 5.902 s first-text time is therefore mostly hidden reasoning, during which the API emitted nothing.
  "Upstream token usage: Unavailable" is true for the API, but server-reported counts exist in the private log.
- Fix: in the next evidence update, state the server-diagnostic token counts (63/155, 88/5) and that first-text
  latency includes undelivered reasoning. At T-303/T-309, decide whether reasoning progress or keepalive events are
  needed so long reasoning does not trip client idle timeouts.

**L3 (low, coverage): incremental visible streaming was not observed on the real model.**

- Each real turn produced exactly one text fragment. Incremental delivery rests on the synthetic socket contracts.
  The evidence discloses this (line 55 onward).
- The real run does show that the decoder tolerates real server streaming framing, including the many reasoning
  deltas it ignored.
- Fix: use a prompt with a multi-token visible answer in a later measurement, for example the T-311 baseline.

**L4 (low, client hardening; not reachable through the reviewed API serializer).**
Location: `scripts/local_chat_smoke.py:115`, `:188`, `:202`, `:63`.

- `json.loads` accepts duplicate keys, last one wins: `{"type":"complete","finish":"length","finish":"stop"}` was
  accepted as a normal stop in my probe. Non-`ValueError` failures (RecursionError from deep nesting, AttributeError
  from a non-object status) escape the handled set. They still save a FAIL report when raised in the main body,
  but they print a traceback (no secrets). An AttributeError inside the cleanup block would skip writing the report.
- The 130 s per-read socket timeout plus a between-lines deadline check lets a slow-drip single line overrun the
  130 s deadline. The API's own bounds limit this.
- Fix: use `object_pairs_hook` to reject duplicate keys, check `isinstance(..., dict)` on JSON replies, catch
  `Exception` in the measurement and cleanup paths, and compute the socket timeout from the remaining deadline.

**L5 (low, private measurement infrastructure): the model sandbox can see API tokens and records.**
Location: private `run.py` / `model-command.json` `--bind <run-dir> /run/agentmage`.

- The whole run directory is bound read-write into the model sandbox. That directory later receives
  `auth/control.token`, `auth/client.token` and `record/`. A compromised runtime could read the API tokens or alter
  records while it runs. Its network namespace is unshared, so it has no path to the API.
- This is uncommitted measurement infrastructure with a hash-verified runtime, so it is not a product boundary.
- Fix: bind only a dedicated subdirectory holding the model key and socket.

Earlier component lows (T-302.1 L1/L4–L8, T-302.2 L1/L3/L4, T-302.3 L1–L4) remain at T-309 as recorded.
