## Code review

- `kernel/engine/src/runtime_loop/completion_claim.rs:108`: the new
  `result.finish != EndpointModelFinish::Stop` check comes before every other binding
  check and refuses with `Invalid`. `EndpointModelFinish` (contracts `endpoint_model.rs:126`)
  has exactly `Stop` and `OutputTokenLimit`. The inequality form is fail-closed for any
  variant added later.
- `Claim::Endpoint` is a private enum variant, and `RuntimeCompletionClaim::endpoint` is its
  only constructor (grep over `kernel/` and `shells/`). No other production path turns
  endpoint text into a completion proposal, so the stop requirement cannot be bypassed
  through a sibling constructor. No production caller yet invokes
  `RuntimeCompletionClaim::endpoint`. That is consistent with the record's statement that
  full endpoint coordinator/API wiring is still open.
- Native parity: the native path already refuses incomplete finishes
  (`model_runtime.rs:1066`, `!finish_reason.is_complete()`; covered by
  `coding_incomplete_model_output_cannot_enter_protocol_recovery`). The endpoint path is
  now consistent with it.
- Transport observation is unchanged: the test asserts that `turn.result().finish` keeps
  both values for identical bytes. Only claim construction differs.
- Registry test: `VerifierRegistry::verify` (`agent_verifier`, lines 109–114) compares
  task, proposal, snapshot and revision. The three candidates share task, snapshot and
  revision, so the six `ContextMismatch` refusals come from proposal identity alone. That
  identity is the SHA-256 of the serialized turn, which carries the run binding, plus the
  payload. Each candidate's own registry accepts it, which rules out a vacuous refusal. The
  test asserts disposition `NoOp` and a passing postcondition for each candidate.
- Test-helper change in `coding_verifier.rs`: the only removed line is the hard-coded
  `EndpointModelFinish::Stop` literal, now parameterized. `completion_turn` still passes
  `Stop`, so existing test bodies behave the same. final.py proves this textually, and the
  audit shows all predecessor passes are retained.
- No change to native admission, model dispatch, turn recording, verifier predicates,
  registry rules, effect authority, tool confinement, the sandbox, network or Git push. No
  new confinement surface, so no escape attempt applies to this diff. The previously
  reviewed boundaries are unchanged by the diff.
- Evaluation integrity: no frozen-task, hidden, held-out, scorer, threshold, ignore or
  prompt content is touched, and no score or model number is claimed.
- Supply chain: no dependency, lockfile or SBOM change.
