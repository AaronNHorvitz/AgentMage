### L1 (low): the failure-cause split is still partly candidate-selected and coarse

The pass/fail result and the denominator are unaffected. Only the recorded
`cause` is imprecise, in three ways:

1. The fixed tag is accepted for every result type at
   `scripts/coding_eval_oracle_worker.py:124-126`. This includes bool, path and
   bool-map tasks, whose coverage declares no adapter policy. In my probe
   `forge-tag-bool-015`, dev-015 is reported as `cause: adapter_policy` with no
   `adapter_policy` coverage entry. The guide and evidence do say that a candidate
   can forge either tag, and only to fail itself.
2. Some plain wrong answers are reported as adapter policy, not test failure. At
   `worker.py:263`, any non-list/tuple helper result gets the policy tag,
   including `None` or a string. At `worker.py:336-339`, so does a `None` or
   string `passed` value. These are not "statement-legal values the adapter
   cannot carry".
3. Candidate-side exceptions and missing report fields still crash the candidate
   and appear as `protocol`. Examples are a helper raising `RuntimeError` and a
   report without `checks` (`worker.py:336`), which the legacy grader passes but
   the statement forbids. So `protocol` still covers both candidate defects and
   wire corruption.

Fix before generated scoring, because failure causes feed published results:

- Accept the policy tag only for result types that list `adapter_policy`
  coverage, and treat it as `protocol` elsewhere.
- Transport JSON-representable wrong values (`None`, `str`, `int`) as data so the
  original assertion decides.
- Add one fixed `candidate_exception` tag with its own cause for candidate-side
  exceptions in the worker loop.
