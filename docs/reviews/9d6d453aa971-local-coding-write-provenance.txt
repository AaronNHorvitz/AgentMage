## Review

**Proof construction (coding_workspace_write_proof.rs).**

- `LinuxCodingAppliedWrite` has no derives at all: no Clone, Serialize, Deserialize or Default. Its
  fields are private, and its only constructor, `from_native_result`, is `pub(super)`, so only the write module
  can call it.
- The single product caller (`apply_retaining_proof`, write.rs:311) passes the owner's own cloned
  `ShadowChangeSet` and approval, plus the `WriteTransactionResult` returned directly by `execute()`. No
  JSON, path, receipt or saved record can reach it.
- It checks all of the following:
  - the outcome is Committed;
  - the approval and change-set digests match;
  - the transaction id;
  - the grant id;
  - the issued revision, the issued canonical-grant digest and consumed = issued + 1;
  - the recomputed approval binding;
  - `verify_write_receipts` passes;
  - the Verified op→(pre, post) map exactly equals the change-set map, and every receipt carries the same
    transaction, grant and pre/postimage.
- The final receipt digest is retained as the application identity.

**Projection (commit_review.rs:33).**

- Before any file read it requires held roots (`verify_apply_roots`) and that the proof's root equals the
  held created root.
- The projected files must match `created.edits` one-to-one, with the same preimage and postimage and no
  created mode.
- It then reads fresh bytes through the held scope, compares them with the postimages, and re-verifies the
  roots.
- The planner (commit_review.rs:154-165) rebuilds the projection from the packet's purpose labels and
  requires `ReviewableChangeSet` equality. The derive is PartialEq over all fields, including both receipt
  identities, files_sha256 and the plan and intent digests. This happens before `check_completion_validation`
  and before any Git observation. The resealed-packet test asserts that Git is never invoked.

**Retirement before dispatch.**

| Dispatch site | Where the proof is retired |
| --- | --- |
| Manual or endpoint `decide_edit` | edit.rs:168, before `apply_retaining_proof`. The endpoint boundary pre-issues the approval and then calls `decide_edit`, so it takes this same path. |
| Runtime write driver | runtime.rs:365, after candidate validation and before `native.apply` |
| Runtime create driver | create.rs:215, at the same point |
| Original transfer | apply.rs:253, before `write.apply` |
| Native worktree creation | repository.rs:487 |

Error branches before dispatch return without any effect. The proof is retained again only when the outcome
is `committed` and the post-check succeeds (edit.rs:210-216).

**Coverage and cumulative lineage.** Three cases refuse:

- a later transaction that covers only part of the cumulative edits (the count does not match);
- re-editing the same path (the first preimage differs from the latest transaction's preimage);
- runtime writes followed by a manual re-edit (the proof was retired, or its preimage is the runtime
  postimage, not the original).

A runtime-written byte cannot be passed off under a later manual proof.

**Kernel-side checks.** The kernel's `issue_write_grant` independently rejects decision hashes that do not
match the change set and preview (write_approval.rs:770-772). The issuer is a per-pending in-memory
`GrantIssuer`.

## Findings

No critical, high or medium findings.

- **L1 (low), platforms/linux/src/coding_workspace_write.rs:318-320.**
  - Problem: `apply_retaining_proof` now calls `approve()` before `execute()` runs its prechecks for root
    identity, change-set and preview equality, expiry and deadline. Before this commit, the grant was issued
    only after those checks.
  - Impact: none observable. The kernel re-checks the digests, the issuer lives in memory only, and `self` is
    consumed. Still, a root-drift refusal now issues and discards a grant first.
  - Fix: move the precheck into a shared helper that runs before `approve()`, or clone the approval after
    `execute`'s precheck.
- **L2 (low), platforms/linux/src/coding_repository_runtime.rs:143-152.**
  - Problem: poisoned-owner recovery in `try_into_repository` clears `created` but leaves
    `applied_write` (and `edit_result`) in place.
  - Impact: unreachable today. Capture requires `created`, and the only product path that sets `created`
    again is native creation, which clears the proof.
  - Fix: add `owner.applied_write = None;` there, as defence in depth.
- **L3 (low), coding_repository_commit_review_tests.rs and coding_workspace_write_proof.rs tests.**
  - Gap 1: no regression projects a multi-file proof through `capture_applied_write_review`. Multi-op
    construction is exercised only implicitly, by the 16-file commit.
  - Gap 2: no test drives a `from_native_result` refusal through `decide_edit` after a committed write. That
    path fails closed by design (error, effect unknown, lineage removed) but is unasserted.
  - Fix: add a 2-file projection test, and a test-only result-alteration hook asserting the error, the
    missing proof and the missing lineage.
