## Design assessment

**Token construction.** `CompletionReady` (`shells/host/src/coding_endpoint_edit_previews.rs:64-96`)
has private fields and no `Clone`, `Debug`, `Serialize` or `Deserialize`. It has two constructors:
- the production construction inside `next()` (lines 302-309), reached only after the original
  owner is `Ready`, `check_completion_validation()` has succeeded and both controls have been
  re-sampled;
- `synthetic_for_framing`, which is `#[cfg(test)]`.

**Consumption.** `into_check` consumes the token and compares the complete request and the turn.
`prepare_coding_completion` (`coding_endpoint_edit_generation.rs:204-237`) consumes it as its
first statement, before the registry, context or transport preparation. It then installs the
returned check on the completion-only turn. This resolves 8aa L2: the framer can no longer be
called without the original owner's token.

**The installed check.** It is the original owner's `completion_check()`. That closure inspects
current shared state (`next`, `owner`, both controls, and `check_completion_validation`), not a
captured pass flag.

**Edit and Test turns.** I checked whether a model could emit a completion claim in an Edit or Test
turn and so avoid the token. Both turns attach a trusted `with_tool_preparation` callback. Its
refusal is terminal (`runtime.proposal.preparation-refused`, coordinator around lines 711-748), so
no unchecked completion path exists. This was not changed by this commit.

**Confinement and data handling.** This commit changes no confinement boundary: no new filesystem,
command, network or approval path. The token holds a cloned request in process memory only and has
no `Debug`, so it cannot be logged by accident.

**Claims.** The claims of no new executor, grant, effect, wire field or source disclosure match the
diff. Both verification flags and both completion verifiers are unchanged.

## Findings

No critical, high or medium findings.

- **L1 (low, test precision / comment overclaim):** `shells/host/src/coding_endpoint_edit_cycle_tests.rs:164-166`
  and `:170-172`.
  - **The overclaim.** The comment says that keeping the old seal in the "request" case proves
    "that the token binds the complete request, not just its hash". It does not.
  - **Why.** The substituted request keeps a stale `request_sha256`. `CodingEndpointContext::completion_only`
    then refuses it on its own, through `verify_runtime_endpoint_run_request`
    (`kernel/engine/src/runtime_coordinator/endpoint.rs:20-30`, `DigestMismatch` → `Invalid`).
  - **Reproduction.** Mutation 4: with `self.request.as_ref() != input.request` deleted from
    `into_check` (`coding_endpoint_edit_previews.rs:75`), the test still passes. The token's
    request clause is untested.
  - **Impact.** The production caller passes the same `input` it issued the token for, and the
    substitution is still refused before transport. This is a gap in defence in depth and test
    precision, not a reachable bypass.
  - **Fix.** Give the "request" case a validly resealed substitute: change the objective, zero
    `request_sha256`, recompute it with the canonical digest, then assert `Invalid`. Alternatively,
    call `ready.into_check(&input)` directly and assert `Err(Invalid)`. Either way, correct the
    comment. Backlog, same row.
- **L2 (low, carried; acknowledged by the builder):** `shells/host/src/coding_endpoint_edit_previews.rs:304-308`.
  - **The gap.** Positive production issuance is still unobserved. If `next()` issued its token
    with a no-op check instead of `self.completion_check()`, no test would fail.
  - **Why.** Only `#[cfg(test)]` issuance reaches the framer in tests, and the production
    `Next::Completion` path needs a native linked pass, which T-301.1 blocks.
  - **Disclosure.** The evidence, TASKS.md and the request state this openly. It remains backlog
    for the native workflow.
- **Wording note (no finding).** The evidence says "Removing the framer's installation would fail the
  invocation assertion". In my mutation run the test fails one line earlier, at the coordinator
  `unwrap()`. Removal is detected either way.

Earlier same-row lows, other than those resolved here (8aa L2 and L3; d0d L1 and L2 as far as the
