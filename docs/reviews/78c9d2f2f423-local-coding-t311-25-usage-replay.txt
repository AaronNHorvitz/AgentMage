## Findings

There are no critical, high or medium findings.

### L1 (low, latent; new): changes to the owned mock's history by the trusted test are silently overwritten

- **Location:** `scripts/coding_eval_oracle_worker.py:837-841`. The owned branch returns without
  comparing the current history to the last replay. Lines 883-885 then reset and replay the
  cumulative history. Line 843 checks only `call_args_list`, so earlier child or attribute calls
  (`mock_calls`) are not treated as unowned history.
- **Reproduction:** unit probes A, B and C above.
  - A trusted `reset_mock()` followed by a cache assertion becomes a false fail.
  - A trusted direct call is erased, which can produce a false pass or a false fail with
    count-based assertions.
- **Reasoning:** this is the same history-loss class as T-311.24 L2. The repair covers only
  cross-instance sharing and history that exists before ownership. Neither the guide nor the
  coverage list discloses this case.
- **Fix:** before generated admission or before selecting any new usage method:
  - Store a snapshot of `transport.mock_calls` after each replay.
  - In the owned branch, refuse with the sticky policy outcome if the current `mock_calls`
    differ from that snapshot.
  - Use `mock_calls` rather than `call_args_list` for the check before ownership.
  - Add tests for reset, direct-call and child-call cases.

### L2 (low, disclosed; concrete false pass): candidate mutation of the message list is not propagated

- **Location:** `scripts/coding_eval_oracle_worker.py:940`. `roots[handle][:] = messages`
  restores the trusted snapshot. The limit is disclosed as coverage
  `candidate-message-mutation-roundtrip` (`scripts/coding_eval_oracle.py:97`) and in the guide
  (`docs/guides/coding-evaluation-oracle.md:50`).
- **Reproduction:** probe `mutates-input`. The oracle passes; the original in-process grader
  fails with `Called 2 times`. v23 had the same behaviour, so this is not a regression.
- **Reasoning:** the disclosure ("can change verdicts") is accurate. The concrete direction,
  though, is a false pass, not just an ungraded item.
- **Fix:** before generated admission, either:
  - return the candidate-side root's packed contents after each call and apply them in place to
    the trusted list; or
  - when the post-call root differs from the snapshot sent, return the sticky adapter-policy
    outcome.

### L3 (low, pre-existing; part of the carried PurePath/subclass policy): trusted-side encoding refusals are not sticky

- **Location:** `scripts/coding_eval_oracle_worker.py:879`. `pack_usage_value` raises
  `AdapterPolicyError`, a `ValueError` subclass, before `RemoteFunction.__call__` is entered. So
  `policy_failed` is never set.
- **Reproduction:** scenario E.
- **Reasoning:** a trusted `assertRaises(ValueError)` around such a call would pass without the
  candidate running. This contradicts the general "sticky refusal" property, although the
  evidence states that property only for replay refusals.
- **Fix:** wrap argument packing in `invoke` in `try/except AdapterPolicyError: refuse()`.
