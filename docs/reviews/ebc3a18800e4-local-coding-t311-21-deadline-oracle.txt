## Findings

### M1 (medium): a refused dev-026 `COMMANDS` prerequisite is misreported as `infrastructure`, and its counts and flags are discarded

- **Location:**
  - `scripts/coding_eval_oracle.py:285`: the `result_record` zero-test exemption covers only
    `observe_case_roots`.
  - `scripts/coding_eval_oracle_worker.py:1053-1054` adds the new `observe_commands` prerequisite.
  - `scripts/coding_eval_oracle.py:45` defines `SUPPORTED["dev-026"]`.
- **Mechanism:**
  1. The candidate refuses the prerequisite. Its `COMMANDS` is missing, has an unsupported shape (for
     example dict records, or an empty argv), or raises on access.
  2. The worker writes a valid `tests.json` with `tests: 0`, `calls: 1` and the sticky
     `adapter_policy_failed` or `candidate_exception_failed` flag.
  3. `result_record` accepts a zero-test record only for `observe_case_roots` tasks. For dev-026 it
     raises `oracle.invalid-result-record`.
  4. `grade_case` catches this and sets `record = None`. `grade` then reports `cause: "infrastructure"`
     with `tests`, `calls` and all flags `null`, and publishes no `tests.json`.
- **Reproduction:** `$R/prereq-probes.py`, run through build-slot with the same synthetic-probe admission
  patch the builder's tests use.

  | Candidate change | Wire result | Report |
  | --- | --- | --- |
  | `COMMANDS = [{'id': …, 'argv': …}]` | `{"adapter_policy":true}` | cause infrastructure, tests/calls null, no tests.json |
  | `del COMMANDS` | `{"adapter_policy":true}` | same |
  | `del COMMANDS` plus a raising module `__getattr__` | `{"candidate_exception":true}` | same |
  | appended `('x', ())` | `{"adapter_policy":true}` | same |
  | Control: dev-022 `CASE_ROOTS = {'case': print}` | — | cause adapter_policy, tests 0, calls 1, flag true, tests.json published |

- **Impact:**
  - Candidate-caused refusals are labelled as harness faults, and the raw counts for those attempts are
    lost.
  - This contradicts the row's own claims that unsupported containers are adapter policy (guide line
    358; evidence line 29: "Unsupported values are adapter policy").
  - It breaks the cause/count rule already established for prerequisite observations (guide lines
    550-552).
  - A future scorer that retries or excludes `infrastructure` attempts would let a candidate turn its
    own failure into an excluded attempt.
  - No test covers a refused `COMMANDS` prerequisite.
  - The attempt is still counted as failed and cannot pass, so this is not high.
- **Fix:**
  1. Generalise the exemption at `scripts/coding_eval_oracle.py:285` to any declared prerequisite, for
     example `SUPPORTED[task["id"]].get("observe_case_roots") or SUPPORTED[task["id"]].get("observe_commands")`,
     with the same `calls == 1`, zero-count and sticky-flag conditions.
  2. Update guide lines 550-552 to name the command-declaration prerequisite.
  3. Add a real-namespace test asserting `adapter_policy` for deleted and unsupported `COMMANDS`, and
     `candidate_exception` for a raising access. Each case should have tests 0, calls 1, a published
     `tests.json` and `control_attempts` 1/0/1, with no private payload in the wire log.
