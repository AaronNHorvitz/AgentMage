## Findings

Low findings (same-row backlog; they do not block):

- **L1** — `platforms/linux/src/coding_repository_commit_review_tests.rs:1752`.
  - Problem: `candidate_checker_public_native_path_keeps_artifact_admission_and_does_not_invoke_checker`
    only checks the error code when `LinuxGitArtifact::verify("/usr/bin/git")` refuses. On a host
    where Git is admitted, it asserts only that the checker panic is not reached and that some error
    happened. It does not pin which refusal occurred.
  - Fix: assert an explicit expected code in the admitted branch as well. For example, the
    synthetic-fixture `code.commit.git-state` or the equivalent native refusal.
- **L2** — `platforms/linux/src/coding_repository_commit_review.rs:200-206`.
  - Problem: if cancellation is requested while the checker runs and the checker then returns
    `Rejected` or `Unavailable`, the caller sees the checker code, not `code.commit.review-cancelled`.
    This is safe either way, because the call stops in both cases, but cancellation is not reported
    consistently.
  - Fix: run `check_cancelled()` before mapping a checker failure, or document that the checker code
    takes precedence.
