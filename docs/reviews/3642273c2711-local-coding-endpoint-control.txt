## Assessment of the claims

- **No renewal.** `DispatchControl::remaining` (`platforms/linux-inference/src/local_chat_transport.rs:716-737`)
  computes `min(owner, previous - elapsed)`, refuses on zero, and stores the narrowed value. This
  matches the contract's no-renewal requirement even for a broken owner. The `RunControl`, which
  reports a constant, and `NarrowOnce` fixtures exercise exactly this.
- **Independent limits.** Original total and idle limits stay independent in `Wire::check`
  (`:767-785`): run remaining, total, idle and `IO_TICK` are min'd, and none can be zero. The
  `set_*_timeout(Some(0))` failure mode is therefore unreachable. The connect timeout is also
  bounded by run remaining (`:580`).
- **Polling points.** Polling happens before connect (`DispatchControl::new`, and `:580`), on every
  socket wait (`fill`/`write_all`→`check`), before and after each decoded event and callback, and
  after framed body plus actual EOF (`:562`, `:330-331`). EOF is mandatory after framed bodies
  (`:1053-1056`). The stalled-EOF fixtures are therefore deterministic and cannot race to success.
- **Stops.** A stop maps to `TransportError::OperationStopped(stop)`, whose code is the closed
  `model.operation.*` label. A stop never touches `ChatCancellation`, and the tests assert
  `!cancel.is_cancelled()`. No result is constructed on the error path, so there is no usage or
  exchange.
- **Frozen request.** Body, binding, transport and credential are unchanged: `execute_inner` sends
  `self.body` with `self.binding` through the same `self.transport`. The success fixture
  independently hashes the transmitted body and text, and checks that usage, verified tokens and
  memory are null.
- **API deadline.** The control is created at `platforms/local-api/src/lib.rs:1119`, before
  `headers()` and the context `event`, so model entry cannot restart it. Socket writes there are
  bounded by `WRITE_TIME` (250 ms), so publication cannot block indefinitely. The allowance equals
  the prepared `total_timeout`, so the run deadline is at least as tight as the transport's own
  total. Preparation, approval and repair-receipt consumption (`coding_repair_api.rs:71`) are
  outside it. A stop after consumption is not refunded, the same as any other dispatch failure, as
  claimed.
- **Rounding.** `remaining.as_nanos().div_ceil(1_000_000)` rounds a positive fractional
  millisecond up and refuses zero, and the unit test checks it.
- **Honest labelling.** The evidence and guide say the peers are synthetic, that there is no
  route-level backpressure or expiry fixture, and that there is no native coordinator admission,
  resource ledger, native workflow, model or score. These match what I observed. Callbacks are
  correctly described as non-preemptible.
- **Confinement.** Unchanged. The transport gains no network destination, credential path, tool,
  child process or retry. Endpoint approval checks are untouched.
- **Supply chain.** There are no Cargo or lock changes (`final.py` asserts an empty diff).
- **Privacy and branding.** Added lines contain no private host path, username, hostname,
  credential, email or sibling-project name, and no other agent product or trademark. `/lane/...`
  paths appear only inside the byte-identical retained review. They are lane placeholders with no

- **L2 (low, diagnostic labelling)** at `platforms/linux-inference/src/local_chat_transport.rs:580-582`.
  When run remaining is the binding bound on `connect_timeout` (the final ≤50 ms of the
  allowance), a connect expiry maps through `io_error` to `chat.transport.timeout` rather than
  `model.operation.timed-out`. It is still refused with no completion, but under the wrong closed
  label. Fix: on a connect `TimedOut`/`WouldBlock`, re-poll `control.remaining()` and return its
  stop if there is one.
- **L3 (low, efficiency for the future coordinator composition)** at
  `platforms/linux-inference/src/local_chat_transport.rs:811-812` and `:847-848`. `byte()`→`fill()`
  calls `check()`, and therefore the owner's `remaining_ms()`, once per byte of header and
  chunk-size lines, up to `MAX_HEADERS` = 16 KiB. With `ProposalDispatchControl` this costs almost
  nothing. The coordinator's `RuntimePhaseControl` instead observes its cancellation probe and
  clock on each call. Fix: poll the owner only before a socket wait (an empty buffer) and around
  decoded events.
