## Root cause of the incomplete verify2 run (limitation 2): resolved by this review

Git 2.55.0 on this host starts detached auto-maintenance after `git commit` in
`initialize_grading_repository`. That maintenance packs ~713 loose objects and removes them. It runs
on the host, outside the sandbox and outside the evaluator's process group, while the worker runs
and while `TemporaryDirectory` removes the tree.

Polling after the function returned showed pack activity at 0.051–0.059 s and all loose objects
removed by 0.176–0.191 s, in 3 of 3 trials. With `-c maintenance.auto=false -c gc.auto=0` there
were no packs and 713 loose objects remained after 3 s.

When grading ends inside that window, `shutil.rmtree` fails. The captured traceback was:

```text
OSError: [Errno 39] Directory not empty: '/lane/state/tmp/agentmage-eval-…/workspace'
```

`main()` turns this into the generic exit 2 and loses the traceback. The builder's leftover
`agentmage-eval-xg109p4j` contains only `.git/objects/pack/tmp_rev_bfBOiG`, written at
04:15:21.809. That is the verify2 timestamp and a maintenance artefact.

| 4 runs, same wrapper | Only the grading Git invocations given the two `-c` options | 4 of 4 passed |

## Findings

### M1 (medium): grading Git repository is mutated by an unowned detached host process; nondeterministic crash

Locations:

- `scripts/coding_eval.py:259-273`: grading repository initialisation.
- `scripts/coding_eval.py:280`: temporary-directory cleanup.
- `scripts/coding_eval.py:424-425`: generic exit-2 handler that discards the cause.

Claims contradicted:

- `docs/guides/coding-evaluation.md:37`: "fresh, read-only Git repository".
- `docs/evidence/t311-1-development-evaluator-2026-11-03.md:21`: "It is read-only during testing".

Reproduction: as above. 3 of 6 unchanged runs crashed (including 1 of 2 documented one-command runs
by this reviewer); 4 of 4 passed with maintenance disabled.

Impact:

- The documented one-command verifier fails at a high rate, so it is not reliably re-runnable.
  At 30 tasks × 2 cases it would almost never finish.
- A host-side Git process outlives the grade and rewrites `.git/objects` while Git-dependent
  hidden tests (dev-001) run. That makes grading input nondeterministic and breaks the stated
  read-only property.
- Crashes leave partial private temp trees containing the projection and reference source; four
  remain in `/lane/state/tmp`.
- One case's infrastructure exception aborts the whole run instead of being recorded as that case's
  `infrastructure` failure.

It fails closed (no aggregate PASS is produced), so it is not high.

Fix:

1. Pass `-c maintenance.auto=false -c gc.auto=0` (or the equivalent `GIT_CONFIG_COUNT` environment)
   to every grading Git invocation.
2. Add a regression test showing the object store is unchanged ≥1 s after
   `initialize_grading_repository` returns.
3. Print the fixed `EvaluationError` code and exception type in the refusal message. The codes
   carry no task content.
4. Correct the evidence's "unresolved" note.

### M2 (medium): all three frozen statements omit interface facts their hidden tests require; tasks are not solvable from the statement

Location: `scripts/coding_eval.py:41-47, 59-64, 76-81` (statements), frozen by the fingerprint test.

Each hidden test needs names or literals that appear in neither the statement nor the base source.
Checked with `git show <base|reference>:<source> | grep -c` and `git grep` over each base projection:

- **dev-001:** `coding_harness.untracked_file_identities(root)` returning rows with keys
  `path`/`bytes`/`sha256`.
  - Error codes `source-inventory-alias` and `source-inventory-limit`.
  - Identity keys `untracked_files` and `untracked_files_sha256`, defined as SHA-256 of
    `json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=True)`.
  - Enumeration through a single NUL-separated `subprocess.run`, which the test mocks.
- **dev-002:** `harness.MODEL_CHOICES` and `harness._model_request_diagnosis(arguments)` returning
  the exact dict `{"selection", "observation": "owned-process-arguments", "serving": "not-observed",
  "qualification": "not-assessed"}`.
  - `diagnose()` output must carry `model_request` and `scope: "development-diagnostics-only"`.
  - It must rename `profile_id` to `fixture_profile_id` and drop top-level `qualification`.
- **dev-003:** a new `gate.observe_exit(process)`, called directly and patched by the cleanup test.

A candidate that implements each statement correctly would still fail these tests. Base-fail and
reference-pass discrimination does not detect this. The bad statements are protected against
correction by the frozen fingerprint and the comment "never rewrite these tests or pins". As a
result, the advertised `prepare` → edit-from-statement → `score` flow and any later model baseline
would measure identifier guessing rather than coding.

No model measurement has used these tasks yet, so correcting them now is not tuning and weakens no
threshold.

Fix:

1. Before any model attempt, extend each statement with an explicit interface contract (names,
   signatures, return keys, error codes and canonical encodings the hidden test checks). Hidden
   tests stay unchanged. Re-pin the fingerprint with a recorded pre-measurement correction, or add
   corrected task IDs and retire these.
2. Add an automated check: every module attribute referenced by a hidden test that is absent from
   the base source must be named in the statement.

### L1 (low): candidate can forge a passing result (limitation 3, confirmed)

Location: `scripts/coding_eval.py:200-218` (driver in the candidate's interpreter);
`docs/guides/coding-evaluation.md:80` ("Exit 0 means all pinned tests passed").

Reproduction: the five-line append above gives exit 0 with an empty log.

This is documented (guide lines 111-115; evidence "Remaining work"), and this row scores only
trusted historical bytes, so it is backlog for this row. It becomes **high** if any model-generated
candidate score is reported or entered on a scoreboard before it is fixed.

Fix:

1. Qualify the "Exit 0" sentence.
2. Cross-check `tests.json` against the raw verbose log (expected test IDs and `Ran N` / `OK`).
3. Move result production out of the candidate's interpreter, for example per-test subprocesses
   with results returned over a parent-owned descriptor, before T-311 baseline scoring.

### L2 (low): resource bounds are per process only

Locations: `scripts/coding_eval.py:221-225`; `--tmpfs /tmp` and the writable `/output` in
`sandbox_command`.

There is no `RLIMIT_NPROC`, no total-memory or tmpfs cap, and no output-directory size cap. Within
the 90-second deadline, a hostile candidate can fork many 512 MiB processes or fill host disk (many
32 MiB files) or RAM (tmpfs). The address-space limitation is partly documented. Inputs are trusted
in this row.

Fix: add a cgroup or `systemd-run --user --scope` memory/pids limit, or at least
`RLIMIT_NPROC` and `--size` on the tmpfs and a quota on results, before generated candidates.

### L3 (low): environment-specific boundary assertion

Location: `tests/test_coding_eval.py:253` asserts `/lane` is absent. That is trivially true on any
host without that lane path, and the test does not check the repository or home.

Fix: assert that `str(evaluation.ROOT)` and the invoking user's home directory are not visible, and
that `/proc/self/environ` holds only the allowed keys.
