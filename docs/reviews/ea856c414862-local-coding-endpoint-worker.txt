## Assessment

### Confinement and trust boundary

- **Who controls the choice.** `worker_trust` comes only from the private launch document, which is read through
  `private_bytes`. That requires:
  - an absolute path with a canonical parent;
  - `O_NOFOLLOW`;
  - the effective UID as owner, mode 0600 and one link;
  - a size of at most 1 MiB.

  The document is not an HTTP, model or tool argument. A model output, document or web page cannot select it.
  - The typed enum plus the shape guard at `coding_endpoint_launch.rs:119-121` accept only the two snake_case
    strings.
  - Duplicate keys fail typed deserialization.
  - The probe confirms that the object, null and wrong-case forms refuse.
- **Who can exploit it.** Development trust admits a worker that its owner can write. Exploiting that requires the
  same UID, which could equally rewrite the 0600 launch file. So it adds no new attacker. The worker still runs only
  from a sealed memfd snapshot inside the unchanged bwrap/seccomp/offline runner, and the guide labels it honestly as
  not production authentication.
- **The selector** (`sandbox.rs:1381-1398`):
  - It is a closed compiled mapping on the canonical `current_exe` basename.
  - Its byte-exact `as_os_str` equality runs before any filesystem access.
  - The original `development_worker_artifact_kind` then applies:
    - canonicality;
    - no symlinked, foreign-UID or group/world-writable ancestor;
    - an `O_NOFOLLOW` regular file owned by the UID, executable, with 0 < size ≤ 256 MiB;
    - bounded copy, fstat drift and rehash checks;
    - an fchmod 0500 sealed snapshot.
- **Host path unchanged.** The host path `verify_development_read_only_worker` → `(Host, None)` keeps the exact
  predecessor semantics: the name check, then the sibling snapshot.
- **Ordering.** The default `RootOwned` arm is the predecessor's code re-indented. Both arms run before credential
  reads and authority creation. The `WorkerTrust::SealedSiblingDevelopment` arm (`coding_endpoint_launch.rs:226`)
  still requires `LinuxDevelopmentPlatformAdapter::activate` with the development marker. Fixed system executables
  and libraries keep `verify_artifact` root-owned checks.
- **No bypass.** I found no traversal, symlink, alias or fallback bypass.
