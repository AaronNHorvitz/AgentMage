## Findings

No critical, high or medium findings.

**L1 (low; pre-existing in v20; backlog before generated admission): a retained per-request signal mock silently
drops later calls, so the oracle can pass a candidate the original fails.**

- Code: `scripts/coding_eval_oracle_worker.py:519-527` creates a fresh `observed` and patch for each recorded
  stop/control request. Calls through a candidate-retained reference to an earlier request's mock go to a stale
  `observed` and are never transported.
- The frozen method has one patch across stop/pause/resume, so in the original such calls still append to `sent`.
- Reproduction (`stash-mock-duplicate`): `stop` saves `signal_running_cli` (the patched mock), then
  `control(..., 'pause')` calls the saved mock and also the normal path.
  - The legacy grader fails: `sent` holds a duplicate SIGUSR1.
  - v21 passes with 18 calls.
  - The same variant on an exported v20 tree (`$R/v20`, run with `GIT_DIR` pointing to the repository's object
    store, read-only) also passes. The defect is not introduced by this repair.
- Severity: low. It needs a candidate that deliberately keeps the test double and calls both it and the patched
  global. Natural lazy caching fails both graders, because the cached stale mock defeats the no-live refusal in the
  original too. No score is produced while generated scoring is disabled.
  - The guide's sentence "Order, missing calls, wrong values … still reach the original assertions" should not be
    read as covering duplicate calls through retained doubles.
- Fix: in `record_signal`, check a per-request `active` flag, cleared when the patch exits. Make any later invocation
  of a stale double set a sticky flag that turns the next job reply into `adapter_policy`, or forward it as a
  failure. Add `stash-mock-duplicate` as a must-fail variant.

Carried, unchanged: review 1 L1's PurePath/subclass codec restriction. It is now disclosed in the guide and evidence
as stricter than the original, and stays backlog before generated admission.
