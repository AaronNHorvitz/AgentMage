## Analysis

- **Token reach.**
  - `collect_inner` → `preservation::collect_with` → `observe_inventory_optional(…, token)` →
    `observe_with`, which uses the caller's token instead of the fallback root when one is supplied.
  - Inventory and base reads use the same path.
  - Every one of the 17 preservation Git reads goes through `Observer`, with a check before and after each
    worker call. There are further checkpoints around the worktree hash, the metadata/file hash phase and
    sealing, and after sealing.
  - No preservation Git read bypasses the observer.
- **Manifest fields.** `manifest_fields.py` confirms the 32 field expressions are unchanged. The
  equality test with and without a live token, together with the real source and index drift test, passes.
  The order of the precheck in `collect_inner` changes: a cancelled linked scope now reports
  `ObservationFailed` instead of `PlanDenied`. Both refuse, so this is harmless.
- **Review path.**
  - `observe_commit_git` refuses on precancel before `verify_apply_roots`. The m4 mutant proves the new
    test discriminates this.
  - It forwards the token to the original preservation, the linked inventory and the base reads, and
    checks again after `linked.revalidate()`. A cancelled successful result therefore cannot yield a
    `GitObservation`.
  - The synchronous planner `plan_reviewed_candidate_tree` passes `None`, as documented.
- **Commit and candidate paths.**
  - A commit postflight failure under cancellation maps to `uncertain_commit_result(…"postflight")`. This
    has the same outcome class as the `check_control!` that follows it, so there is no regression from
    Uncertain to Unchanged.
  - The candidate builder's `after` collection now refuses under cancellation. Before this commit, a
    cancellation that landed after `write_tree` could still return `Succeeded`, so this is an improvement.
  - Scratch cleanup (`session.cleanup()`) still precedes `after`.
- **Not claimed and not changed.** The worktree lifecycle executor (`repository_safety.rs:1124,1158,1178,1189`)
  and `coding_repository.rs:317,427` still collect without the token. The batch does not claim these
  paths. The guide sentence "every existing confined Git worker" sits inside the dormant commit-executor
  section, where it is accurate. This is noted for backlog context, not as a finding.
- **Confinement.** Trusted executable admission, the bubblewrap/systemd inspection worker, the environment
  scrubbing (`GIT_CONFIG_NOSYSTEM`, `HOME=/nonexistent`, and so on), output bounds and the hardened prefix
  are unchanged. No new public substitution seam: `Observer`, `preservation::collect_with` and
  `collect_cancellable_with` are private, `pub(super)` or module-private.
- **Public repository hygiene.** The added lines contain no home paths, usernames, hostnames, credentials
  or third-party product names. Only the lab path `/lane/state/tmp/...` appears, as in prior retained

  - Fix: a private observation seam test that asserts each collector call receives the caller token.

  - Fix: either rename the test, or have the stop-point assert that the error originates before any
