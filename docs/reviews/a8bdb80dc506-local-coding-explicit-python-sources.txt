  - A string value fails decoding. An empty array, `..`, test paths and duplicates give
    `400 code.runtime.source-selection`.
  - A non-project scenario with `source_paths` refuses.
  - Selection is validated before the owner lock and extraction (`coding_owned_api.rs:83`). The test checks
    that the held repository `Arc` and empty runtime are unchanged afterwards.
  - Consent and control are still required: 403 without control, `handoff-consent` without approval.
  - `CodingPythonSourceSelection` has private fields and is built only through `new`.

  - `python_project_paths` (`coding_development_runtime.rs:2195-2237`) requires all of: `content_read`,
    `RegularFile`, `python_source_path_allowed`, an exact component match, and disposition `Parsed` or
    `ParsedWithErrors`.

    is unique and every output entry is drawn from it, so the result is exactly the selection set.

**L1 (low): in the root layout, a writable package `__init__.py` can still hide discovered tests through
unittest's `load_tests` hook. The prior L1 is therefore only partly addressed.**

- Location: `shells/host/src/coding_development_runtime.rs:445-453` (`python_source_path_allowed`), used by
  `python_project_paths` (`:2205`), together with the root command `-s . -t .` (`:2265`).
- Claim affected: the evidence file says this "addresses review L1, including the original
  `src/test_calc.py` case". TASKS.md says "Both low findings are addressed".
- Problem: in the root layout, discovery imports every package `__init__.py` on its way to test modules.
  When that `__init__.py` defines `load_tests`, it replaces discovery for the whole package subtree. Package
  `__init__.py` files pass the new exclusion. The new test
  `project_sources_exclude_discovery_modules_and_test_directories` keeps `src/__init__.py` writable on purpose.
- Reproduction: I used a temporary directory containing `src/__init__.py` (empty), `src/calc.py` with
  `return a-b`, and `src/test_calc.py` asserting `add(2,3)==5`.
  1. `env -i /usr/bin/python3 -I -B -m unittest discover -s . -t . -v` gives `FAILED (failures=1)`, exit 1.
  2. I rewrote only `src/__init__.py` to define a trivial passing `TestCase` and
     `def load_tests(loader, tests, pattern): return tests`. The same command then gives `Ran 1 test … OK`,
     exit 0.
  3. `src/test_calc.py` and `src/calc.py` were never touched.
- Why it is low:
  - It is the same class the prior review rated low: the approved runner is trusted and is not independent
    grading.
  - Any writable imported module can already monkeypatch `unittest` in either layout.
  - The frozen scorer, not this transcript, decides coding scores.
  - Every write is separately approved and visible.
  - Confinement is unaffected.
  - The package layout (`-s tests`) is not exposed to this hook, because `tests/**` is excluded.
- Fix: in the root layout, exclude from `exact_files` (or refuse at startup) every `__init__.py` whose
  package directory contains, directly or transitively, a module matching `test*.py`. Add the probe above as
  a test next to the existing root interpreter fixture, and correct the "addresses L1" wording. Resolve this
  before any root-layout run is cited as coding-success evidence.
