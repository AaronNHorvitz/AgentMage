## Review of the change

### Claim and capture order

1. `mkdirat(original.roots[2], directory, 0700)` relative to the held parent. This is exclusive.
2. `openat` of the child through the same held parent descriptor, with
   `RDONLY|DIRECTORY|NOFOLLOW|CLOEXEC`.
3. `claim.revalidate()`. This runs the original scope's revalidation, then `statat(held parent, name,
   SYMLINK_NOFOLLOW)`. The named entry must equal the held child's dev/ino, owner uid, directory type, and mode
   with `& 0o077 == 0`.
4. Capture.
5. `claim.matches(worker.roots[2])`: the worker's scratch descriptor must have the same dev/ino as the held
   child.
6. `claim.revalidate()` and `worker.revalidate()`.
7. Disarm the guard.

Nothing fallible follows the disarm, since `Ok(Self{..})` cannot fail. This closes earlier L2: the worker's
projected scratch is bound to the directory created through the held parent, not just to whatever the path names
at capture time. The production closure (`repository_candidate.rs:108-112`) is unchanged in substance, and its
only caller is `local_commit.rs:226`. `new_with` is private to the module, and only tests call it with a custom
closure.

### Rollback (earlier L1)

`Drop for CandidateClaim` runs only while the guard is armed. It runs only if `revalidate()` passes again, then
issues a single `unlinkat(held parent, name, REMOVEDIR)`, and ignores the error. `REMOVEDIR` cannot remove a
nonempty directory, and nothing else is unlinked.

Every failure from the initial `claim.revalidate()` through the final `worker.revalidate()` drops the guard while
`original` is still alive. Locals drop in reverse order, so `worker` drops first. The guard also runs during a
panic unwind from the closure.

The following cases retain the directory: the initial `openat` fails (the `?` fires before a guard exists, which
the evidence documents), the child or parent is replaced, the child is a symlink, the mode changed, or there are
unknown entries. Even if the parent path is swapped after the check, removal acts on the held parent descriptor.

### Remaining race and launch

The residual same-uid race between the identity check and `unlinkat`, and between `mkdirat` and `openat`, can at
most remove an empty directory or bind a foreign empty owner-private directory. The evidence and guide disclose
this accurately as "not an atomic transaction". It gives the guest no authority, so it is not a finding.

A failed constructor cannot launch a worker, because the constructor never dispatches. Dispatch only happens in
`step_with`, on a returned session.
