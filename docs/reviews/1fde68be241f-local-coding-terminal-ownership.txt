## Analysis of the requested points

- **Complete disclosure before the single attach POST.**
  - `attach` parses, refuses non-tty stdin, reads the held root (control token), and adds
    `expected_worktree_root_sha256`.
  - It checks the encoded size against `MAX_REQUEST` and then confirms. The confirmation shows the whole
    `request` object plus the default-source text and the warning, and the challenge is
    `attach <held digest>`.
  - The POST sends that same `body` once.
  - The test checks that every field appears before the challenge, and checks the exact POST body for
    four scenario/model/source combinations.
  - The server's `Attach` struct matches these field names and has `deny_unknown_fields`.
- **Canonical sources, no filesystem inspection.**
  - `attach_body` only splits strings and calls `CodingPythonSourceSelection::new`, which is
    `WorkspacePath::new` plus string predicates. It never opens a file.
  - The canonical sorted order is both displayed and sent; the test sends
    `[["calculator.py"],["package","core.py"]]`.
  - Source paths are refused for `failed-test-repair` on both client and server.
- **Closed model, scenario and path validation.** Models are exactly `muse`/`gpt-oss`. Scenarios are
  the three labels. Roots must be absolute with no `..`. Every invalid case in the test asserts zero
  prompts and zero requests.
- **Wire-size refusal before confirmation.** The size test is discriminating. Every path is individually
  valid: it reaches the GET (one call), but the request is refused before any prompt (`answered == 0`).
- **Piped or declined consent.** A pipe sends no request for either command. A declined attach sends
  only the GET. A declined recovery sends only the status read.
- **Recovery for attached and pending owners.**
  - Attached (`(true,false)`) requires `live_creation_owner == true` from the selection.
  - Pending (`(false,true)`) explicitly shows `runtime_selection: null`.
  - Busy, unavailable, contradictory, missing-field and separate-process (non-owner) states are refused
    before any prompt.
  - The server, not the client, still enforces release and exclusive references (`recoverable()`,
    `Arc::try_unwrap`).
- **Separate client and control credentials.** The peer asserts the client token on `GET /v1/status`
  and the control token on every other route. A wrong token panics the worker thread, and
  `finish().join().unwrap()` then fails the test.
- **Genuine 409, malformed or lost replies.** A real `HTTP/1.1 409` goes through the unchanged strict
  `receive` path. A 409, a closed peer or a malformed success each give exit ≠ 0, with the request count
  fixed at 2. There is no retry.
- **Truthful no-extra-grant checks.**
  - Attach requires `attached`, `live_creation_owner`, `model_and_tools_approved == false`,
    `resume == false` and `retention == "process-only"`.
  - Recover requires `apply_approved == false` and `fresh_diff_required == true`.
  - Both test and probe exercise these checks.
- **Ownership stays with the server.** The client adds no authority. Creation, activation, model and tool
  approvals, release and the original-checkout apply remain separate server steps, and the warnings say
  so accurately.
- **Confinement.** The client opens only the auth directory and `/dev/tty`, and talks only to a loopback
  `SocketAddr` over fixed literal routes. The diff adds no path to the worktree, sandbox or network. I
  found no escape through this surface.
- **Honest claims.**
  - The evidence and guides say these are synthetic-peer terminal contracts, not native creation, a
    positive workflow or a score.
  - They state that the host-53 and Linux-19 baseline failures were not selected and are not repaired.
  - The prior review's L1 is carried as low backlog that blocks root-layout success claims.
- **Integrity.**
  - TASKS.md changes only the T-306 row text, and its status stays `[ ]`.
  - There is no sub-row, and no T-311, task, hidden, held-out or threshold change.
  - No dependency or Cargo.lock change, and no added private path, name or product comparison.
  - The `/lane` and `/tools` paths inside the retained review are generic environment paths already
    used in earlier committed reviews; no username or hostname is added.
  - The commit author metadata is the owner's own identity.

    credential.

  `expected_entry_sha256`) in `Recover`. Have the client bind it into the challenge, as attach does.
