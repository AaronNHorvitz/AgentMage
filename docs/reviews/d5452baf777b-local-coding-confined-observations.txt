- **L1 (low, backlog): the confined `worktree list` no longer shows whether a linked worktree's
  directory exists.** Location: `platforms/linux/src/repository_safety.rs:396`, the
  preservation `worktrees` observation.
  - Cause: in the guest, every linked worktree recorded under the checkout's metadata with an
    absolute host path is reported `prunable gitdir file points to non-existent location`.
  - Effect: deleting a user's linked worktree directory on the host (without pruning) no longer
    changes `worktrees_sha256`. This holds for the non-worktree deltas too: None,
    BranchFastForward, Fetch, CandidateTree and LocalCommit.
  - Related effect: a nested linked worktree inside the checkout loses its gitfile target, so
    untracked listings show its files one by one instead of as a nested repository.
  - Reproduced in the guest layout: identical `prunable` output before and after `rm -rf` of the
    worktree directory. The host showed the change.
  - This is a weaker preservation signal, not a confinement escape, and it is not disclosed.
  - Fix: add a host-side existence/identity check for each registered worktree (from the held
    metadata) to the framed manifest. Alternatively, document the reduced signal in Decision 0188
    and the guide.
- **L2 (low, backlog): stricter bounds for ordinary observations are only partly disclosed.**
  Location: `repository_observation.rs:47` via `repository_safety.rs:670`.
  - Ordinary preservation and inventory reads move from the 30 s direct `PROCESS_TIMEOUT` and up to
    32 MiB of output to the worker's 15 s deadline, 256 MiB MemoryMax, 16 tasks and 4 MiB of
    output. `repository_inventory.rs:137-164` still requests `MAX_INVENTORY_BYTES` (32 MiB), which
    is now silently capped at 4 MiB.
  - The docs disclose only the 4 MiB ceiling.
  - Practical effect: `ls-files --others --ignored` lists every ignored file. Projects with a
    populated ignored build or dependency tree are likely to refuse inventory. This fails closed,
    so it is not a safety problem.
  - Fix: state the deadline and resource change in the evidence/guide, and either measure a
    representative repository or reduce the ignored-listing volume within the existing ceiling.
