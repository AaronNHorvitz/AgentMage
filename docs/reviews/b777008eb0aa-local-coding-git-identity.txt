## Analysis

- **Construction is closed.** `LinuxCodingGitCreation` has private fields and no `Clone`, `Debug`,
  `Serialize` or `Deserialize`. Its only constructor, `from_dispatch`, is `pub(super)`. In product code it
  is called once, in `execute` (`coding_repository.rs:469`), with the plan cloned before the consuming
  `dispatch` and the receipts that `dispatch` returns.
  - No API or CLI route accepts `git_creation`. The CLI only compares the server's pending preview against
    the preview it received earlier (`coding_cli.rs:638-640`).
  - The test-only `with_test_created_worktree` path (`coding_repository.rs:198`) and all four test fixtures
    set `None`.
- **Correlation is real.**
  - `from_dispatch` re-runs `plan.verify()`, which recomputes the plan digest. That is why the branch, base
    and operation substitutions (cases 10-12) are refused.
  - It requires a WorktreeCreate operation and two Succeeded outcomes, plus `cleanup_verified`.
  - It requires matching transaction, plan, manifest, authority-transaction and attempt IDs across the plan,
    canonical receipt and specialized receipt.
  - The 14 substitutions plus the missing-receipt case each exercise at least one of these checks.
- **The accessor revalidates roots.** `created_git_identity` calls `verify_apply_roots`, which checks the
  original, worktree and management roots. It then requires the authority receipt digest to equal
  `creation_receipt_sha256`. The tests replace each of the three roots, change the receipt and drop the
  provenance; every case is refused.
- **Lifetime.** Provenance lives inside `CreatedWorktree`, so it moves with the owner through
  `into_runtime_worktree` and `try_into_repository`. The busy return (a second live lease) is refused.
  Reopening the store restores the receipts but not `git_creation`. All of this is tested.
- **Fails closed.** If correlation fails after a successful dispatch, `execute` returns an error before
  `self.created` is set. The native worktree exists on disk, but this owner never adopts it, and nothing is
  mislabelled as attached. See L1 for the diagnostic code.
- **Surface and claims.**
  - `inspect_apply` and the apply preview carry the historical object with
    `current_git_state_verified`, `commit_authority` and `publication_authority` all false.
  - The preview digest covers the object: the test recomputes `preview_sha256` over the body that includes
    `git_creation`.
  - Both values reach the existing API GET and prepare routes unchanged, and the CLI shows them in `show`
    and in the apply confirmation.
  - No new route, Git command, commit, push or signer was added.
  - The evidence honestly labels the creation observations as SYNTHETIC and reports that no native creation
    was measured in this lane. The supported-host branch of the native test (new identity assertions) has
    still never executed here. That is inherited prior-review backlog, and the docs disclose it.
