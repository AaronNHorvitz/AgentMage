## Findings

No critical, high or medium findings.

- **L1 (low): `prepare_edit_proposal` does not bind the startup to the owner's workspace.**
  Location: `shells/host/src/coding_endpoint_prepared_startup.rs:210-282`.
  The method checks kind and task but never compares `self.request.workspace_id` with the repository's created
  `held.workspace_id()`. So a startup sealed for another workspace, carrying that workspace's exclusion policy,
  re-reads files from this owner and replaces its pending preview (probe P1: `ok=true replaced=true`).
  The native `bind` still refuses the workspace mismatch (`platforms/linux/src/coding_repository_endpoint_edit.rs:142`, the
  `request.workspace_id != *created.held.workspace_id()` check). The caller is trusted, holds `&mut owner` and
  already holds the context bytes. So there is no write, grant or disclosure bypass, only a discarded preview
  and reads under the wrong narrowing policy.
  The commit's `narrowed` exclusion test also relies on this mismatch: the startup it uses could never bind.
  Fix: expose a content-free workspace check on `LinuxCodingRepository` (or check during `select_created_sources`)
  and refuse with `Scope` before any read. Then build the `narrowed` test's exclusion ledger for the owner's workspace.
