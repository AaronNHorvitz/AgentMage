## Review by area

- **Parser selection and immutability:** `output_format` is a closed serde enum. Unknown values,
  `null`, booleans, `process_exit_v1` and duplicate keys return 400 (API test). The kernel seal now
  refuses only `ProcessExitV1` for test kinds (`validation_template.rs:388`). The selected parser enters
  the definition `source` digest and the sealed template. The text parser identity is
  `sha256(json([sha256(validation_result.rs), sha256(validation_result_text.rs)]))`, a structured
  pair of whole-file digests computed from `include_bytes!`, never from caller input.
- **Retry budget:** `check_validation_selection` requires `series.template == template`. Any format
  change after the first admitted attempt returns `code.validation.stale`, and the spent count is
  retained. The new platform test asserts this for both text formats; I confirmed it in the code. A
  rerun still requires the exact prior receipt, `plan_failed_test_rerun` and `verify_rerun_plan`.
- **Normalizer:** text parsing runs only after the existing checks: digest-bound channels,
  termination, signal, truncation, secret classification and control bytes. Rust reads only stdout
  and Python only stderr; swapping the channels returns Malformed (kernel test). A pass requires
  exit 0 and the minimum count. Failures require a nonzero exit. Skipped-only and too-few results
  never pass. Counters use checked arithmetic.
- **Ownership and auth:** the API still requires the control token and a service-created worktree.
  A valid format cannot adopt a caller worktree (409 `code.command.worktree-required`). The CLI

- **Producer fixtures:** v1–v4 bytes are unchanged (the diff adds only `v5/`). Complete original

- **Evaluation integrity:** no frozen task, hidden test, held-out input, threshold, prompt or

## Findings

### M1 (medium): the fast gate now accepts a change to the validation-receipt schema without building or testing its Rust consumer

Location: `scripts/local_agent_fast_gate.py:25` (`VALIDATION_SCHEMA_INPUTS`), `:171` (skips the
schema in the coverage check) and `:188` (adds only `node --test`). Test:
`tests/test_local_agent_fast_gate.py:106`. Claims: `docs/guides/local-agent-development.md:35` and
`docs/evidence/t303-test-adapters-2026-11-06.md:92` ("its actual JavaScript consumer tests").

`shells/host/src/coding_tools.rs:70` embeds this exact schema with
`include_str!("../../../schemas/runtime/validation-receipt.schema.json")` as
`TARGETED_VALIDATION_OUTPUT_SCHEMA_JSON`. That schema feeds the model-visible tool-catalog digest.
Decision 0155 and this batch's evidence report that this dependency caused four host producer-fixture
failures. So the schema has a Rust consumer, `agentmage-host` and its dependents, and the current v5
fixtures depend on its bytes. Before this commit, a schema change outside a crate made the gate
refuse (no coverage registered). Now it is accepted with JavaScript coverage only.

Reproduction (read-only), from the commit root:

```text
python3 -B -c 'import json,subprocess,sys; sys.path.insert(0,"."); import scripts.local_agent_fast_gate as g;
md=json.loads(subprocess.check_output(["cargo","metadata","--no-deps","--format-version","1","--locked","--offline"]));
print(g.plan(g.ROOT,["schemas/runtime/validation-receipt.schema.json"],md))'
```

The output plans only `git diff --check`, `--lint-untracked` and `node --test
tests/test_planning_schemas.mjs`. It plans no `cargo fmt`, `clippy` or `test` for `agentmage-host`
and no producer reproduction. A future schema-only edit (for example, another parser identity) would
pass the per-change gate while breaking `the_committed_fixtures_are_the_records_the_runtime_builds`
and the other host catalog tests. That is the same breakage this batch hit, which was caught only
because kernel sources changed at the same time.

Concrete fix:

1. When `schemas/runtime/validation-receipt.schema.json` is in `paths`, add `agentmage-host` to the
   package selection, expanded through `affected_packages`' reverse dependencies. Also add the
   reserved `runtime_producer_fixtures.py` check and `tests.test_runtime_producer_contract`, as for
   the fixture inputs.
2. Extend `test_validation_schema_changes_run_the_actual_consumer_tests` so a schema-only plan must
   include `-p agentmage-host` in its `cargo test` command.
3. Correct the two documents to name the Rust consumer.

This is gate-soundness evidence integrity, not a runtime security defect. It must be fixed before
T-303/T-306 close on a batch that relies on this gate.

### L1 (low, backlog before T-303 parent acceptance): common honest outputs become non-retryable Malformed results

Location: `kernel/engine/src/validation_result_text.rs:66`, `:152` and `:228`, together with the
unchanged rerun precondition at `kernel/engine/src/validation_result.rs:602`.

The following honest transcripts are refused as Malformed:

- `#[ignore = "reason"]` (`ignored, reason`). This repository's own gate output contains this line;
  see run 4, `print_runtime_producer_fixtures ... ignored, run by ...`.
- libtest's ">60 seconds" progress line.
- Python tests that write to stderr, such as default `logging` warnings.
- `NO TESTS RAN` (Python ≥3.12, exit 5).
- A failing Rust test whose captured stdout contains a line starting with `test result: ` or
  `running `.
- A Rust compilation failure, which leaves stdout empty (`:66`).

`plan_failed_test_rerun` admits only `AssertionFailed` or `CompileFailed`. After any Malformed
receipt, the worktree's validation series therefore cannot continue, even with attempts left; a
changed format is `stale`. Refusal is the safe direction, and the guide discloses some of these
cases: custom ignored reasons, and compilation as malformed. But the T-303 row requires
"read failures and retry within budgets". Retrying after a compile error is the most common case
in a Rust repair loop, and the measured parent loop needs a safe, explicit path for it: for example,
a distinct compile/incomplete classification from the exit code plus an empty transcript, with
separately approved rerun, and the remaining refusals listed in the guide. No change in this batch
is required.

No critical or high finding.
