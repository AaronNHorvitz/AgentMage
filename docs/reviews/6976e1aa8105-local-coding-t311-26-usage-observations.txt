## Code review

`usage_proxy` is the trusted side; it runs in the assertion namespace with the original methods.

- **L1 (history drift).**
  - `history()` freezes typed, encoded copies of the following, each bounded by 128 calls and
    the frame size:
    - `mock_calls`, `call_args_list` and `method_calls`;
    - `called`, `call_count` and `call_args`.
  - The owned branch compares this snapshot with `last_history` both before the request and
    before replay. Any mismatch calls `refuse()`, which is sticky, before `reset_mock()`, so
    trusted observations are never erased.
  - The unowned branch now also refuses on child, direct-call or flag history.
  - `last_history` is updated only after the replay.
- **L3 (sticky encoding).** Argument packing in `invoke` now converts `AdapterPolicyError` into
  sticky `refuse()`. The only other packing failure paths are:
  - frame size, which `RemoteFunction` turns into a sticky `failed`;
  - depth, which is an `AdapterPolicyError`.

`usage_result` is the candidate side. It snapshots every retained root of the instance after the
trusted contents are applied and before the candidate call. It then returns
`{"adapter_policy": True}` if any encoded root differs afterwards, and never restores the
argument. `ProtocolError` from encoding is now also mapped to policy, not malformed protocol.

### L1 (low): candidate-side mutation check is defeatable by deliberate self-modification; the guide omits that caveat

- **Location:**
  - `scripts/coding_eval_oracle_worker.py:970` and `:980-984`. The snapshot and comparison run
    inside `usage_result`, in the candidate's own interpreter.
  - The new guide text at `docs/guides/coding-evaluation-oracle.md:72-79`.
- **Reproduction:** the `tamper-hides-mutation` probe above.
  - The candidate appends to `messages`, then overwrites the caller frame's `snapshots` dict.
  - Oracle v25 passes; the legacy grader fails with `Called 2 times`.
- **Reasoning:**
  - In legacy grading the trusted test observes the mutation directly. Under the oracle, the
    observation is self-reported by code that hostile candidate Python can reach.
  - The worker's own comment (`:1395-1396`) and the T-311.23 guard text (`guide:621-623`) state
    this limit. The new paragraph instead says net changes "cause adapter-policy refusal" without
    qualification.
  - Generated scoring and admission are disabled, so no recorded score is affected.
- **Fix:** before generated admission:
  - add the self-modification caveat to the v25 paragraph;
  - add a `not_graded` coverage tag, for example `deliberate-candidate-self-modification`;
  - keep it on the generated-admission blocker list.
