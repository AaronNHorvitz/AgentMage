## Code review

- **Expiration.** `job_observation` sets `active = False` in a `finally` around the patch
  context. `record_signal` reads `active` through its closure cell, so a call through the patched
  mock, or directly through its `side_effect`, after the request has returned or raised sets
  `signal_state["stale"]`. A unit test covers the exception path, and my `late-then-uncaught` probe
  confirms it (candidate_exception, fail).
- **Shared state.** `candidate()` creates `job_signal_state` once per worker and passes it on every job
  request. `job_result` refuses before dispatch, so nothing runs after the refusal (the unit test asserts
  `stop` is not called). It checks again after dispatch, so parse, export, bundle, no-live and
  expected-refusal paths are all covered. A caught exception or `reset_mock()` cannot clear the
  worker-owned dict.
- **Assertion side.** An `{"adapter_policy": true}` reply raises `AdapterPolicyError`, which is not
  KeyError, HarnessError or ArgumentTypeError, so the frozen `assertRaises` blocks cannot absorb it.
  `policy_failed` is sticky, every later remote call refuses, and `passed` requires
  `not remote.policy_failed`. A refusal therefore always fails, is counted as one failed attempt with
  its test count, and is labelled `adapter_policy`, not `test_failure`.
- **Scope.** There is no new authority, live signal replay, request/response schema change, profile, threshold, selection, hidden
  byte, sandbox, launcher, cleanup, legacy evaluator or fast-gate change.
- **Evaluation integrity.** Only dev-028 development controls and synthetic probes are touched. There is no held-out
  content, generated admission, model run or score. Failures are retained, not dropped.
