## Findings

### L1 (low): the oracle rejects truthy non-Boolean results that the unchanged frozen assertions accept

`scripts/coding_eval_oracle_worker.py:123-128` requires `type(passed) is bool`
and Boolean check values. The selected hidden methods use only `assertTrue` and
`assertFalse`, which accept any truthy or falsy value. Probe: I wrapped the
dev-021 reference so `passed` and every check are cast to `int`. The **oracle
reported `protocol`** (1 error). The unchanged legacy grader **passed** the same
source (`cause: none`). The statement does not require a `bool` type. So for
this clause the oracle is stricter than the "complete and unchanged" methods. A
future generated candidate that builds checks with `and`/`or` chains could be
failed by the adapter rather than by the tests.

This affects no current number: only frozen controls are admitted, and both
references return real Booleans. The guide does say "Boolean", but it does not
call this a deviation. Fix before generated scoring, either way:

- Add a coverage label such as `strict-boolean-result-type`, with one sentence in
  the guide saying that this rejection is adapter policy, not a frozen assertion.
- Or transport `bool(value)` together with a separate non-scoring type
  observation.

### L2 (low): malformed results table in the evidence

`docs/evidence/t311-9-verification-oracle-2026-11-03.md:23-24`: the header row
has 4 cells and the delimiter row has 5. GitHub-flavoured Markdown does not
render it as a table. The validators pass. Fix: drop one `| --- |`.
