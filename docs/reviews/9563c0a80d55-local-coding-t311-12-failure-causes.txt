## Findings

### M1 (medium): Boolean and Boolean-map predicates still refuse representable wrong values as malformed protocol

- **Location:** `scripts/coding_eval_oracle_worker.py:159-160` (`bool`: `type(result) is bool`) and
  `:178-180` (`bool-map`: every value `type(...) is bool`), raising `ProtocolError` at `:181-182`. Also
  `scripts/coding_eval_oracle.py:80-81`: coverage for these kinds declares neither an exact-Boolean policy
  nor an ungraded exact-Boolean type.
- **Why this misses the row:** T-311.12 is "done when" it carries "representable wrong helper/predicate
  values to unchanged original assertions" and separates candidate failures "from malformed wire data".
  - That is done for argument and verification tasks, but not for the two Boolean predicate tasks.
  - dev-015's frozen method grades `case_passed` only through `assertTrue`/`assertFalse`. dev-029's
    method grades through `all(checks.values())` and `assertFalse(...["answers"])`. Both are truthiness
    assertions.
- **Reproduction:**
  - Append `_orig = case_passed` and `def case_passed(*a): return int(_orig(*a))` to the dev-015
    reference. The legacy grader passes. The independent oracle reports `passed: false`,
    `cause: protocol`, `protocol_failed: true`.
  - `return _orig(*a) or None` behaves the same.
  - For dev-029, `{k: int(v) for k, v in _orig(*a).items()}` behaves the same.
- **Impact:** a well-framed, valid JSON reply is labelled malformed wire data. A candidate that the
  unchanged original assertions accept is failed by the scorer. That is wrong cause data and a wrong
  verdict on 2 of the 10 independent tasks. Both would reach published results once generated scoring
  opens.
- **Claims:** the request states without qualification that "Integer predicate observations now follow
  original truthiness assertions". The builder's integer-truthiness probe covers only dev-022, and the
  dev-015 and dev-029 cases are not tested. With policy tags now forbidden on these result types, the
  strictness cannot even be labelled policy.
- **Fix:**
  - For `bool`, accept any `scalar_value(result)` (finite JSON scalar) as data. For `bool-map`, accept a
    `str`-keyed dict whose values satisfy `observation_value`. Return them unchanged so the original
    assertions decide.
  - Add `exact-boolean-result-type` to `not_graded` for dev-015 and dev-029.
  - Add confined probes with legacy contrasts: integer and `None` truthiness for both tasks, plus one
    wrong value that fails the original assertion.
  - Keep the policy-tag-is-protocol rule for these types.

### L1 (low): JSON-valid observations over the frame or integer-digit limit crash the candidate and record `protocol`

- **Location:** `scripts/coding_eval_oracle_worker.py:429`. `encode_message(...)` runs outside the
  per-call `try`. `observation_value` (`:44-53`) accepts any `int`, but Python's `json.dumps` refuses
  integers over 4300 digits. Results over 64 KiB also raise `ProtocolError`.
- **Reproduction:** a dev-006 helper returning `10**5000`, or `['x'*70000]`, gives cause `protocol` with
  candidate exit 1. The failure is still counted and nothing passes.
- **Impact:** an oversize candidate value is labelled as wire corruption. The guide names the frame
  bound but not the resulting cause.
- **Fix:** encode the result inside the call handling. On a frame/encoding refusal, reply with
  `{"adapter_policy":true}` for policy-declared types, or with a fixed tag for the others. Alternatively,
  document oversize as `protocol` explicitly.
- Backlog; does not block the row.
