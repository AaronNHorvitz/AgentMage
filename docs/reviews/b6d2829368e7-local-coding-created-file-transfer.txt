## Source review

- **Lineage establishment** (`coding_repository_create.rs`): `create_driver` uses `try_lock`, so a
  busy or poisoned owner refuses. It also requires the held worktree root and revalidates it.
  `apply` accepts Create operations only. It refuses paths that already have lineage, duplicates, and
  anything past the shared 16-path limit, and it clears pending command, edit and apply decisions
  before dispatch. `complete` requires all of: the wrapper's own `applied` flag (all indexes, no
  failure, not uncertain); a `Committed` outcome; the same transaction and consumed grant; a valid
  receipt chain with matching transaction and grant ids; and, per operation, an exact map of path,
  postimage and mode against the authorized plan. Restore clears `applied`. Zero digests, caller
  receipts and rehashed foreign receipts cannot create lineage, and the tests exercise these refusals.
  Edits keep `created_mode` and the zero preimage (`coding_repository_edit.rs:63`,
  `coding_repository_runtime.rs:313`).
- **Original creation** (`coding_workspace_create.rs`, `coding_repository_apply.rs`): explicit
  root-pair read consent is still checked before any observation. The public `select` still reads;
  `select_targets` is `pub(crate)` and still refuses `.git`, case aliases and non-ASCII-safe paths.
  Parents are resolved through the no-symlink adapter; a missing parent refuses and none is created.
  Preparation requires an absent destination, and the kernel's pre-consumption observation checks

  Approval is single-use, expiring, stale-checked (including `created_mode`) and never replayed. Only
  a `committed` outcome removes lineage. Restart restores nothing.
- **Host**: with a lease, the owned create driver is used; without one, the `unowned` wrapper delegates

## Findings

**M1 (medium): owned native creation is not refused on the hookless direct execution path, so it can
record transfer lineage without the coordinator's tool-terminal publication.**
`shells/host/src/linux_coding_runtime.rs:2637-2641` refuses owned structured writes when
`event_context` is `None`, because "Owned lineage needs the coordinator's atomic tool-terminal commit.
The legacy direct boundary path has no such publication owner." The new create path,
`execute_prepared_controlled_create` (`:2880`), has no such guard. With a lease attached it selects
`lease.create_driver` (`:2942-2947`). On the direct path, `finish_specialized_effect_event` takes the
`(None, None)` branch (`:3222-3228`), which only checkpoints the authority write transaction, and then
`driver.complete(&result)` (`:3073-3075`) inserts absent-before lineage.

This path is reachable through the public API. `compose_ephemeral_coding_coordinator`
(`shells/host/src/coding_harness.rs:27`, built on `ReusableRuntimeCoordinator::new`, which has no
correctness hooks, `runtime_loop.rs:1372-1395`) accepts any `RuntimeToolBoundary`. The loop then calls
`tool_boundary.execute(...)` (`runtime_loop.rs:3575`), which reaches `execute_call(..., None)`
(`linux_coding_runtime.rs:4026`). A `LinuxCodingRuntimeBoundary` with `attach_owned_worktree` therefore
reaches the create path with an owned lease and no event context. Owned structured writes are refused
there; owned creations become transferable.

This contradicts Decision 0160 ("Failed publication … establish[es] no lineage"), the brief ("unpublished
ownership confers no new transfer lineage"), `docs/guides/coding-original-apply.md:89` ("only after
creation through the live coordinator's … driver, followed by successful terminal publication") and
`docs/guides/coding-owned-runtime.md:38-40`. The shipped development factory composes the durable
coordinator, and the original write still needs a separate exact approval. Even so, this is the exact
provenance invariant the increment claims, and it is enforced inconsistently with its write sibling.
No test covers the owned host create path in either direction.

Fix: add the same refusal before any effect at the start of `execute_prepared_controlled_create`:
`if self.owned_worktree.is_some() && event_context.is_none() { return Err(RuntimePortFailure::Invalid); }`.
Add a host regression showing that an owned boundary on the direct path refuses creation before
grant consumption and leaves `available_paths` empty. If host tests cannot run in this lane, add a
component-level equivalent and record that limit.

**L1 (low, backlog): the original-apply terminal confirmation wording is edit-centric.**
`platforms/local-api/src/coding_cli.rs:517` says "Writes exactly this complete diff in the original
checkout" for creation previews too. The complete creation preview is displayed, so nothing is hidden.
Fix: mention "new files" when `write_preview.operations` is present.

Existing backlog lows (lifecycle/continuation, factory allocation, standard-library shadowing, the
predecessor's terminal status/owner snapshot consistency L1) are unchanged and stay backlog.
