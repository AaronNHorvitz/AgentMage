## Review notes

- **Authorization.** Paths, connection, startup, repository, control, clock and verifier are all
  supplied by the trusted in-process factory. No HTTP or model field selects them.
  `serve_coding_endpoint_strict_edits` checks the factory's run and session IDs against the
  service's fresh identities (`coding_endpoint_prepared.rs:140-143`). `CodingEndpointStrictEdits::new`
  checks the transport model binding, the paths (`check_sources`) and the budget range before any
  I/O; startup tests cover this. `prepare` rejects request substitution and out-of-range turns
  before reading. Each advance still goes through the unchanged HTTP disclosure-consent check:
  without consent it returns 403 with zero model calls and zero clock reads. Each native write
  needs its own exact approval, and tampered or old approvals return 409. All of this is
  asserted in the new HTTP method.
- **Owner state.** `read_context` requires `Owner::Ready` and the workspace binding. A pending,
  failed or uncertain owner therefore refuses before any model dispatch. This closes the
  predecessor's "spends one accounted model call" backlog note for this service path. The
  symlink-before-read cases above confirm `model_call_count` 0.
- **Clock.** The new public `Clone` and `new` on `CodingEndpointPreparedClock` share one
  `Arc<Mutex<C>>`, so a clone cannot start a fresh running-time budget. The factory passes one
  clone to previews and native boundaries and the original to the coordinator. The expiry case
  exercises this. Only its doc comment is stale (L1).
- **Owner genericity.** The `P` parameter with a default leaves existing constructors
  source-compatible. `check_admission` is the same code, moved out of `admit` and reused unchanged
  by `admit_turn_port`, so capacity, held-run limits and tombstones are identical.
  `serve_admitted_coding_endpoint_with_turns` is a public, trusted library entry point and always
  uses `TerminalToolDisposition::Discard`. That matches the "strict service discards owners" claim.
- **Linux guard.** The predecessor's L1 is fixed: `#[cfg(target_os = "linux")]` now precedes
  `coding_endpoint_edit_previews` (`shells/host/src/lib.rs:52-54`).
- **Evidence honesty.** The evidence and guide label the creation provenance and endpoint answers
  as synthetic. They claim no real model, native Git, command or test run, grade or score. They
  record the full gate as FAIL, along with the Markdown error, its document-only correction and
  the fact that the source suite was not rerun. My fresh default run confirms the corrected
  Markdown passes and the source numbers reproduce exactly (855/53/11).
- **Evaluation integrity.** No held-out, hidden-test, scorer, task-pin, threshold, dependency,
  Cargo manifest/lock, SBOM or status-model path is touched, and no score is claimed. The
  `| [` row lines in TASKS.md are identical to the base (checked by `check.py`). No row or sub-row
  is added or closed. The batch ends in two running, measured test methods.
- **Public hygiene.** The added lines contain no private host path, username, hostname, credential
  or private sibling-project name; only test-fixture token placeholders appear. The only model
  name is the reviewer attribution inside the retained review file, not branding. No other agent
  product is named.
- **Supply chain.** No dependency change.

## Findings

No critical, high or medium findings.

- **L1 (low, documentation), `shells/host/src/coding_endpoint_prepared_startup.rs:358`.**
  The doc comment still says "Two private references to one original epoch clock". This commit
  makes the type publicly `Clone` (line 361) and constructible (`new`, line 368), so any number of
  references can exist. Safety is unaffected, because every clone shares the same mutex-guarded
  clock and none can reset time. Fix: reword it to "Shared references to one original epoch clock;
  every clone reads the same clock, and none can start a fresh budget."
- **L2 (low, test coverage), `platforms/local-api/tests/support/coding_endpoint_prepared.rs:531`.**
  The strict service's per-turn fresh read has no committed regression for link substitution or
  model-proposed out-of-scope edits. The native layer has its own symlink and hardlink tests, and
  I reproduced all nine cases above at the service level. Still, nothing in the repository pins
  that a swapped `one.py` symlink or hardlink, or a swapped worktree root, refuses with zero model
  calls through this service. Nothing pins that excluded, unlisted, traversal or absolute edit
  paths in a strict answer end FAILED with no challenge. Fix: add these cases to the existing
  scenario list, asserting `model_call_count` 0 or no challenge, and unchanged outside bytes.

Both are same-row backlog, alongside the predecessor's open L2/L3 and earlier lows.
