## Code assessment

The repair is in `platforms/local-api/src/coding_endpoint_api.rs:552-590`.

- **Ordering.** The review-state mutex is now taken with `try_lock` before
  `release_with_tool_boundary`:
  - `WouldBlock` gives 409 and `Poisoned` gives 500. Neither consumes the run.
  - Already-published state gives `NotHeld` before consumption.
  - This removes the old post-consumption `500` branch, which silently dropped an extracted owner
    (part of earlier L1).
- **Locks.** The only lock order is session then review. The repository routes
  (`handle_repository`) take only review, so the change adds no deadlock.
- **Error response.** A `convert` failure after a successful release now writes a complete HTTP 409:
  - `error` is the fixed `code.endpoint.original-review-unavailable`;
  - `released: true` and `original_review_available: false`;
  - a fixed instruction message.
  - The converter error is dropped with `Err(_)`, so no diagnostics, paths or private content leak.
  - `released: true` is accurate: `convert` is reachable only after `release_with_tool_boundary`
    returns `Ok`.
- **Scope.** The Discard and Return dispositions are untouched. Nothing restores the run, grants
  authority, approves anything, writes the original checkout or retries.
- **Service test** (`coding_endpoint_release_tests.rs`). It drives the real `serve_admitted_endpoint_inner`
  over TCP with an actual coordinator admission. For both a Configuration-refusing and an IO-refusing
  converter it checks:

  - a foreign digest and an unstarted run each get 409 with zero conversions;
  - cancel, then a terminal CANCELLED outcome;
  - a non-empty event prefix;
  - the release 409 with the exact body fields;
  - exactly one conversion;
  - release, events and advance then each return exactly `{"error":"code.endpoint.not-held"}`;
  - the apply GET and prepare routes return 428;

  (`safe()` escapes non-ASCII and DEL), a nonzero exit, one confirmation, and exactly the two requests
