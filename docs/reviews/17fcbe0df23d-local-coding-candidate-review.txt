## Security and correctness analysis

- **Packet to live-owner binding.** `verify_review_packet` rebuilds and re-digests the packet. Change-set
  paths are strictly ordered, so they are unique, and `files.len() == created.edits.len()` plus a
  per-path lookup gives a bijection with this owner's edit lineage. Each file's preimage, postimage and
  current bytes must match the lineage. The diffs are kernel-computed from the same bytes in
  `write_approval::exact_diff`. The packet's base, repository and snapshot must equal the owner's identity
  and a fresh capture, and `validations` must equal exactly the final sealed attempt rebound through the
  kernel binder. `check_completion_validation` additionally requires a linked full pass whose observation
  equals the current capture (`coding_repository_validation_workspace.rs:69`). New-file lineage
  (`created_mode`) is refused.
- **Findings gate.** Visible Medium, High and Critical findings refuse planning before any Git read; Low
  findings pass. Suppressed findings are not consulted, which matches the documented "visible" wording.
- **Modes.** Modes come from the current object's owner-execute bit. The source observation binds mode and
  ctime, and sandboxed commands mount only read-only sealed copies (`command_runner_worktree.rs:123`). Agent
  tools therefore cannot change a mode after review without causing a snapshot mismatch. The write
  primitive preserves an existing executable bit (the 0o700/0o755 cases).
- **Git observations.** The production closure checks the system Git artifact trust first; on this host
  it refuses, as the native-entry test and the diagnostic show. It then uses the existing preservation
  collector on the original and a confined linked inventory on the task worktree. `verify_owned_worktree`
  takes the pointer from the worktree, but the existing verifier still demands an absolute canonical
  `<original .git>/worktrees/<name>` path compared by `Path` components (no `..` normalisation), the
  `../..` commondir and an exact backlink. A rewritten `.git` pointer also changes the source snapshot.
  Branch, HEAD, manifest, linked identity and inventory are compared in full across both reads, and
  roots, validation and source are rechecked before the inert plan is released.
- **Index identity.** `user_index_sha256` comes from the original repository's manifest, and the
  temporary index is placed in the held management root. This matches what
  `LinuxCandidateTreeBuilder::build` later checks (`local_commit.rs:201-207`).
- **Reachability and honesty.**

    module.
  - The public method has no production caller, HTTP route or CLI route, as the documentation states.
  - The new test-only accessors are `#[cfg(test)]`, and production fields remain private.
  - Synthetic Git and process observations are labelled as such in the code, the evidence and the guide.
  - No native candidate, coding score or model result is claimed.
- **Public-repo hygiene.** Added lines contain no home paths, usernames, hostnames, email addresses,
