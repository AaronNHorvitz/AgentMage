### Adversarial reasoning

- **No way around the packet requirement.** `PreparedLocalCommit`'s fields are private. It has
  no `Deserialize`, no `Default` and no other constructor, so `new` is the only way in, and
  `new` requires the full packet.
  - A forged packet would have to satisfy `verify_review_packet`, which rebuilds the packet and
    compares the whole struct and its digest. Self-hashing therefore cannot hide a material
    finding.
  - Suppressed duplicate and low-confidence findings are checked, and the 40-case test (and
    M10) prove it.
  - The request bytes do not change: the plan plus the approval digest. The plan's
    `review_packet_sha256` binds the retained packet into the grant-bound request hash.
- **Test-only bridge.** `commit_packet_for_test` is `#[cfg(test)] pub(crate)`. The fixture is
  promoted only to `pub(super)` inside `#[cfg(test)] mod tests`, and no product constructor is
  compiled.
- **Debug output.** The manual `Debug` impl prints only `transaction_id`. Before this change,
  the derived `Debug` printed the full plan, including the message.
- **Documentation claims.** The evidence note and guide accurately say this is packet admission
  only, not reviewer, artifact, candidate, signer, owner or consent provenance. They also say
  no product, API, MCP, CLI or native route is enabled. The claim that the check is repeated
  "immediately before issuing its executor permit" is true of the code (`local_commit.rs:1279`).
  The tests exercise the shared `verify_at` guard rather than `execute`, and the note says so.
- **Earlier low addressed.** The first low in the retained b43c967558b3 report (admission only
  at planning; a bare packet hash carried to approval and launch) is addressed as that report

  and the builder says so.
- **Evaluation integrity, delivery, public content and IP.**
  - No evaluator, task, held-out, hidden-test, scorer, prompt, threshold, dependency, SBOM or
    scoreboard path changed.
  - The TASKS row lines are byte-identical to the base (check.py), and no new row or sub-row

  - The added lines contain no private host path, username, hostname, credential or personal

## Findings

No critical, high or medium findings.

- **L-1 (low, backlog, same row).** The dispatch-site packet recheck has no test and adds no
  protection.
  - **Location:** `kernel/engine/src/local_commit.rs:1279` (`self.prepared.verify_at(self.now_epoch_ms)`
    in `EffectDriver::execute`).
  - **Test gap.** Mutation M9 deletes this call and every test still passes. The tests reach
    only `verify_at` directly and the constructor.
  - **No added protection.** `prepared` and `now_epoch_ms` are private and immutable after
    `LocalCommitEffectDriver::new`, which has already run the same check with the same
    timestamp. The dispatch recheck is therefore deterministic and cannot fail if
    construction succeeded.
  - **Pre-existing expiry issue (since be075e8b).** The approval-expiry part of this recheck
    uses the construction-time clock. An approval that expires between driver construction and
    dispatch is not refused by the kernel; only the platform's own deadline applies. This is not
    exploitable today: there is no product caller, and the full approval composition is
    documented as open.
  - **Fix when composing execution:**
    - take the current trusted time at `execute`, or bound it from the `EffectAuthorization`;
    - re-run `verify_at` with that time;
    - add a driver-`execute` test with a consumed-grant fixture. It should show refusal on
      expiry after construction and on any drift, with the executor never invoked.
- **L-2 (low, observation).** `reconcile_local_commit` (`local_commit.rs:996-1004`) is still a
  public raw-receipt path.
  - It mints a `LocalCommitReceipt` from a plan and a raw approval without the packet.
  - It is post-effect reconciliation, not an effect, and its only in-tree caller is the
    driver, which already holds an admitted `PreparedLocalCommit`.
  - **Fix during product composition:** make it crate-private, or take the
    `PreparedLocalCommit` instead. Then no receipt can be produced for a plan that never passed
    packet admission.
- Earlier same-row lows remain backlog: the exhaustive-severity low from b43c967558b3, L1 and
  L2 from e0702bdd9b45, and the earlier T-306 lows.
