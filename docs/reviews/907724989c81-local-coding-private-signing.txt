## Review against the requested points

- **Keygrip attachment and listing binding.**
  - `selected_keygrip` runs over the same `listing` bytes that `signing_identity` validated and whose
    SHA-256 is part of the inspection evidence. It runs only after the export step and the control
    check (`local_commit_inspection.rs:271`).
  - Selection is the exact `fpr` field 10, and `pub`/`sub` lines reset it. Revoker (`rvk`)
    fingerprints are never selected.
  - A duplicate, malformed, missing or all-zero grip returns `None`, which keeps public identity
    usable and refuses private use (`sign_hash` at `local_commit_signing.rs:175-179`).
  - Grips are 40-character hex, so a newline or path cannot be injected into `SIGKEY` or the file
    name.
- **Private capture.**
  - The keyring path must equal its canonical form (`local_commit_signing.rs:47`). Root, directory
    and file are opened with `NOFOLLOW|NONBLOCK|CLOEXEC`, and the directory and file through held
    descriptors with `openat`.
  - The type, uid and mode checks hold: directories must be `&0o077 == 0`, and the file must be
    `&0o7177 == 0`, `nlink == 1` and 1..=128 KiB.
  - Reads are bounded 16 KiB `pread` calls with a control check before each. Control is checked
    again after reading and after sealing, and name, held metadata and directory identity are
    revalidated before reading, after reading and after sealing.
  - The tests exercise every checkpoint, including replacement of the root, directory, file and mode.
  - The decision honestly states the same-user non-atomicity.
- **Secret buffer.**
  - The heap copy is `Zeroizing<Vec<u8>>`. `sealed_payload` writes directly into a memfd, seeks to
    0 and seals it with no intermediate copy. No Debug or serialization, path or digest of the secret
    is recorded.
  - No secure-memory or kernel-erasure claim is made, and the unit sets `MemorySwapMax=0`.
- **Worker.**
  - The worker is a foreground `--server` agent with `--no-options`, `--disable-scdaemon`,
    `--pinentry-program /nonexistent`, no external cache and zero cache TTLs, in a private tmpfs home.
  - The fixed command stream is sealed and reaches the agent through stdin (`systemd-run --pipe`).
    `run_owned` preserves the stdin the caller sets; the filter uses a separate pipe fd.
  - Commands are fixed: `RESET/SIGKEY/SETHASH 8/PKSIGN/BYE`. No shell is involved.
- **Artifacts and owner.**
  - `SigningManifest` holds root-owned `LinuxGitArtifact`s for systemd-run, systemctl, bwrap and
    gpg-agent, and revalidates all four in `control_path`.

## Findings

No critical, high or medium findings.

- **L-1 (low, backlog).** In `platforms/linux/src/local_commit_signing.rs:295-296`, the percent
  decoder accepts a signed escape. `u8::from_str_radix` accepts a leading `+`, so `%+1` decodes to
  0x01.
  - Reproduced: `parse_response(b"OK\nOK\nOK\nOK\nD (7:sig-val(1:x1:%+1))\nOK\nOK\n")` returns
    `Some(..0x01..)`.
  - This contradicts the evidence sentence saying the parser rejects malformed percent escapes. The
    impact is low: the bytes come from the confined agent and are explicitly unverified and carry no
    authority.
  - Fix: require both bytes to satisfy `is_ascii_hexdigit()` before decoding, and add `D %+1` to the
    protocol test's malformed list.
- **L-2 (low, backlog, test strength).** In `platforms/linux/src/local_commit_signing_tests.rs:532-534`,
  the `None` and `"A\nPKSIGN"` keygrip assertions in
  `private_signing_refuses_invalid_selection_before_capture_…` cannot tell which check refused.
  - The keyring `/never-read-private-keyring` would also fail at `verify_private_keyring`. The
    production check at `local_commit_signing.rs:175-179` is correct by inspection.
  - Fix: use a real valid fixture keyring for that signer, so only the keygrip check can refuse.

Observations, not findings (already disclosed as open in Decision 0194):

- The gpg-agent artifact is held and root-owned but not digest-pinned.
- The installed-agent fixture gives the agent a writable copy of the key, whereas production uses a
  read-only bind. Behaviour on a read-only mount and under the socket-denying filter is therefore
  unexercised until native admission is tested.
