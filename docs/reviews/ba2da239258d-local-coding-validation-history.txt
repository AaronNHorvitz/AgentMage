## Analysis

- **Kernel check** (`validation_result_history.rs:30-67`) does the following:
  - It requires 1 to 3 attempts and exactly `n-1` plans.
  - It re-runs `verify_validation_receipt` against the single template, the original `PreparedCommand` and
    the original `CommandReceipt`. That covers template, command, scope, parser and digest binding.
  - It rejects any repeat of validation ids, command ids, approval digests, authority transactions or
    operation ids.
  - For each edge it requires `verify_rerun_plan` (prior receipt digest, failed-names digest, retryable
    failure, command spec and plan digest). The plan's attempt id and approval must equal the immediate
    successor's.
  - The last receipt must be `is_full_pass` (Passed with Complete coverage).
  - A pass cannot sit in the middle of a series, because `retryable_failure` requires a non-zero exit while
    a pass requires exit 0.
  - The check takes only shared references and mutates nothing.
- **Native owner:**
  - `consume_validation` (`coding_repository_validation.rs:274-307`) carries history and plans forward only
    on a rerun. `check_validation_selection` admits an existing series only when the template is identical
    and the attempt count matches. A fresh series starts only when `self.validation` is `None` and attempts
    is 0, so templates cannot be mixed.
  - The edge is recorded and the attempt counted before dispatch (`coding_repository_command.rs:394-399`).
  - `finish_validation` appends evidence only after `verify_validation_receipt` succeeds.
  - `linked_pass_verified` also requires `attempts == history.len()`, so a lost, uncertain or corrupted
    successor keeps the check false permanently. The next prepare is refused with `code.validation.uncertain`.
  - The attempt id and approval recorded in the plan (`command_attempt_id`, `pending.hash`) are the same
    values used in the observation, so real flows can link.
  - A denial returns before `consume_validation`, so it adds no edge.
  - Worktree creation, lease transfer and poison recovery clear the whole series, history included.
- **No new authority:** No executor, permission, grant, parser, budget, replay or restore path is added. The
  only new state is two vectors capped at 3 entries and 2 plans. Inspection exposes `ValidationReceipt`s that
