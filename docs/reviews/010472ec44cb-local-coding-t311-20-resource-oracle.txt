  `return_value` is exactly `subprocess.CompletedProcess`; the candidate rebuilds `CompletedProcess([], rc,
  stdout, stderr)` — identical to the hidden test's `CompletedProcess([], 0, stdout=…, stderr="")` — and patches
  its own `module.subprocess.run` for the same scope. Guard construction forwards the exact positional tuple;
  sample forwards the trusted MagicMock's tuple and patches `module.gpu_memory` on the candidate side for the
  same scope as the original. Guard instances persist in a per-process dict; duplicate IDs refused. Tuple vs list
  preserved by the codec (builder variant `gpu-wrong-container` fails as the original would).
- **Assertion authority.** Hidden methods run unmodified in the trusted namespace; candidate replies are typed
  data only (`unpack_call_value` yields only None/str/bool/int/finite float/Path/list/tuple/str-keyed dict).
  Wrong value/return/error/peak variants fail; falsey `[]`/`None` pass as in the original; reserved tag keys
  inside an `error` map stay data (builder `guard-reserved-data`).
- **Closed schemas / fixed failures.** Trusted side accepts only `{"harness_error": true}` or `{"value": <codec>}`
  (`coding_eval_oracle_worker.py:244-248`) and then requires exactly `returned/error/peak` for samples
  (`:772-774`). HarnessError is reconstructed as the trusted base class with a fixed message; any other
  candidate exception is the existing payload-free tag (builder test confirms the private text is absent from
  wire.log). Candidate side refuses unknown operations/fields, bool instance numbers, out-of-range instances,

  the refused output directory is never created; CLI `main` is unchanged. Probe snapshots use mocks only in tests.

## Findings

No critical, high or medium findings.

**L1 (low, backlog before generated scoring) — equality-passing subclass/unsupported values are refused.**
`scripts/coding_eval_oracle_worker.py:521-536` (`pack_call_value`, exact `type(...)` checks) via
`resource_result` `:829`. A candidate whose `gpu_memory` returns a `namedtuple` with the correct values, or whose
`sample()` returns a falsey `frozenset()`, passes the original assertions under the legacy verifier but is
graded `adapter_policy` failure by the oracle (reproduced above). The guide (`docs/guides/coding-evaluation-oracle.md:304`)
discloses "unsupported containers … are adapter policy", and the cause is labelled distinctly, so this is not a
hidden claim; but it is a false-negative path for plausible correct implementations ("returns (used_mib,
free_mib)"). Fix before generated scoring: either encode tuple/int/str subclasses as their base type when the
original assertion is equality/truthiness only, or name the subclass divergence explicitly in coverage and keep a
contrast probe for it.

**L2 (low, pre-existing pattern, backlog) — sticky candidate-exception inflates later method errors.**
`RemoteFunction.__call__` `:183-184` makes every call after one candidate exception fail. In the
`ValueError`-on-malformed probe the oracle reports 2 errors where the original suite would report 1 (test 2 would
pass). The pass/fail verdict is identical and failures are counted, not dropped; per-method counts should not be
published as original-suite counts without saying so. Fix: document in the guide that post-exception methods
are counted as errors, or reset the sticky flag per hidden method.
