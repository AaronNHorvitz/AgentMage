## Review of the change

- **Checkpoint placement.** `run_with` checks `session.control_active()` once before
  `branch_before`, after each of branch, sign, write, read+`verify_raw_commit`, verify and update,
  and after postflight. The pure `verify_raw_commit` check runs before the checkpoint, which is
  harmless. A stop returns `uncertain_commit_result` (outcome `Failed`, `cleanup_verified=false`,
  no commit object or branch fields). `reconcile_local_commit` rejects any outcome other than
  `Succeeded`, plus missing `commit_object` and `!cleanup_verified`
  (kernel/engine/src/local_commit.rs:935-961). So a stop after CAS or postflight cannot become a
  receipt, and nothing implies rollback. Before any dispatch, `preflight` cancellation returns a
  `Denied` no-effect result with the approved manifest, which is correct because collection is
  read-only.
- **Control source.** `NativeSession::control_active` uses the original `cancellation` reference
  passed to `run_plan` and the same `io.deadline()` that `sign` and `verify` already receive. That
  makes it consistent with the existing worker bounds, and every worker still gets the token.
  `CancellationToken::clone` shares the `Arc` node, so the test's "propagated" clone is a genuine
  same-token cancellation.
- **Mutation adequacy.** For each `completed` in 0..=7, the stop is injected at the end of stage
  `completed`, and the test asserts the exact call prefix `ORDER[..completed]`.
  - Removing any one of the 8 sequence checkpoints lets the next stage run, or turns the final
    result into `Succeeded`, so the test fails.
  - Removing either `preflight` check fails the panic closure or the propagated-cancel assertion.
  - The test also asserts that the stored object exists from `write` onward and that `update` ran
    exactly when `completed >= 6`.
  - Both object widths (40 and 64) and both cancellation and expiry are covered.
- **No new authority.** `Session` and `run_with` remain module-private. `preflight` is
  `pub(super)` and only gates a caller-supplied collector closure; it grants nothing. There is no new
  public API, permit, fallback, trust exception or product route.
- **Confinement and untrusted input.** The diff adds no new filesystem, network, process,
  environment or parsing surface, so there is no new escape surface to reproduce. Existing
  confinement tests among the 79 controls pass (for example
  `policy_denies_every_worker_socket_and_connection_syscall` and
  `commit_io_worker_refuses_unsealed_foreign_network_and_unsafe_mutation_scopes`).
- **Evaluation integrity.** The diff touches no evaluation, hidden or held-out data, scorer,
  prompt, threshold, dependency, SBOM or scoreboard file (diff stat: 7 files, all listed in

## Findings

No critical, high or medium findings.

- **L-1 (low, backlog; acknowledged by the builder).** Native forwarding is untested.
  `platforms/linux/src/local_commit.rs:451` (`run_plan` → `execution::preflight`) and
  `platforms/linux/src/local_commit_execution.rs:45-47` (`NativeSession::control_active` →
  `io.deadline()`) have no test that would fail if the native wiring were reverted or returned a
  constant. Today the only native tests stop at artifact admission. Fix: once a native fixture can
  be admitted, add a native-entry test with a precancelled token that asserts the collector is never
  invoked and the result is `linux.git.commit.preflight`. Also add one native run whose `CommitIoSession`
  deadline has already passed and that returns `control_stopped` with no dispatch.
- **L-2 (low, backlog).** The checkpoint before `branch_before`
  (local_commit_execution.rs:141) reports `Failed`/uncertain (`control_stopped`) although no worker
  has been dispatched. The `preflight` stop, by contrast, reports `Denied` no-effect. This is
  conservative and harmless to safety, but it may push a cancel between session creation and the
  first stage into recovery handling that is not needed. Fix if desired: return
  `failed_commit_result(&before, "linux.git.commit.control_stopped")` for that first check only,
  after confirming that `CommitIoSession::new` has no effects.
- **L-3 (low, observation).** Postflight collection is not bounded by the I/O deadline, but
  the final checkpoint enforces that deadline. A slow postflight after a successful CAS therefore
  yields an uncertain result for a commit that did land. This trade-off is documented and
  fail-safe, and no receipt is falsely issued. Recovery should be able to reconcile this case
  durably (already open under durable recovery).

Earlier same-row lows, including L-1 from the 0c859b28ff89 review, remain backlog.
