## Findings

No critical, high or medium findings.

- **L1 (low, test robustness)**, `platforms/local-api/tests/support/coding_workflow.rs:220`. The
  `first-selection` case targets reply index `7` by a literal. If the workflow's route order
  changes, the literal could silently move to a different reply. The `routes[..calls.len()]`
  assertion would not catch that, because it checks the recorded order, not the target route.
  Fix: find the index by position, as the `repair-*` cases do, for example the second
  `GET /v1/code/workspace` after `POST /v1/code/repository/validation/prepare`, or assert
  `script.routes[index]`.
- **L2 (low, coverage; carries predecessor L2)**,
  `platforms/local-api/tests/coding_worktree.rs:1105-1164`. The actual-API repair pin test
  reaches only `code.command.worktree-required`. No test sends a correctly pinned repair
  proposal through the real service with an owned failed receipt, and no guided command runs
  against the actual service. Fix: cover this when native or actual-service guided consumer
  evidence lands. It belongs to the existing same-row backlog; it is not a new sub-row.
- **Informational.** The repair route returns `409 code.repair.scope` for a root-pin mismatch,
  while the workspace route returns `409 code.workspace.root-stale`. Both are documented
  (`coding-model-repair.md`, `coding-workspace.md`), so this is not a defect.
- **Carried, not fixed by this commit (as the evidence states):** predecessor L1 (the prepare
  reply is not bound to the first edit inspection) remains open backlog. The guide now describes
  the narrower check accurately (`coding-guided-worktree.md:60-66`).
