## Findings

No critical, high or medium finding.

- **L1 (low, backlog), `platforms/linux-inference/src/local_chat_transport.rs:359-361`:** the new
  `Zeroizing::new(serde_json::to_vec(messages)...)` only zeroizes the final allocation. `to_vec`
  starts at a small capacity and reallocates as it grows, so every earlier buffer holding private
  conversation content is freed without being erased. The evidence and guide wording ("the temporary
  message encoding is zeroized on drop") holds only for the last buffer. The body encoder already does
  the same (`platforms/linux-inference/src/local_chat.rs:221`), and this change adds a second copy.
  Fix: compute the context with `serde_json::to_writer` into a small writer that updates `Sha256` and
  counts bytes, which needs no buffer. Alternatively, serialize into a `Zeroizing<Vec<u8>>` pre-reserved
  to `body.len()`; the array is strictly shorter than the body, so it never reallocates.
- **L2 (low, backlog), `platforms/local-api/tests/local_chat_api.rs:196-260` and `:495-531`:** the guide
  documents the wire values `finish: "stop"` and `finish: "output_token_limit"` for
  `runtime_model_result` (`docs/guides/coding-proposals.md:162`), but no API test reads
  `runtime_model_result.finish`. The transport test compares the enum value, not its serialized string,
  so renaming the variant or its serde casing would silently change the documented API. Fix: in
  `assert_endpoint_runtime_observation`, or in the length case of the truncated-generation test, assert
  `result["finish"] == "output_token_limit"` for the length suffix and `"stop"` on the success fixture.

Carried backlog: predecessor low L1 (a route-level preparation-refusal test with a native failed-test
receipt) is unchanged by this increment.
