## Code review

- **Hint soundness against the checker** (capabilities/repository-map/src/coding_proposal.rs:170-187 vs 610-632).
  - The hint takes each `split_inclusive('\n')` line with its exact bytes (CR and LF retained; the final unterminated
    line without LF). It finds the first occurrence, then searches again from the next character boundary. This is
    exactly the checker's overlapping-aware whole-file uniqueness test on the text `resolve_edit` derives for a
    single-line range.
  - A string containing a unique line is itself unique. So any range inside one excerpt that includes an advertised
    line passes uniqueness, and the compressed intervals cannot mislead.
  - Whitespace-only lines are never advertised. This is advisory only and grants nothing.
- **Visibility of advertised lines.**
  - Every excerpt candidate is line-aligned: parser ranges are widened to full lines at :337-346, the whole-file
    candidate and the line windows use line bounds, and merging aligned ranges preserves alignment. So every line
    from start_line to end_line lies wholly inside the excerpt.
  - Hints are clipped to that range with `partition_point` over sorted anchors (:141-152).
  - The new test checks every advertised anchor through the unchanged checker.
- **Index consistency.**
  - `anchors` is computed from the same canonically sorted `sources` vector that `render_source_context` indexes
    with `position` (:313-316, :131-135). Indices therefore agree.
  - `expect` calls cannot fire: the line is a substring of the source, and it is non-empty after the whitespace check.

- **L-1 (low, backlog T-309): intermittent flake in the MCP stdin test.**
  - Location: platforms/local-api/tests/coding_cli.rs:65-69.
  - Problem: the test writes all MCP messages with `write_all(...).unwrap()` before `wait_with_output`. If the child
    exits or closes stdin early, the write gets EPIPE and the test panics before the child's actual output is asserted.
  - Reproduction: observed once in the full gate, then 5/5 passes in isolation.
  - Fix: write stdin on a separate thread, or tolerate `BrokenPipe` and then assert on the child's exit status and
    replies.
  - Not caused by this diff.
