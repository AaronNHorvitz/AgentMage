## Verification of the requested properties

- **Identity binding, end to end.** The CLI takes `root`/`tree` from `GET /apply`, accepting only
  64-hex digests. It checks both against the typed paths before and after consent
  (`coding_cli.rs:477-490`). It displays both identities in the escaped JSON and in the exact
  `read <root> <tree>` token, and sends both in the POST body (`coding_cli.rs:495-496`). The
  terminal test asserts the exact wire JSON, including both identities, and the token in the
  transcript. `PrepareApply` makes both fields required `String`s under `deny_unknown_fields` and
  `object_json`. The API test refuses missing, null, numeric, array, object and duplicate-key
  values with 400, and 403 without control. Duplicate fields are rejected by the serde-derived
  struct.
- **Order before reads.** `prepare_apply` (`coding_repository_apply.rs:65-73`) compares both
  strings against the in-memory held pair (`created.original` / `created.held`). It does this
  before `verify_apply_roots`, source selection, any read, `prepare_write` or the
  `self.apply = Some(..)` assignment. The comparison is exact and byte-wise. My probe confirms
  that uppercase, trailing-space, trailing-newline, truncated, swapped and duplicated digests
  refuse `code.apply.read-scope`. The builder test parks the original root and selects an
  ineligible path; the refusal still comes first, and the preview, receipts and both sources'
  bytes are unchanged. The repository mutex is held across the check and use, so creation cannot
  interleave.
- **Preserved preview stays usable.** My probe shows that after six stale refusals the earlier
  pending preview still decides and commits its exact bytes, and human work is preserved.
- **Digests cannot adopt.** The digests are only compared, never used to resolve a path. With no
  held pair (restart), correct old digests refuse and nothing is pending or written (probe). With a
  same-path recreated worktree (new directory object, identical bytes) the held identity changes,
  and the old consent refuses (probe). This confirms the digest binds the object, not only the
  path.
- **Separate write consent is unchanged.** `decide_apply`, its grant and transaction, consumption,
  expiry and lineage consumption are untouched by the diff. There is no automatic retry in the CLI
  or API. Synthetic peer and creation injection stay inside `#[cfg(test)]` modules or integration
  tests, and are labelled.
- **Retrieval.** The native producer caps raw content at 64 KiB
  (`coding_development_runtime.rs:830-851`). JSON escaping expands it to at most about 6× (`\u0000`).
  The test's largest envelope is 393,246 bytes. The decode now covers that envelope. `matches`
  still scans only `take(65_536)` of the decoded content, which covers an entire admitted source.
  Both boundary controls (a term inside versus beyond byte 65,536) behave correctly. Only
  `item_id` changes; the test restores it and asserts full `CodingContextSource` equality
  (provenance, hashes, excerpt bytes). Ranking only applies to the eligible, non-essential
  `repository-source-<16 hex>` tier with a `agentmage:workspace-file:` source id. Only the native
  producer emits that tier, and repository text sits inside a JSON string, so parsing cannot
  amplify its structure. Token counting and model admission code is unchanged.
- **L2 documentation.** The new guide paragraph matches the code
  (`coding_repository_edit.rs:49-75`): more than 16 distinct paths across held and new edits gives
  `code.edit.lineage-limit`. A preimage differing from the last committed postimage gives
  `code.edit.lineage`. A new creation resets `edits` (`coding_repository.rs:421`). Restart drops
  ownership. Nothing is weakened.
- **Honest claims and hygiene.** The evidence states that the prior batch's L1 repair was

  makes no native, model, GPU, score or release claim. The added lines contain no private host

### L1 (low, backlog): owned-edit read consent still names a root digest the server does not bind

Location: `platforms/local-api/src/coding_cli.rs:446-461` (`edit_prepare`) and
`platforms/local-api/src/coding_repository_api.rs:68-75` (`PrepareEdit`). This code predates the
diff and has the same pattern as the original-apply L3 that this commit repairs.

The terminal requires `read <worktree-root-digest>`, but the body sends no identity. Suppose a
separately approved new creation completes during the prompt. The server then reads the new held
worktree. The per-source `expected_sources` hashes limit this to files with identical bytes, and
the result is an inert preview returned to the same trusted caller. Fix: add a required
`expected_worktree_root_sha256` to `PrepareEdit`, compare it against `created.held` before
`select_created_sources`, and send the displayed identity from `edit_prepare`.
