## Analysis

- **Composition and consent.** `endpoint-run-apply-saved` routes to `endpoint_transfer::run(.., drive=true)`
  (`coding_cli_endpoint.rs:246`). Inside the single `workflow::bounded` guard, it checks the selection
  and controlled mode, then calls the same `guided_steps` used by `endpoint-run`
  (`coding_cli_endpoint.rs:151`). After that come `save_observed`, the release confirmation, the
  original read and the apply decision. All steps share one `Client` with the guard's deadline and
  signal latch. Every confirmation still goes through `Client::confirm`, which returns Err on deny or
  stop and re-checks running. Each exact token is distinct: `share <digest> step-N`, `allow <challenge>`,
  `save-record <digest>`, `release <digest>`, then the existing read/apply tokens. The main PTY test
  shows the seven prompts in order. It also shows the record saved before the release prompt and the
  write preview before the apply prompt.
- **No implicit actions.** Every error path returns `Err(())`; there is no retry, cancel or release
  path. The four uncertain-reply cases (close, 409, header stall with a 1 s deadline, SIGINT during a
  body stall) stop after the third call, and no record is written. Declines at each of the five phases on
  both service types leave the original and worktree preserved. Event-state and repository-apply status
  match the phase reached. The upstream model listener sees no connection on a cancelled run.
- **Archive placement.** `archive_scope` (`coding_cli_endpoint_transfer.rs:10`) requires an absolute,
  canonical path, refuses a `Path::starts_with` (component-wise) match against either root, and
  requires a 0700 owner directory. Both roots were already verified canonical and symlink-free at lines
  39-54, so component-prefix comparison is sound. It runs before any HTTP (line 81), before and after
  saving (96/98), and after the release confirmation (112). `save_observed` independently holds the
  directory fd and rechecks dev/ino/mode/uid. This addresses private-record review L1. The documented
  limit, that metadata checks give no lease against concurrent ancestry moves, is accurate.
- **Step-bound tokens.** The token now includes the local loop index. A queued earlier token fails the
  next disclosure, so the held `allow` is never sent. This addresses guided-endpoint review L1.
  Single-shot `endpoint-step`/`endpoint-approve`/`endpoint-deny` keep `share <digest>` (`None`), as
  claimed. Residual note, not a finding: the counter restarts at step-0 in each new process and confirm
  does not discard pending terminal input. A line queued into one chained command could therefore
  satisfy step-0 of the next. At step-0 the response is `None`, so no tool approval can be carried, and
  an interactive shell would normally consume leftover input first.
