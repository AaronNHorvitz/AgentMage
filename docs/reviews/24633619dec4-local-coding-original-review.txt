## Findings

No critical, high or medium findings.

- **L1 (low, error reporting):** `platforms/local-api/src/coding_endpoint_api.rs:555`,
  `let repository = convert(tool)?;`. If extraction fails after `release_with_tool_boundary`
  has already marked the entry Released, the handler returns `Err`. `serve_connections`
  discards that error (`lib.rs:419`), so the client gets a closed connection with no status.
  Ownership is lost: a later release returns 409 and apply returns 428. The client cannot tell
  this apart from a lost success reply until it inspects. The same applies to the unreachable
  `review.repository.is_some()` 500 branch at line 557, which silently drops the extracted
  owner. This is documented ("extraction errors may lose ownership") and has no
  confinement or data-loss effect on the original checkout. It is the review-mode counterpart of
  base L1.
  - Fix: before returning, write an explicit `500 {"error":"code.endpoint.release-extraction","ownership":"lost"}`
    response.
  - Fix: add a test with a boundary whose extraction refuses.
  - Severity: same-row backlog.
- **L2 (low, coverage):** no test drives the terminal client against a review service
  (`agentmage-code … original`, `original-prepare`, `original-apply`), although the guide
  documents that path (`docs/guides/coding-runtime-api.md`, "Review the original diff in the
  endpoint service"). I confirmed reachability only by code reading: `coding_cli.rs:590-668` uses
  only the three published routes with the control token.
  - Fix: add one client-level test against `serve_coding_endpoint_strict_edits_with_repository_review`.
  - Severity: backlog.
- **L3 (low, coverage, honestly labelled):** in the combined review fixture, the transferred
  lineage comes from an edit made through the same owner before the run. No model edit approved
  inside a combined run is transferred, because native validation preparation is blocked in
  this lane. The evidence states this plainly, so it is not a claims problem.
  - Fix: once native validation preparation works, add a combined-run case in which a model edit
    is approved, then transferred.
  - Severity: backlog.

Base lows L1 (returned-owner extraction failure after release response) and L2 (direct older
non-turn service coverage) remain open as same-row backlog.
