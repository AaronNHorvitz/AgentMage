## Findings

No critical, high or medium finding.

- **L1 (low, backlog): existing-file mode is not bound to the immutable base.**
  platforms/linux/src/coding_repository_commit_review.rs:258-275 derives `CommitFileMode` from the
  current executable bit. The new check at :293-308 compares only content digests. `ReviewableChangeSet`
  does not carry a file mode (kernel/engine/src/review_packet.rs). A base `100644` file whose execute bit
  is set before or after its approved content write could therefore enter the inert plan as
  `Executable`, with no reviewed change and no base-preimage refusal. For example, a confined validation
  command could run `chmod +x` inside the worktree, and the review would show only the content diff. This
  predates this commit, and Decision 0187 scopes the check to content, so it is not a regression. It is,
  however, the same "starting change becomes commit content" class. Fix: keep the base tree mode for
  each selected blob in `collect_with`, which `parse_tree` already reads. Refuse when the planned mode
  differs from the base mode for an existing-file edit, unless a reviewed, approved mode change exists.
  Add an owner test with a base `100644` entry and a current 0o755 file.
- **L2 (low, backlog): whole-tree refusal is broader than the selected paths.**
  repository_base.rs:137-139 refuses the entire base if any entry anywhere in the tree has a non-UTF-8
  name or a control character, such as a newline (reproduced above). The 4 MiB transcript cap also binds
  well before 100,000 entries: records are about 55 bytes plus the path, so the practical ceiling is
  roughly 40-60k entries. Both outcomes fail closed and are correctly documented as limits, so this is
  only availability. Unrelated unusual names or medium-sized repositories make candidate planning
  unavailable. Fix when needed: skip validation of unselected records that are not ancestors of a
  selected path, or read only the ancestor trees with `ls-tree -z <tree-oid>` per level. The ancestor
  and blob checks stay unchanged.
