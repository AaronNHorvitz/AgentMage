## Findings

No critical, high or medium findings.

- **L1 (low, backlog): a near-ceiling schema is accepted but makes every later chat fail
  generically.** `ChatOutputSchema::new` (`platforms/linux-inference/src/local_chat.rs:220`)
  enforces no size limit of its own. A trusted settings choice can carry a schema of up to about
  256 KiB (`platforms/local-api/src/lib.rs:92`), which takes the whole 256 KiB encoded-request
  ceiling (`local_chat.rs:13`). PUT returns 200, and each later chat or proposal then fails with the
  generic request error, without saying the schema used up the budget. This is reachable only by
  the control-token owner and is fail-closed, so it is not a security issue. Fix: refuse schemas
  above a stated share of the request ceiling at PUT, or report the schema's encoded size in GET.
- **L2 (low, backlog): no build receipt ties the measured binary to its source.**
  The retained `finalize_measurement.py` copies `<repo>/target/debug/agentmage-local-api` after
  checking the five Rust source hashes and a clean HEAD. It does not record the build command or
  prove the binary was rebuilt from those bytes (`chat_transport_binary_build` is null in the
  retained policy). The captured `json_schema`/`strict:true` bodies show the new code ran, so this
  checkpoint is not in doubt. Fix: build in the same step and record the command and output hash.
