## Findings

### M1 (medium, correctness of the model-visible context): tool payloads reach the model as decimal byte arrays

**Where.** `shells/host/src/coding_endpoint_context.rs:192-195` and the `CurrentContext` fields at
`:249-252`.

**Problem.** `actual_completed_calls`, `untrusted_tool_results` and `pre_effect_refusals` serialize
raw `ToolCall`, `ToolResult` and `RuntimeToolRejection`. Their `ContractPayload.bytes` therefore
becomes `[123,34,…]` on the wire (reproduced above).

The existing native coding context already handles this case explicitly. At
`shells/host/src/coding_context.rs:583-604` it verifies each payload's digest and decodes arguments
and outputs into JSON or UTF-8 content. Its own comment says "The model gets verified UTF-8 instead
of a decimal byte array". The new production context regresses that established projection. It
also skips the per-payload `sha256` check performed at `coding_context.rs:572` and `:590`.

**Failure scenario.** In the claimed two-turn loop, turn 1 approves `read_text` on `src/lib.rs`.
Turn 2's user message then carries the file content the model asked for only as decimal codes, and
the model's own prior arguments the same way. A real local model cannot reliably read source from
this, so the read tool, which is the only useful tool in the read-only catalog, does not deliver
information through the surface it claims.

The encoding also inflates each payload about 3.6 times (24 bytes become 86). A single 32 KiB read
alone takes about 115 KiB of the 256 KiB kernel ceiling. Because overflow is a whole-run
`Exhausted` refusal by design, runs end after a few reads.

The tests cannot detect this. They compare the context to `serde_json::to_value(&results)`, the
same raw form (`coding_endpoint_context_tests.rs:265-276`), and the socket model ignores the
content. The guide's "Tool records retain their original payload bytes" is literally true but
hides that the model cannot use them.

**Fix.**
1. Project calls, results and refusals as the native context does:
   - verify `payload.sha256 == sha256(bytes)`;
   - decode UTF-8, and parse it as JSON when the media type is `application/json`;
   - emit `{schema, media_type, sha256, content}` in place of `bytes`;
   - refuse with `Invalid` on any mismatch or non-UTF-8 payload;
   - keep the bounded streaming writer.

   Reusing the existing `coding_context.rs` projection helper is preferable to a second copy.
2. Update the context test so it asserts readable content, for example the read result's `text`
   containing `fixture()`, and a refusal on a digest mismatch.
3. Have the turn-2 socket assertion check that the result content is readable source.

### L1 (low, backlog): the overflow test does not directly assert that permission and model request never started

**Where.** `coding_endpoint_context_tests.rs:520-529`.

**Problem.** The README and test name claim "no permission entry". The test asserts zero
executions, no accepted connection and no `ModelCompleted`, but not the absence of
`PermissionRequested`, `PermissionDecided` or `ModelRequested`. The behavior holds by construction,
because preparation fails before any proposal. This is the same pattern as predecessor L3.

**Fix.** Add a `matches!` over `coordinator.events()` that excludes those three kinds.
