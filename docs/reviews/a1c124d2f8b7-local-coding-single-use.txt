  - The field is private and set nowhere else. The constructor initialises it to `false`.
    `into_executor` consumes the driver.
  - So no caller can reset it. A later entry returns `EffectLaunch::failed()` without touching
    `receipt` or `error`, so original evidence is neither replaced nor recreated.
  - The coordinator records the refused reentry as a `Failed` "worker-launch-failed" terminal for
    the second transaction (`authority_transaction.rs:764-779`). That is accurate, because nothing
    was launched.

  expiry, argument mismatch, unsealed packet and cancelled.

## Findings

No critical, high or medium findings.

- **L-1 (low, pre-existing, recovery semantics):** `kernel/engine/src/local_commit.rs:1342-1344`.
  - The problem: when the executor has already run but reconciliation fails (for example
    `cleanup_verified = false` → `ResultDenied`), the driver returns `EffectLaunch::failed()`.
    That constructor is documented as "the effect boundary was not crossed"
    (`authority_transaction.rs:420`).
  - The coordinator then terminalizes the transaction as `Failed`/"worker-launch-failed", with
    `uncertain = false` (`authority_transaction.rs:768-779`).
  - The new "uncertain" case shows the executor launched (launch count 1) but asserts only
    `!= Succeeded`. A durable owner reading the coordinator journal would see a non-uncertain
    failure for an attempt with unknown effects.
  - This commit did not change it, and the driver is dormant.
  - Fix during product composition: after executor invocation, return
    `EffectLaunch::completed(EffectResult::from_redacted_material(OperationOutcome::Uncertain, …, StateChange::Uncertain))`
    or something equivalent for any reconciliation error. Assert that the coordinator outcome is
    `Uncertain` in the "uncertain" case.
  - Same-row backlog.
- **L-2 (low, evidence wording):** `docs/evidence/t306-single-use-2026-11-10.md:31`.
  - "The focused run passes all fourteen" refers to the initial focused run, at 13:46. That run

  - Fix: say "initial focused run (before the final single-assertion removal)" next time.
  - Backlog.
