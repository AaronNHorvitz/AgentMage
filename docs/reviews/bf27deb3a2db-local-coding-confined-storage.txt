Independent experiments, with disposable material in `/tmp` only and no host keys:

1. **Minimal-MPI verification (M-1).** I created a disposable GNUPGHOME and an rsa2048 key, and ran
   `gpg --detach-sign --digest-algo SHA256` over random data until a signature packet carried an
   MPI of 2,040 bits or fewer. That happened on the 37th signature: a minimal 2,040-bit MPI whose
   integer has a zero leading octet at modulus width. `gpg --verify` reported GOODSIG and VALIDSIG.
   So a stripped minimal MPI from a zero-led modulus-width value is the form GnuPG itself emits and
   verifies. Together with the deterministic equivalence test (padded expression gives a
   byte-identical packet), this means a naturally zero-led agent value now gives a verifiable packet.
   I then stopped the agent with `gpgconf --kill gpg-agent`.
2. **Git identity acceptance (L-3).** I ran `git hash-object -w -t commit --no-filters --stdin` in a
   disposable bare repository.
   - Accepted: `A. <a@b.c>`, `Ünïcødé  Name <ü@b.c>`, `N <"q\\x"@b.c>`, `N <a@b.c>`, ` N <a@b.c>`,
     `N  <a@b.c>` and `N <a b@c.d>`.
   - Refused: `A> <a@b.c>` (badName) and `N <a>x@b.c>` (missingSpaceBeforeDate).
   - Every identity Git refuses contains an angle bracket, and the new check in `Prepared::new`
     refuses those. The whitespace refusals are stricter than Git, which avoids normalization
     mismatches with commit-tree. Together with the kernel's control-character, non-empty-name and
     domain-charset rules, no accepted identity is one that Git refuses.
3. **L-3 test is not vacuous.** The test recomputes `identity_sha256` as
   `sha256(serde_json::to_vec(&(author, committer)))`. This equals the kernel's `canonical_sha256`
   (`kernel/engine/src/local_commit.rs:1337`), and `reseal` uses the kernel's `ZERO_SHA256` for the
   plan hash. `valid_identity` accepts every mutated value (`<bad`, `bad>`, ` leading`, `trailing `,
   a trailing NBSP), so the refusal is produced by the new check. The signer closure panics, so
   refusal before signing is proven.
4. **Test-only direct creation.** `LOCAL_COMMIT_CHILD`, `LocalCommitCapture`,
   `capture_local_commit_process(_in)`, `finish_local_commit_capture`, `SignedGitRunner`,
   `object_output`, `signed_commit_arguments` and `format_git_date` are now `#[cfg(test)]`. The
   module-level `#![allow(dead_code)]` in `local_commit_packet.rs` was removed. The diff adds no

5. **Isolation repair.** `signer_inspection_installed_gpg_reads_sealed_public_identity_without_an_agent`
   calls `capture_local_commit_process` directly (`local_commit_inspection_tests.rs:747`). It was the

## What holds

- **M-1 repaired.** `rsa_scalar` (`local_commit_packet.rs:174-199`) keeps the single fixed prefix,
  the decimal length without leading zeros (at most 4 digits, 1..=1024) and the exact `)))`
  terminator with no trailing data. It then strips leading zero octets and returns `None` for an
  empty or all-zero value (`position(..)?`). The MPI bit count is computed from the stripped first
  octet (`:137`).
  - Tests: `commit_packet_zero_led_rsa_values_form_the_same_minimal_packet` covers padding of 1, 2
    and 8 octets and up to the 1,024-octet bound, with byte-identical packets, and refuses all-zero
    values of 1, 2 and 1,024 octets.
  - Real signatures: the disposable RSA test injects a zero-led form of each actual captured
    primary and subkey signature in both formats. It gets bytes identical to the stored commit and
    verifies them through the public-only verifier with `verify_signature_status` for the exact
    fingerprint.
  - The code comment is corrected. The previous evidence file now opens with an explicit
    correction, and its historical counts and failures are unchanged.
- **L-3 repaired.** `Prepared::new` (`:73-83`) refuses `<`/`>` in names and emails,
  leading/trailing (Unicode) whitespace in names and emails, and any whitespace in emails. It does
  this before any signer call. Accepted bytes are inserted verbatim. Installed Git stores and reads
  back the accepted fixture bytes exactly (`local_commit_packet_tests.rs:587-633`) and moves no ref
  (`for-each-ref` is empty).
- **Verified value.**
  - `VerifiedCommit` has private fields, no derive except a redacting manual `Debug`, no
    `Clone`/`Serialize`/`Deserialize`, and no mutating method.
  - It can only be constructed inside the `packet` module, by `sign_commit_with` after
    `split_signed_commit` content equality and the injected verifier. Production `sign_commit`

- **Closed session** (`repository_commit_io.rs`).

### L-4 (low, test coverage, same-row backlog): executor composition is unexercised in this lane

- **Location:** `platforms/linux/src/local_commit.rs:469-500`. The only executor-level test,
  `native_signed_commit_verifies_exact_content_and_only_updates_task_branch`
  (`local_commit.rs:2022`), is an inherited failure at `generate_signer` (`:1946`, `ArtifactDenied`).
- **Reasoning:** the session state machine enforces Branch → Write → Commit → Update. It does not
  enforce that the executor runs the second public-only verification between readback and CAS. It
  also does not enforce that a verification failure after storage maps to an uncertain result
  rather than proceeding. Both hold by reading (`:486-497`), but no runnable test would catch a
  later reordering or deletion. The same is true of the new `storage_failed` mapping.
- **Fix:** add a deterministic seam for `run_plan`, like `step_with`, with a synthetic
  signer/verifier/dispatch. Assert the call order, that a verification failure after readback never
  dispatches `update-ref`, and that each post-dispatch failure yields `Failed` with
  `cleanup_verified: false`.

The earlier same-row backlog (L-1, L-2 and older lows) remains open, as the request states.
