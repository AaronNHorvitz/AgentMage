## Assessment

**Confinement and authority.**

- `serve_coding_endpoint_prepared` (platforms/local-api/src/coding_endpoint_prepared.rs:48-86) is a thin
  composition. It calls the trusted factory once with fresh identities, then the original `prepared.admit`. Admission
  runs `check_sources` and then the original `CodingEndpointRuns::admit` with the original native boundary. The
  wrapper maps any error to `Configuration`.
- The existing `serve_admitted_endpoint_inner` still does the following:
  - refuses a pre-set stop and non-loopback listeners;
  - refuses a request whose run/session differs from the fresh identities (this is how the foreign-run case is
    refused);
  - requires the control token and per-advance model-disclosure consent;
  - binds every route to the exact run_id and request_sha256.
- The new code adds no wire route, no deserialized authority, no executor and no permission logic. Return to the
  owner is `boundary.map(into_repository)`, which abandons any pending preview through the original native boundary.
  The test checks this: `pending` is null after return.
- The schema projection maps two exact schema IDs to the original 112-byte constant. The full-digest comparison
  (coding_tools.rs:318-320) is unchanged. The new test confirms that a substituted ID or digest is refused for both
  catalogs. The constant matches the original literal byte for byte; audit.py checks this against the base commit.
  The constant is schema text only and carries no effect authority.
- The test-only `with_test_created_worktree` (platforms/linux/src/coding_repository.rs:167-184) is compiled only with
  the dev-only feature. It records an explicit `synthetic-test-creation-not-native-git` receipt hash and refuses if
  any creation or pending creation already exists. It is not reachable in normal builds and does not change native
  Git or executable trust.
- I found no traversal, symlink or environment-leak path in this diff. The confinement code it relies on (held
  roots, preimage checks, atomic writer, guidance exclusion) is unchanged. The `../escape.py` and `private/…`
  snapshots are refused inside admission, before any model connection or write.

## Findings

No critical, high or medium findings.

- **Low L1: the service-level exclusion test cannot tell which check refused, and has no positive source control.**
  - Where: platforms/local-api/tests/support/coding_endpoint_prepared.rs:322-365 and
    platforms/local-api/src/coding_endpoint_prepared.rs:83.
  - Problem: the wrapper maps every admission error to `ApiError::Configuration`, and the positive service test
    always passes `sources: vec![]`. As a result, the HTTP-level test would still pass if any non-empty source
    snapshot were refused, or if the refusal came from endpoint context composition rather than the guidance
    exclusion.
  - Why it is only low: the exclusion check itself is unit-tested with positive and negative cases
    (shells/host/src/coding_endpoint_prepared_startup_tests.rs:107-125). The test is therefore weak at the service
    level, but the boundary is not untested.
  - Fix: add one positive service case with an allowed, consented snapshot (for example `one.py`), and assert that
    the excluded and malformed cases are refused while the allowed one is admitted.
- **Low L2: fixture cleanup can still double-panic.**
  - Where: platforms/local-api/tests/support/coding_endpoint_prepared.rs:78-81. `Fixture::drop` calls
    `remove_dir_all(..).unwrap()` without the `thread::panicking()` guard that was added to `Api::drop`.
  - Effect: if a test fails and cleanup also fails, the process aborts and hides the primary failure. This is the same
    class of problem as the development SIGABRT.
  - Fix: guard the unwrap the same way `Api::drop` now does.
- **Low L3: the prepared schema IDs are duplicated string literals.**
  - Where: the host match arm (shells/host/src/coding_tools.rs:346) repeats the IDs as literals instead of using
    exported constants next to `LINUX_CODING_PREPARED_INPUT_SCHEMA_JSON`.
  - Why it is only low: if the IDs drift, the result fails closed (SchemaDenied), so this is maintainability only.
  - Fix: export the two IDs from the Linux crate and match on them.

The earlier metadata, aggregate-output, CPU and disk preflight lows, and the command-factory gap, remain same-row
backlog as stated.
