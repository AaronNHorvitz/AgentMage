## Verification of the claimed design

- **Borrow only after consumption and checkpoint.** `WriteApplyAuthorization` is constructed at
  exactly one site (`kernel/engine/src/write_transaction.rs:382`), after
  `revalidate_before_apply`, `consume_for_execution` and `checkpoint(issuer)`. It carries a
  borrowed `&WriteApprovalReceipt`, the same argument the kernel validated. Fields stay private
  and there is no external constructor. The new kernel regression asserts `std::ptr::eq` with the
  original receipt, that the checkpoint ran first, and that the grant is `Consumed` at checkpoint
  time. The receipt grants nothing new: the grant is already consumed, and the caller of
  `execute_write_transaction` already holds the receipt.
- **Capture before dispatch.** `Attempt` clones the authorization's change set and approval
  before calling `native.apply` (`coding_repository_runtime.rs:374-381`). Prior proof is retired
  (`applied_write = None`, line 400) only after candidate shape and lineage checks pass. When the
  candidate check fails, nothing is written, so the old proof still describes on-disk bytes; the
  capture path re-reads them anyway.
- **Correlation at completion.** `complete()` requires `successful_apply` (exact applied index
  set, no failure or uncertainty, reset by `restore`). It also requires the transaction id from
  the authorization, the consumed grant digest, `verify_write_receipts`, verified-op equality
  with the approved change set, and per-receipt transaction and grant ids. It then calls
  `from_native_result`, which checks issued-grant digest and revision, revision+1 consumption, the
  recomputed binding digest (same formula as `write_approval.rs:914`), receipts and outcome. A
  caller-forged `WriteTransactionResult` can at most restate the actually applied, approved
  operations. Proof construction failure leaves the attempted paths removed from lineage, which
  fails closed.
- **Complete coverage only.** Retention requires `ops.len() == created.edits.len()` and, for each
  op, `created_mode.is_none()`, `before == op.preimage` and `after == op.postimage`. Reasoned
  cases: a retry on the same file (A→B, then B→C) gives `before=A ≠ B`, so no proof. A second
  file gives a length mismatch, so no proof. A prior manual creation keeps `created_mode`, so no
  proof. The kernel `ShadowChangeSet` has no creation form, so runtime writes cannot create new
  files. A→B→A then A→C retains proof for A→C, which correctly describes the actual first
  preimage and current postimage. `capture_applied_write_review` independently re-checks the
  same conditions, plus held-root identity and fresh source bytes.
- **Driver reuse and replay.** A second `apply` before `complete` refuses (`write-repeated`). A
  second `complete` with a Committed result and no attempt errors. Dropping without `complete`
  retains nothing and leaves the attempted paths ineligible.
- **Poisoned recovery.** `try_into_repository` now clears `applied_write`. The existing poisoned
  regression creates a manual-edit proof first (`f.edit` sets `applied_write`, and
  `prepare_current_apply` does not clear it), so the new `is_none()` assertion is meaningful.
- **Manual path unchanged.** It still passes `transaction-<change_set_id>`, so the prepared-edit
  binding is unchanged. Relaxing `from_native_result` to accept a caller-provided id is safe
  because the runtime path's id comes from the kernel authorization, not the caller.
- **Reachability.** The production host path constructs the owned driver from the attached lease
  and calls `complete` only after `finish_specialized_effect_event`. The existing local-api owned
  session attaches the lease. `capture_applied_write_review` remains an internal composition
  with no HTTP or terminal route, as disclosed.
- **Honest labelling.** The decision, evidence, TASKS and guide text state synthetic creation
  provenance, a test-controlled publication choice, a memory driver in the kernel test, and no
  actual terminal publication, native Git, model, grade or score. The gate is reported as FAIL,
  the comparison is called non-gate, and the retained base review is byte-identical (verified by
  check.py and light.py).
- **Hygiene and IP.** Added lines contain no private host path, username, hostname, credential,

  divergence would surface only in production. In this lane, all 42 host
