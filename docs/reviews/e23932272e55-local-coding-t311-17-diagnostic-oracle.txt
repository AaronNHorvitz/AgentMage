## Findings

No critical, high or medium findings.

- **L1 (low, pre-existing, all adapters) — out-of-band writes to the protocol fd can substitute
  the observation.** Location: `scripts/coding_eval_oracle_worker.py:706-760`. `candidate()`
  keeps fd 1 as the protocol pipe while running candidate code and its children, and
  `RemoteFunction.__call__` (around line 160) takes the first well-formed line. Reproduction:
  the `forged-frame` probe writes a valid dev-009 frame with `os.write(1, …)` and then raises
  ValueError. The oracle passes, and the real `candidate_exception` reply is left unread. The
  candidate gains no scoring advantage over hard-coding the fixed expected behaviour, because
  the inputs are frozen and the candidate controls its own observations. However, the report
  then reflects behaviour the function did not exhibit. Separately, a child that inherits fd 1
  is labelled `protocol` rather than `test_failure`.
  Fix before generated scoring: in the candidate worker, `os.dup` the protocol fd to a private
  descriptor and `os.dup2(2, 1)` before importing candidate code, so children and
  `print`/`os.write(1)` cannot reach the pipe. In the oracle, after the last call, treat any
  unconsumed bytes from the candidate at EOF as a protocol failure.
- **L2 (low, pre-existing) — host scratch path visible to candidate code.** Location:
  `scripts/coding_eval_oracle.py:131-151`. The candidate can read the bwrap argv from
  `/proc/1/cmdline`, which includes the host case path
  (`<state>/tmp/agentmage-eval-XXXX/candidate`). It contains no username, nothing is
  committed, and logs are private. Before generated scoring, avoid exposing host layout to
  candidates: pass bwrap arguments through `--args FD`, or launch through a fixed-path
  re-exec so PID 1's argv holds no host paths.
- **L3 (low, documentation) — the frame bound in characters is undocumented.** The guide says an
  "oversized but frame-bounded diagnostic" passes. Because the codec escapes non-ASCII
  (`ensure_ascii`), a statement-conforming 16,384-character non-ASCII tail could exceed the
  64 KiB frame and become an adapter-policy refusal. The frozen method's ASCII child cannot
  trigger this. Fix: state the effective bound (bytes after JSON escaping) in the guide's
  diagnostic section.
