## Analysis

Authorization and destination. `prepare_edit_generation` runs
`check_edit_context` (kind == Edit, task == sealed objective, every outline path
parsed as a `WorkspacePath` and outside every excluded scope) before encoding. It
then calls the original `prepare_chat`/`prepare_chat_shared`, which refuses
unless `approval.0 == transport.endpoint` and performs no network I/O.
`RuntimeEndpointModelPhase::for_run` re-verifies the sealed run and requires the
prepared binding's endpoint and model to equal `run.model_selection`. It also
enforces the per-phase message, content, serialized, body, requested-token,
output-byte and total-timeout ceilings. `new` requires the packet to equal the
prepared message fingerprint. The tests cover a foreign task, an excluded path,
command kind, a wrong approval, a wrong transport and two ceiling refusals. All
of them refuse with no accepted socket.

Context integrity. `CodingProposalContext` has private construction, and every
excerpt indexes a file in `outlines`. So checking only outline paths for
exclusions covers all the source text that gets disclosed. The refactor of
`prepare_edit_proposal` into `check_edit_context` behaves the same as the
reviewed base.

Startup seal. `prepare_preview` compares `request_sha256`. `Startup::prepare`
re-seals after appending the guidance policy SHA-256 to the constraints, and
the registry-derived visible tools also go into the seal. The digest therefore
binds the kind, the narrowing policy and the reduced limits. In addition,
`prepare_edit_proposal` re-checks the supplied startup's own kind, task and
exclusions.

Answer handling (untrusted model output). Phase accounting hashes and counts
every fragment against the transport's 1 MiB text limit. The generation callback
adds a 64 KiB cap. A fragment that would cross the cap is dropped, sets
`oversized` and cancels. Later fragments are dropped. Only `Ok` with
`finish == Stop` and no oversize reaches the original strict parser. Without
oversize, the private `answer` equals exactly the hashed and verified stream.
A token limit (`length`), a missing `[DONE]`, an over-cap answer, duplicate JSON
keys and a stale unedited context file all refuse. The prior preview and
worktree bytes stay unchanged, and `dispatch_attempts == 1` is kept for each
case. The answer can only become an inert preview. The mutable/protected check,
the native diff, exact approval and the atomic writer are unchanged from the
reviewed base. A prompt-injected document or answer therefore gets no tool,
command, network or write authority from this path.

Control. The phase latches single use, then checks control before dispatch.
The transport's controlled path checks control around socket waits and
fragments; existing transport tests cover this, see
`platforms/linux-inference/tests/local_chat_transport.rs:1362-1788`. The phase
checks control around each callback and after EOF. `prepare_preview` checks
control before any read. The tests cover stop before dispatch (no socket,
0 attempts), stop inside a callback, and stop between generation and preview.
The control identity is the caller's responsibility and cannot be verified
here. The docs state this.

Accounting and honesty. Usage keeps `completed_*` as `None` on failure, so
missing completed counts stay absent. The docs say plainly, in TASKS.md, the
evidence doc and the guide, that cumulative budgeting across generation and
coordinator phases belongs to the caller. They also say the HTTP fixture's extra
generation phases are outside coordinator accounting, and that the creation,
endpoint and model answers are synthetic. I found no claim of a real model, a
score or a grade. No new wire route, executor, grant or retry is added: the
helper is reachable only from trusted Rust callers.

threshold, dependency, SBOM or scoreboard file. Audit confirms the TASKS.md row

## Findings

No critical, high or medium findings.

- **Low L1: weak refusal assertions in the control test.**
  `shells/host/src/coding_endpoint_edit_generation_tests.rs:514` and `:521`
  assert only `is_err()`. That holds for both the callback-cancelled result and
  the post-stop `prepare_preview`. A regression that refuses for a different
  reason, for example `Scope` instead of `Preparation(Cancelled)`, or
  `Incomplete` hiding a missing control check, would still pass. Fix: assert
  `Err(RuntimeEndpointPhaseFailure::Stopped(ModelOperationStop::Cancelled))` for
  the result. For the preview, assert
  `Err(GenerationError::Incomplete)` in the callback case and
  `Err(GenerationError::Preparation(RuntimePortFailure::Cancelled))` in the
  post-EOF stop case. Same-row backlog.
- **Low L2: fail-closed ceiling mismatch.** The phase ceiling
  (`kernel/engine/src/runtime_loop/endpoint.rs:164`, reached from
  `shells/host/src/coding_endpoint_edit_generation.rs:120`) compares the
  transport's fixed 1 MiB `response_text_limit_bytes` with
  `run.limits.max_output_bytes`. The generation itself never accepts more than
  64 KiB (`coding_endpoint_edit_generation.rs:182`). Any narrowed run with
  `max_output_bytes < 1 MiB` therefore always refuses generation with
  `ResourceExhausted`; the fixtures raise it to 2 MiB (`…_tests.rs:131`). This
  fails closed, so it is not a security issue, but it will block realistic runs.
  Fix: prepare the chat with a response text limit equal to the generation cap,
  or record the requirement in the guide. Backlog.

The earlier lows stay as same-row backlog: the predecessor's L1 workspace
identity check before preview reads, the schema-ID constants and the command
preflight lows. This change does not widen them. The generation helper keeps
the trusted original-owner precondition, and native `bind` still refuses a
foreign workspace before write authority.
