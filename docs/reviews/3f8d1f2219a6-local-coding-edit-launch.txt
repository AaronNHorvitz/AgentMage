  runs before `serve_connections`, no model request is made during startup, and native Git children
  get `/dev/null` stdin. Only the operator's stdin can supply `approve <digest>`, and the native
  owner rechecks the digest, expiry, held roots and Git observations.

  in the real binary.

## Findings

No critical, high or medium finding.

- **L1 (low, test portability): the executable test only passes on hosts where Git is untrusted.**
  `platforms/local-api/tests/coding_endpoint_edit_launch.rs:119-123` always asserts
  `linux.repository.git_artifact.invalid`. On the target Fedora host, `/usr/bin/git` is root-owned, so
  native trust passes. `prepare` would then refuse the synthetic `.git`/`"a"*40` base with a different
  code, and the test would fail. The sibling tests branch on this condition
  (`tests/coding_worktree.rs:340`, `src/coding_repository_tests.rs:401`).
  Fix: branch on `fs::metadata("/usr/bin/git").uid() != 0` (or `LinuxGitArtifact::verify`). In the
  trusted branch, assert the observation refusal and keep the same invariants: empty stdout, no
  credential read, unopened model socket, empty owned root, unchanged source and HEAD.
- **L2 (low, robustness): making stdin nonblocking also affects the terminal's stdout and stderr.**
  `src/coding_endpoint_edit_launch.rs:141-152,236`. On an interactive terminal, fds 0/1/2 share one
  open file description, so O_NONBLOCK applies to stdout/stderr and to any process sharing the tty
  (for example `| tee`) for the whole approval window. I reproduced this with a pty and a duplicated
  descriptor: the flag carried over, and a write returned EAGAIN after 12,288 bytes once the output
  buffer filled. During that window, `eprintln!` (lines 240, 252, 263, 279) panics instead of
  returning an error if the output is paused or slow. This fails closed: no effect happens before
  `decide`, and unwinding restores the flags. Fix: keep the descriptor blocking and wait with
  `poll(2)` using a short timeout to observe stop/expiry. Alternatively, write diagnostics with
  error-returning `writeln!` while the flag is set.
- **L3 (low, usability): the 120-second approval deadline starts too early.**
  `src/coding_endpoint_edit_launch.rs:236`. The deadline starts when `ApprovalInput::new` runs,
  before encrypted state opens and before the full-repository native inspection. A slow inspection
  eats into the operator's window, or uses it all up, before the preview is printed. The guide's
  "within 120 seconds" reads as measured from the prompt. Fix: create the reader, or reset `deadline`,
  right after the preview and prompt are flushed. The native preview expiry still applies.
- **L4 (low, coverage): nested-root and `..` cases are not committed tests.**
  `src/coding_endpoint_edit_launch_tests.rs:237-251` tests only equal roots and a symlink alias.
  The nested-root and `..` refusals I showed above should be committed. They belong in the same backlog as the
  predecessor's L2 (committed service escape cases).

Earlier same-row lows (stale shared-clock wording, committed service escape cases, native held-owner,
kernel refusal reasons, schema and command-resource lows) remain backlog. This change does not affect them.
