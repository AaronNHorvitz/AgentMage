## Findings

### L1 (low; backlog): memory exhaustion during response encoding still crashes the worker as `protocol`

- **Location:** `scripts/coding_eval_oracle_worker.py:84-91` (`encode_message` catches only
  `ValueError`, `TypeError` and `RecursionError`), reached from `response_message` at `:102-107`.
  That call is outside the per-call `try` at `:432-452`.
- **Reproduction:**
  1. Take the dev-015 reference source.
  2. Append a wrapper that returns `'x' * (150 * 1024 * 1024) if v else ''`.
  3. Grade it. The oracle reports `cause: protocol` with `candidate_exit_code: 1`.
  - `candidate.log` ends in `MemoryError … when serializing dict item 'value'`.
  - Cause: `json.dumps` materializes the full value under the 512 MiB address-space limit before
    the 64 KiB check.
  - The legacy grader passes the same bytes (a truthy string).
- **Why low:**
  - The attempt still fails and is counted.
  - It needs a reply about 2,400 times the frame bound.
  - A candidate in control of its own process can always crash it.
  - Only the cause label is affected, as in the original L1.
- **Claim impact:** the guide and evidence say oversized responses no longer crash the worker. That is
  true for ordinary oversize values (70000 bytes and 2,000,000-element lists both reproduce
  `adapter_policy`), but not for values that exhaust memory while being encoded.
- **Fix:** bound encoding incrementally so it stops early, without materializing the value. For
  example, iterate `json.JSONEncoder(allow_nan=False, separators=(",", ":")).iterencode(...)` with a
  running byte total that stops above `MAX_MESSAGE`. Alternatively, also catch `MemoryError` in
  `encode_message`. Add a probe for this case, or state the residual in the guide.

### Note (informational, unreachable)

- **Location:** `scripts/coding_eval_oracle_worker.py:447-448`.
- **Behavior:** `raise ProtocolError("oracle.unknown-result-type")` sits inside `except BaseException`,
  so it is converted to the `candidate_exception` tag, not to a protocol failure.
- **Why unreachable:** `supported_task` restricts `result_type` to the five SUPPORTED types for both
  configs.
- **Fix if desired:** move the type dispatch check before the `try`.
