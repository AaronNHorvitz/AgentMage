## Review of the change

**Native extraction (`coding_context.rs:1014-1031`, call site `:590-593`).** The new
`project_verified_coding_payload` runs the same steps in the same order as the removed inline
code: digest check, strict `from_utf8`, JSON parse only for `application/json`, otherwise
`String`. It produces the same `{schema, media_type, sha256, content}` object. Native output
behavior is unchanged, and final.py confirms the native test module is byte-identical.

**Endpoint projection (`coding_endpoint_context.rs:279-331`).**
- The manual `json!` projections list every field of `ToolCall` (7), `ToolResult` (10) and
  `RuntimeToolRejection` (2). All three contracts are `deny_unknown_fields`, and none of
  `ContractError`, `EvidenceReference`, `ValidationIssue` or `StateChange` carries a
  `ContractPayload`. So no opaque byte array can still reach the model by a nested route.
- The history test builds its expected value from the contracts' own `to_value`, replacing only
  `bytes` with `content`. It is therefore independent of the projection, and would fail if a
  future contract field were silently dropped.
- `Projected<T>` serializes one record at a time into the existing `BoundedContext` writer. No
  second history is built, and nothing is omitted or truncated.

**Error classes (`:349-368`).**
- Writer overflow is a serde_json I/O error and maps to `ResourceExhausted`.
- The projection's `S::Error::custom` is a data error and maps to `Invalid`.
- The system-message encode in `new()` can only fail on I/O for these value types, so its prior
  `ResourceExhausted` behavior is preserved.

**Raw-size preflight (`:176-197`).**
- Every payload in all three positions is compared against `capacity`. This is the content
  budget remaining after the system message, the same bound the writer uses.
- The check runs before any decode, so any oversize payload yields `ResourceExhausted` ahead of
  digest or format failures in any record.
- The decoded temporary `Value` is therefore bounded proportionally to the remaining capacity,
  which is under the kernel's content ceiling.

**Latching.**
- `next_turn.take()` runs before any check (`:153`), so every failure path, including the new
  ones, leaves the context closed.
- The new test proves this: a subsequently valid turn-1 input is refused `Invalid` after each of
  the 15 failure cases. Without the latch it would succeed.

**Test discrimination.**
- The oversize case uses an all-spaces `application/json` payload. Without the preflight it would
  reach the JSON parser and fail `Invalid` rather than `ResourceExhausted`, so the test does
  detect removal of the preflight.
- The digest, JSON-UTF-8, malformed-JSON and text-UTF-8 cases each hit `Invalid` in every
  position. Nothing earlier in `prepare_context` inspects payloads.
- The exact-bound loop checks the exact content and encoded limits, and the one-byte-under cases
  are refused `ResourceExhausted` with real observations.
- The socket test checks the exact turn-2 source string `pub fn fixture() -> u64 { 42 }\n` and
  the absence of `bytes`.
- The overflow test now excludes `ModelRequested`, `PermissionRequested` and
  `PermissionDecided`, which addresses aa1705bf758a L1.

**Untrusted input and confinement.**

## Findings

### L1 (low, backlog): the absent-output assertion cannot detect a missing `output` key

**Where.** `shells/host/src/coding_endpoint_context_tests.rs`, in
`endpoint_context_projects_plain_utf8_and_absent_output_without_changing_contracts`, the
`assert!(projected.is_null())` branch.

**Problem.** `serde_json::Value` indexing returns `Null` for an absent key. A regression that
omitted `"output"` from the projection would still pass, and the history test only covers
`Some` outputs. The current code does emit `"output": null`, at `coding_endpoint_context.rs:318`.

**Fix.** Also assert
`user["untrusted_tool_results"][0].as_object().unwrap().get("output") == Some(&Value::Null)`.

### L2 (low, backlog): the preflight test does not separate "remaining capacity" from "total budget"

**Where.** The `invalid == 4` case of the corrupt-payload test.

**Problem.** The case uses `max_content_bytes + 1` bytes. A regression that compared payloads
against the total `max_content_bytes` instead of the post-system `capacity` would still pass.
Payloads of size `capacity + 1 ..= max_content_bytes` would then reach JSON decoding first.

**Fix.** Add a case whose length is `max_content_bytes - system.len() + 1`. Derive `system.len()`
from a successful build. Assert `ResourceExhausted`.

**Carried, unchanged.** Owner-review lows L1 (caught-panic reuse), L2 (terminal-envelope error
latch) and L3 (faulted-slot capacity), and the earlier lows, remain backlog in these rows. This
commit does not touch them.
