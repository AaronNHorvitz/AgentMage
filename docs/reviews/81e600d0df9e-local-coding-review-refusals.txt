## Findings

No critical, high or medium finding.

- **L1-residual (low, same-row backlog):** creation lineage can still be lost after a *published*
  creation, at `coding_repository_edit.rs:168-173` and `:215-219`, and
  `coding_repository_runtime.rs:392-396` with `:241-243`.
  - **Mechanism.** A manual or runtime edit of a natively created path removes that path's
    `created.edits` entry (the absent-before record with `created_mode`) and takes `applied_write`
    before dispatch. If that edit fails or is not published, neither is restored, and
    `creation_review_incomplete` is never set.
  - **Effect.** A later ordinary edit records the path with `prior = None`, so its `before_sha256`
    is whatever bytes are on disk and its `created_mode` is `None`. Candidate review then projects
    the path, which is absent from the Git base, as an existing-file edit. This is the same
    relabeling as the original L1, reached by a different route.
  - **Reproduction** (scratch tests, output verbatim):
    - Control (published create, then a successful edit): `Ok([("new.py", "000…000")])`. Correct:
      the file is still absent-before.
    - A (published create, then an unpublished runtime edit of `new.py`, then an ordinary edit):
      `marker=false edits=[]`, then `review=Ok([("new.py", "4bf458a9…", "410a6bb8…")])`. The
      preimage is `sha256("runtime unpublished\n")`, not zeros.
    - B (published create; drift between preview and decision makes the manual edit fail with
      `code.write.transaction`; then an ordinary edit): `marker=false edits=[]`, then
      `review=Ok([("new.py", "893105a8…")])`, which is `sha256("drifted\n")`.
  - **Why low.** All candidate bytes are still in the full diff; no write, transfer, Git or
    execution authority is gained; and the candidate plan is inert (candidate execution is OPEN).
    This matches the L1 severity.
  - **Claim wording.** The committed sentence at `docs/guides/coding-original-apply.md:147-148`
    ("prevents an unrecorded creation from appearing as an ordinary existing-file edit") is broader
    than what is implemented. It holds for creations that were never published. It does not hold
    for creations whose record a later failed or unpublished edit drops.
  - **Fix.** Make the marker, or a per-path lineage-lost set, sticky whenever an edit dispatch
    removes an entry with `created_mode.is_some()` (or `before_sha256 == 0…0`) and fails to restore
    it through checked completion. Then add tests A and B as regressions. Alternatively, narrow the
    guide sentence to unpublished creations.
- **Process note (low, backlog), `scripts/local_agent_fast_gate.py`.** The per-step `--timeout
  1800` covers the time spent waiting for a shared reservation.
  - Under host contention the schema step timed out after 1,800 s without running a test, so the
    bundle's single-command reproduction could not complete.
  - The refusal is correct fail-closed behaviour; the measured body is 1.55 s.
  - Fix: start the timeout after the reservation is acquired, or report the wait separately.
