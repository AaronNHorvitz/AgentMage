## Analysis

- **Authorization and consent.** `endpoint-record-save` refuses non-terminal stdin and runs under
  `workflow::bounded` (180 s, signal latch). The exact `save-record <digest>` challenge is read
  from `/dev/tty`. After consent, the stop latch and deadline are rechecked before creation. Saved
  transfer calls `save_observed` before the release `confirm`, so a save that declines or fails
  never reaches release. Tests and probes confirm this. Four separate decisions, in order, are
  asserted on both review services.
- **Filename injection.** The name comes from `request.request_sha256`. `binding()` validates the
  supplied digest with `digest()`, and `checked_selection` requires an exact match, so only hex
  reaches `openat`. A path component cannot be injected.
- **Confinement of the write.**
  - The path must be absolute and equal to its canonical form.
  - It is opened with `O_DIRECTORY|O_NOFOLLOW` and checked for the current user and mode 0700
    exactly.
  - The directory fd is held across consent. Identity (dev, ino, mode, uid) is rechecked through
    the path before the write and again after it.
  - `openat(held, name, O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC, 0600)` never replaces or
    follows a name.
  - After writing, the file is checked for regular type, 0600, the current user, nlink 1 and exact
    length. A `NONBLOCK` reopen of the name compares dev/ino.
  - `fsync` is called on the file and on the directory before the receipt is printed.

  I found no bypass. The decision correctly describes the path rechecks as non-atomic observations.
- **Crash and partial-failure handling.** After creation, errors are reported as uncertain. Nothing
  is cleaned up or retried, which the decision, guide and probe all reflect. The documentation
  discloses that blocking filesystem calls can delay stop.
- **Private content and logging.** The record is written only to the owner-only file and to
  stdout/tty, as before. The receipt prints the destination, size and flags. Neither tokens nor the
  auth directory appear in the record or the receipt. Plaintext storage is disclosed in the
  prompt, decision and guides.
- **Claims and labelling.** The evidence says creation provenance is synthetic, runs are
  cancelled before the model or tools run, and the upstream receives no request. The tests assert
  this: `executions == 0`, and `accept()` returns WouldBlock. No native Git, model, coding score,
  row close or restored authority is claimed. The 243/11/10/5 counts are traced to the raw logs.
  The account of the initial new-assertion failure and the preliminary run is accurate, and
  check.py confirms no existing test line was removed.
- **Public repository hygiene.** No private host path, username, hostname, credential or personal
  data is added. `/lane/...` paths in the retained reports follow the established

## Findings

No critical, high or medium findings.

- **L1 (low): saved transfer accepts an archive directory inside the original or worktree root.**
  Location: `platforms/local-api/src/coding_cli_endpoint_transfer.rs:62-64`, which passes
  `directory` unchecked to `coding_cli_record.rs:172`.
  - Scenario: a user passes the original checkout itself as the private directory. Root
    checkouts are often mode 0700 under a home directory. The plaintext record, which may contain
    task and tool observations, is then created as an untracked file inside the human
    repository. A later `git add -A` could publish it.
  - Mitigation: the user must pass the path explicitly, and the exact prompt displays the full
    destination. That is why this is low, not medium.
  - Fix: in `run`, refuse an `archive` that equals, or `starts_with`, `original` or `worktree`
    (both are already canonical). Add one PTY case.
- **L2 (low, test precision): standalone collision cases do not assert where the refusal
  happens.** Location: `platforms/local-api/tests/support/coding_endpoint_record.rs:147-162`.
  - The regular-file, symlink, hard-link and directory collision cases assert only a nonzero
    status and preserved sentinels. They do not assert `prompts == 1`, so they do not prove the
    refusal comes from the post-consent exclusive create. A regression that refused earlier for
    an unrelated reason would still pass.
  - The saved-transfer test does pin `prompts == 1` for its collision case.
  - Fix: add `assert_eq!(output["prompts"], 1)` to each of the four cases.
