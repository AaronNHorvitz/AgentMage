### L1 (low, backlog): a candidate can choose the `protocol` cause by raising the adapter's own exception class

- Location: `scripts/coding_eval_oracle_worker.py:515-517` re-raises any `ProtocolError`, including one
  raised by candidate code inside `capture`, `verify_case`, a helper or a predicate.
  `docs/guides/coding-evaluation-oracle.md`, "Candidate exceptions and cause limits", still says
  unexpected exceptions during a candidate call produce exactly `{"candidate_exception":true}`.
- Reproduction: reviewer probe 12 (`import __main__; raise __main__.ProtocolError(…)`) on both tasks.
  The worker exits 1 and the report shows cause `protocol` with the failure counted. Before this repair
  the cause was `candidate_exception`.
- Impact: this affects the cause label only. The attempt still fails and is counted. A candidate could
  already obtain `protocol` by corrupting fd 1, and the guide discloses that. It does not affect
  integrity, but the repair widened the re-raise beyond adapter-originated requests.
- Fix:
  - Validate request shape before entering the candidate `try`, for example with a
    `validate_*_request` step outside it. Keep `except BaseException` around only the candidate call.
  - Alternatively, raise a private sentinel subclass that is not reachable from `__main__`.
  - Or document that a candidate-raised adapter exception yields `protocol`.

### L2 (low, backlog): `mock` stub kind does not check for configuration beyond stdout/returncode

- Location: `scripts/coding_eval_oracle_worker.py:433-434` accepts any `MagicMock` `return_value`. A
  fixture that also set `stderr`, `args` or `side_effect` would be sent as a plain mock, and that
  configuration would be silently lost.
- This cannot happen with the two pinned hidden methods: dev-018 sets only stdout and returncode, and
  `SUPPORTED` is closed. The guide's statement that other stub shapes are refused is therefore narrower
  in practice than the code enforces.
- Fix: for `mock`, also require that `fixture.side_effect is None` and that the only configured
  children are `stdout` and `returncode`, otherwise refuse as protocol. Or state the limit in the
  guide before more capture tasks are added.
