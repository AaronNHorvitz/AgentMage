builder's invalid-symlink neighbor, because a load of the control token would succeed here and would show
up on the wire. I ran the built `agentmage-mcp … --share-selected-endpoint` against it.

- The catalog contains exactly `endpoint_request` and `endpoint_events`.
- Every HTTP request on the wire was `GET /v1/code/endpoint/request` with the **client** token. The

  HTTP request. So was `workspace_read {"paths":["/etc/passwd"]}` and `endpoint_request {"run_id":…}`.

  address, port 0, uppercase-hex digest, a 129-byte run id, a run id containing a space, and a

## Review of the change

- **Authorization (`coding_endpoint_api.rs:217-225`).** The delegated set is an exact `(method, path)`
  match. Paths are already restricted by the shared parser: they must start with `/v1/` and cannot
  contain `?`, `#` or `%`. Authentication (401) runs first. The policy is a startup enum parameter. No
  wire field reads it, and `serve_coding_endpoint` still hard-codes `ControlOnly`.
- **Events and release.** The events branch shares an arm with release, but release is selected by
  `ends_with("/release")`, and a client can only reach that arm with the exact path `/events`. `events()`
  only reads. I found no client path to advance, cancel, release, disclosure consent or approval.
- **MCP credential and pinning (`coding_mcp.rs:15-27`, `294-321`).** Endpoint mode validates the pin with
  the shared `binding`, checks `client.token` once at startup, and only ever calls with `control=false`.
  Arguments are validated twice (catalog keys and types, then the exact shape and range `≤ u32::MAX`)
  before any HTTP request. `checked_selection` rechecks the sealed request (`verify_runtime_endpoint_run_request`,
  retention, run id and digest) on every call.
- **Shared validators (`coding_cli_endpoint.rs:131-167`).** `event_page` is a faithful extraction of the
  former terminal branch: the same bounds, the same per-event hash and identity checks, and the same
  labels. The terminal call sites still pass `control=true`.
- **Workspace MCP unchanged.** `serve` passes the original `tools()` and the original instructions
  string. The endpoint tools are not in that catalog, so `validate_arguments` refuses them, and the
  reverse also holds.
- **Claims are labelled honestly.** The evidence record says no executable activates the service, the
  ports and verifier are synthetic, there is no native filesystem, grant, model or score claim, and the
  pages give no whole-stream or recovery proof. The diff touches no evaluation, hidden or held-out test,
  scorer, threshold, dependency, Cargo.lock or supply-chain file. No row or sub-row is added or closed.
- **Hygiene.** The added content has no private host path, username, email, hostname, credential,
  trademark branding or private sibling-project name. `/lane/...` sandbox paths appear only inside the
  byte-identical retained review, as in earlier retained reviews. I found no licence or IP concern.
- **Reachability.** The HTTP delegation is reachable only as a host library choice. The guide says so
  plainly, and the MCP mode is reachable through the actual binary. That matches this increment's
  non-closing claim. Activating the executable service is still a parent prerequisite.

## Findings

No critical, high or medium findings.

- **L1 (low, availability). A delegated observer can make trusted controls report busy.**
  At `platforms/local-api/src/coding_endpoint_api.rs:306-327`, the events branch takes the session lock
  with `try_lock` and keeps the guard while `response` writes to the socket (bounded by `WRITE_TIME`,
  250 ms in `lib.rs:71`). Trusted `advance` (line 260) and `release` use `try_lock` too and answer 409
  `api.busy` on contention. Before this commit, only control holders could take that lock. Now an
  ordinary-client holder that loops event reads, or reads slowly, can repeatedly turn a person's advance
  or release into 409. Cancellation is latched without the lock and still works, and there is no
  confidentiality or authority impact.
  Fix: copy the single page (`events[after..end].to_vec()`, `len`) under the guard, `drop(guard)` before
  `response`, and add a test that alternates a client event read with a control advance.
  Backlog in the same rows.
- **L2 (low, process, outside the repository). The request's Node fallback loop is broken.**
  The loop assigns `node_bin_dir=` (empty) and exports `PATH=":$PATH"`, which would put the current
  directory on PATH if a candidate existed. Use `node_bin_dir=$(dirname "$node_candidate")`. It had no
  effect here because no candidate exists. The predecessor review reported the same problem.
- The carried backlog lows are unchanged: the predecessor's L1 cancelled finalization, its L2 exact
  readable numeric text, and the prior HTTP regression-coverage low.
