**Endpoint binder** (`coding_endpoint_authority.rs:48-87`):

- **Seal and identity.** `verify_runtime_endpoint_run_request` enforces the schema version, a valid

## Findings

No critical, high or medium findings.

- **L1 (low): the binder accepts a zero tool-call budget, which the native path refuses.**
  `shells/host/src/coding_endpoint_authority.rs:55`. `validate_runtime_run_limits` allows
  `limits.max_tool_calls == 0`. For such a request the binder returns `Ok` with an empty action set.
  The native entry refuses that case (`coding_authority.rs:377`), and the returned policy's own
  `CodingRuntimePolicy::binds_run` requires `maximum_tool_calls > 0` (`coding_authority.rs:200`), so
  the binder produces a pair its own policy type will not bind. The result fails closed (no action is
  ever admitted), so this is not an escape. Fix: add `|| request.limits.max_tool_calls == 0` to the
  guard and add a refusal case to the mode/tampering test.
- **L2 (low, backlog for the activation step): endpoint binding applies no repository guidance
  narrowing, and the guide does not say so.** `coding_endpoint_authority.rs:28` and
  `docs/guides/runtime-endpoint-runs.md:587-599`. On the native path, `CodingSessionProfile` supplies
  trusted guidance exclusions, disabled tools, confirmation-required tools and budget caps
  (`coding_guidance.rs:188-233`). The endpoint binder uses only the caller's exclusions and registry.
  This is safe as inert composition with no caller, but the eventual trusted factory could silently
  bind a broader policy than a native run over the same workspace would get. Fix: state in the guide
  and doc comment that no guidance narrowing is applied here. When the factory is wired, derive
  `excluded_scopes` and the registry from the same verified `CodingGuidancePolicy`, and test that a
  guidance-excluded path and a disabled tool are refused.

Earlier lows (endpoint MCP L1, owner-lock occupancy by delegated event readers, and the earlier parent
lows) remain backlog as recorded. The previous L2 (shell Node fallback in the private request) is
resolved: review.py uses a Python `shutil.which` lookup with empty PATH elements removed and no shell
or download.
