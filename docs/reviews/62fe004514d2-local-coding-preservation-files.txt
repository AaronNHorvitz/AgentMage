## Review findings by area

- **Encoding preservation:** worktree records (path, mode, size, mtime, `d`/`f`+hash/`l`+link
  text/`s`), metadata records (path, mode, size, mtime, with directories recorded), reflog records
  (path+hash, directories unrecorded), operations (name, mode, size) and the common-directory
  identity (path, dev, ino) are byte-identical to the removed functions. The fixture test checks this
  against `std` metadata. The sort and concatenation are unchanged.
- **Confinement:** every root and ancestor is opened component by component with
  `O_DIRECTORY|O_NOFOLLOW`, and descendants are opened relative to held descriptors. Files are opened
  with `O_NOFOLLOW|O_NONBLOCK` relative to the held parent and compared on the full snapshot (dev,
  ino, mode, uid, gid, nlink, size, mtime/ctime with nanoseconds) before and after reading. Reads use
  `pread` capped at the observed size and the 64 MiB limit, and the entry is re-checked with `statat`
  without following links. Names that reach `entry()` are single components; multi-component paths
  go through the component-wise walk. Every behavioural change I found refuses in more cases than
  before. Dangling or symlinked `index.lock`, `alternates`, `hooks` and `logs` were previously
  followed or skipped by `Path::exists`; they are now recorded or refused. Linked read-only scopes
  are refused before collection (`repository_safety.rs:358`), so the new strip-prefix requirement in
  `Files::new` cannot break them.
- **Root binding:** `Files::new` runs before the first Git worker, and `revalidate()` runs after
  `seal` and before return. Both check the held checkout and Git identities, current-user ownership,
  absence of group/other write and the scope's path digest. The collector test replaces either root
  at worker 1 or 17 and refuses with all 17 synthetic workers called. A swap followed by a swap back
  between samples is not detected. The documentation states this honestly ("not an atomic snapshot").
- **Cancellation:** checks run before and after each 64 KiB chunk, per directory entry, per pending
  directory and around every public entry point. An individual syscall is not preempted, as
  documented.
- **Resource bounds:** no limit was raised. The counter now counts every listed entry, including
  directories and excluded names, which closes the directory-only reflog loophole. Pending
  directories hold a path and a `Stat`, not descriptors. The 16,384-entry positive case passes with
  the lane's 1,024-descriptor limit.

## Findings

No critical, high or medium findings.

- **Low L-1 (hardening, `platforms/linux/src/repository_preservation_fs.rs:426`):** `read_regular`
  re-opens the entry by name after the `O_PATH` observation. A substituted device node would be opened
  (`O_RDONLY|O_NONBLOCK`, so a driver `open` side effect can occur) before the post-open `fstat`
  rejects it. Planting a device node on the repository filesystem needs mknod privilege, and a hard
  link cannot cross from `/dev`, so this is not reachable by an unprivileged repository author.
  Fix: open the content through the already-verified `O_PATH` descriptor (`/proc/self/fd/<n>` reopen
  or `openat2` with `RESOLVE_NO_SYMLINKS|RESOLVE_BENEATH`) so the inode cannot change between
  observation and open. Add a test that substitutes a non-regular object at that point. Backlog.
- **Low L-2 (documentation precision, `platforms/linux/src/repository_preservation_fs.rs:164`):** the
  worktree counter also counts the skipped top-level `.git` entry. A checkout with exactly 16,384
  non-`.git` entries, accepted before this commit, now refuses. This fails closed, but the docs only
  mention "directory and excluded entries". Fix: count after the `.git` skip, or state it in the
  guide. Backlog.
