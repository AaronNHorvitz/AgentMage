## Findings

No critical, high or medium findings.

- **L-1 (low, backlog): the CLI `edit-prepare` never inserts the identity, contrary to the guide.**
  `platforms/local-api/src/coding_cli.rs:830` validates the raw input against `PrepareEdit` before
  `edit_prepare` runs. `PrepareEdit` now requires `expected_worktree_root_sha256`, so input without
  it fails with a bare error. The insertion at `coding_cli.rs:569` therefore only overwrites an
  equal value on this path; it is effective only through `propose-worktree`. The statement in
  `docs/guides/coding-owned-edits.md:43` ("The terminal inserts the identity shown in its read
  confirmation") is true for `propose-worktree` only. A strict-change JSON retained from before
  this change, as `coding-terminal.md` describes, now refuses. The behaviour fails closed and has
  no security impact. Fix: pre-validate after insertion (parse into a `Value`, insert or compare,
  then `object_json::<PrepareEdit>`), or state in the guide that the input must already carry the
  displayed digest.
- **L-2 (low, backlog): migration hides existing strict-parsing negatives.**
  `platforms/local-api/tests/coding_worktree.rs:935-940` keeps four raw malformed bodies (string
  `approve_read`, a duplicate key, array-form `expected_sources`, a non-object body) that lack the
  new required field. Three of them now get 400 for the missing field rather than their intended
  defect. As a result, the `expected_sources` object-shape guard
  (`platforms/local-api/src/coding_repository_api.rs:85-90`) is no longer exercised by any test on
  this route. The guard code is unchanged. Fix: add `"expected_worktree_root_sha256"` with the
  displayed (or any 64-hex) value to those byte strings.
- **L-3 (low, backlog): correlation applies only at the repository selector, not at
  `prepare_edit`.** `LinuxCodingReadScope::select` is public
  (`platforms/linux/src/coding_workspace.rs:101`). `prepare_edit` accepts any scope whose
  path/device/inode digest equals the held root (`coding_repository_edit.rs:77-82, 95`).
  `select_created_sources` relies on exactly this equality, which proves it. So a crate-external
  trusted Rust caller that knows the worktree path can still prepare an inert held-worktree edit
  preview without presenting the displayed root. HTTP and CLI cannot reach this, and writes still
  need exact approval. The guide's "the uncorrelated selector is internal" is true of the method
  but not of the capability. Fix: have `prepare_edit` accept only a scope type minted by
  `consented_created_sources` (a private newtype), or document this limit.
- **L-4 (low, backlog): one evidence sentence is not asserted.** The evidence says a retained scope
  "can still read a displaced original directory". The test guards that read with
  `if let Ok(sources) = scope.read(&paths)` (`platforms/linux/src/coding_repository_tests.rs:748`),
  so it only proves "never the replacement". Fix: assert the outcome, or soften the sentence to
  "may".
- Earlier same-row lows remain backlog as stated: commit-control native forwarding,
  conservative pre-dispatch uncertainty and slow postflight recovery. The 0c859b28 L-1 and the
  9008ee38 L1 are addressed by this batch for the HTTP/CLI and native selector surfaces, subject
  to L-3.
