## Assessment

- **Refactor equivalence:** The order of operations, failure codes and outcome classes are the same as before. A
  branch, storage, readback, compare-and-swap or postflight failure is reported as uncertain. A signer error goes
  through `failed_signer_result`, and `CleanupUncertain` maps to `signer_cleanup_uncertain`. The success
  projection is field-for-field identical. Swapping `Err(_)` for `.map_err(|_| ())` and `Err(())` loses no
  information, because the original code discarded the error too. There is no fallback and no direct signed
  creation. I found no change to trust rules, permits or result mapping.
- **Confinement boundary:** It is not weakened. No caller-supplied backend, bytes or session can reach
  `run_with` outside the private module. The kernel permit, preflight equality, signer revalidation, exact pin and
  closed I/O owner all still come before the native session is constructed.
- **Test strength:** The four tests cover what the evidence claims.
  - Both widths (40 and 64) are covered, and the full call order is checked with `assert_eq!` on the
    `calls` vector.
  - The test asserts that the exact `VerifiedCommit` bytes and object reach `write`, that the object reaches
    `read`, and that the readback bytes reach `verify`.
  - The postflight manifest is deliberately distinct from preflight, so forwarding is actually tested.
  - A failure at each of the 7 stages stops with no further calls.
  - Corrupt readback (empty, truncated, changed tree, changed message) stops before `verify` and `update`.
  - All 6 `LinuxLocalCommitErrorKind` variants are injected at sign and at re-verification. Neither reaches
    `update`, and an object is stored only in the verify case.
  - A postflight failure after the synthetic CAS stays Failed, with cleanup unverified and last-observed
    manifests.
  - Reading the assertions, the obvious mutations of `run_with` would each be caught: reordering
    verify/update, dropping `verify_raw_commit`, forwarding `before` instead of `after`, or retrying.
- **Honest labelling:** The code comments, evidence, guide and TASKS say that synthetic outcomes prove control
  flow only, not native execution, cryptography, approval or reviewer provenance. I found that accurate. Nothing
  claims parent closure or readiness.
