## Own escape reproductions (bubblewrap with the product's mount shape)

- **Descriptor leak:**
  - Setup: checkout `--ro-bind-fd`, metadata and owned root `--bind-fd`, with the directory fds passed in.
  - In the guest, `/proc/self/fd` lists only 0, 1, 2 and the listing fd. bwrap closes the bind-fd
    sources before exec, so `openat` on a leaked host-writable directory fd cannot bypass the
    read-only checkout.
  - Direct write to the checkout: EROFS. Write to the metadata: allowed, as designed.
- **Writable-metadata pivots:**
  - Rename of metadata to checkout, hardlink of checkout to metadata, and rename of checkout to
    metadata all fail with EXDEV.
  - A relative symlink in the metadata pointing at a checkout file fails with EROFS on write.
  - An absolute symlink in the metadata to a host file outside the projections resolves inside the
    guest's own root tmpfs. The host file is unchanged. A mkdir at a host-ancestor path likewise lands
    only in the guest tmpfs, and the host is unchanged.
- **Environment:**
  - The guest runs with `--clearenv` plus only the fixed kernel `hardened_environment()`, which
    `verify()` re-checks (no PATH, `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL=/dev/null`,
    `HOME=/nonexistent`).
  - systemd-run gets only `XDG_RUNTIME_DIR`/`DBUS_SESSION_BUS_ADDRESS` (asserted by the inert test).
  - `--expand-environment=no` disables `$` expansion of the host paths that now enter the ExecStart argv.
- **Network:** `--unshare-all` (network namespace), `RestrictAddressFamilies=AF_UNIX AF_NETLINK`,
  network invocations refused in both `run` and `execute_with`, `protocol.allow=never` in the sealed prefix.
- **Prompt-injection reachability:** this path only executes kernel-sealed, approved plan invocations.
  - `invocation.verify()` re-checks the hash, environment and prohibited operations.

## Assessment

- **Authority:** strictly reduced relative to the PASS base. The base spawned Git directly on the
  host with the user's full filesystem authority. Now:
  - The checkout is read-only.
  - Only the held selected metadata (which must lie strictly inside the checkout) and the owned root
    are writable, and no host ancestor is mounted.
  - Linked read-only scopes, `git_directory == checkout_root`, nested or overlapping owned roots,
    non-normal path components and control characters are refused, as are reserved runtime prefixes
    and their ancestors (including `/`).
- **Fail-closed outcomes:**
  - All three held identities (dev, inode, uid, mode, directory type and canonical spelling) are
    rechecked at capture, before projection, before launch, at admission (`accepts`), immediately
    before seccomp release and after supervision.
  - A post-run mismatch returns `CleanupFailed` regardless of the worker result.
  - Incomplete output returns `CleanupFailed`. Oversize returns `OutputLimit`.
  - Cancellation observed after a successful exit returns `Cancelled`.
  - In-loop revalidation errors flow through the existing `Attempt::cleanup`.
  - The caller still re-collects the preservation manifest after any non-success and reports
    `Uncertain` on change. Kernel reconciliation is untouched.
- **No fallback:** the direct-spawn helpers (`wait_bounded`, `terminate_child`, `read_bounded`) are
  deleted. The non-test `report_invocation_spawned` stub is gone, and the remaining seam is `#[cfg(test)]` only.
- **Evaluation integrity:** no frozen, hidden or held-out task, scorer, prompt, threshold or
  scoreboard file is touched (the nine changed files are listed above). `check.py` confirms the

    README describe the concurrency regression in the present tense ("observes the admitted worker
    … stops that worker, mutates … resumes it"). The seam is platforms/linux/src/sandbox_supervision.rs:752-758.
  - Problem: in this lane, `concurrent_user_changes_survive_worktree_removal_and_cleanup` panics at
    `LinuxGitArtifact::verify("/usr/bin/git")` (platforms/linux/src/repository_safety.rs:2085,

    head, so the new seam has never executed. The evidence does say that none of the new methods
    establish native execution, but it never states that this moved regression is itself unexercised.
  - Fix: add one sentence to the evidence file saying the moved concurrency regression remains among
    the inherited failures at executable-ownership admission, and that its new seam is unexercised
    until native admission works.
- **L2 (low, undocumented invocation change)**
  - Location: platforms/linux/src/repository_execution.rs:327-330.
  - Problem: every approved local invocation now gets `--work-tree=<checkout_root>` outside the
    kernel-sealed argument list. The base ran with the owned root as cwd and no work tree option.
    Decision 0189 documents only `--no-replace-objects`.
  - Not a confinement risk: the checkout is mounted read-only, and an explicit option overrides any
    `core.worktree` in the user's config. But it changes what Git treats as the main work tree for
    add, remove and CAS, and the inert-plan test does not assert it.
  - Fix: document the option and its reason in Decision 0189 or the guide, and assert it in
    `worktree_effect_worker_projects_only_exact_metadata_and_owned_roots_writable`.
- **Residual, disclosed and not a finding:**
  - The positive supervised path is not exercised in this lane. That covers systemd OpenFile directory
    projection, the existing seccomp policy permitting the syscalls `worktree add` needs, and the guest
    `/usr/bin/git` helper symlink under the real launcher. Native executable-ownership admission and the
    user bus are unavailable here, and the evidence states this.
  - `/tmp` is not in the reserved-prefix list. This is benign because `--tmpfs /tmp` is ordered
    before the projection binds.
