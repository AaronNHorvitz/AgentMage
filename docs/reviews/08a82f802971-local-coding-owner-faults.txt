## Review notes

**Owner (L1).** `advance` (`shells/host/src/coding_endpoint_owner.rs:193-214`):

- It refuses `Faulted` before touching the coordinator.
- It sets `faulted = true` before `run_endpoint_until_boundary`.
- On normal return it sets `faulted = result.is_err() && coordinator.requires_reconciliation()`.

This means a caught unwind from any dependency (model transport, tool boundary, verifier, clock)
leaves the entry closed. No other method reaches the coordinator mutably. `events` only borrows,
and `release` drops the coordinator.

`release` (`:231-247`) allows a faulted entry, even without a terminal outcome. The identity stays
spent, the capacity slot is freed and admission of the same identity is refused, as the extended
old test shows. Production code adds no `catch_unwind`, synthetic terminal, replacement coordinator
or budget renewal; the only `catch_unwind` is in the test.

Faulting on a panic before any effect (the clock panic inside approval validation) is deliberately
conservative and documented. It loses the challenge but cannot reopen a run.

**Kernel (L2).** In `coordinator_endpoint.rs:280-288`, a missing or mismatched endpoint envelope
after a shared `Complete` now sets the original `correctness_reconciliation_required` latch.
`run_until_boundary_impl` (`runtime_loop.rs:2122`) then refuses every later call before any
dependency, so restoring the metadata cannot reopen the run. That is what the test shows: events
unchanged, one model call, zero tool executions.

The only other unlatched post-dispatch arm in that function is `Suspended`, which returns
`UnsupportedMode`. It is unreachable for endpoint runs: the function always passes
`suspension = None`, and the suspension branch (`runtime_loop.rs:2231`) requires a probe. This is
not a finding.

**L3.** The extended old fault test fills the three other slots while keeping the faulted entry,
then checks in order:

1. A fifth admission is refused with `Capacity`.
2. The events are unchanged.
3. Release frees the slot and the fifth run is admitted.
4. The original identity remains `AlreadyAdmitted` and `NotHeld`.
5. The executions count is still 1.
6. There is no extra socket connection.

No original assertion is removed; the diff is additions only.

**Confinement and authority.** The tool boundary, permission challenge, transport approval and
workspace scope are unchanged. No change touches network enablement, the sandbox or paths. The
fault latch only removes the ability to advance.

**Claims and labelling.** The evidence and guide describe synthetic socket fixtures,
