## Assessment against the request's claims

- **Ownership.** `into_endpoint_edit(self, …)` consumes the live `LinuxCodingRepository` and needs
  `verify_created()` plus a pending native edit. Nothing in it builds authority from a path or a
  receipt. On refusal it returns `(Self, error)` with `latest` unset and no write; the 23-case test
  and my probes confirm this.
- **Binding.** The constructor checks:
  - the request verifies, its mode is ControlledWrite and it has no event cursor;
  - the workspace equals the held worktree identity;
  - `visible_tools` equals the one-tool registry's references;
  - the creation receipt matches;
  - the call's tool id, version, schema, media type, exact bytes and sha256 equal those of
    `{"preview": <original preview>}`, and its action id is inside the run's tool-call range;
  - every `WriteApprovalPreview.files` entry (all operation paths) is exactly mutable and not under
    a protected path;
  - every declaration passes `WorkspacePath::new`, which rejects `..`, `.`, empty components,
    leading `/`, bare `*`/`**` and non-canonical Unicode.
- **Challenge.** It is sealed with `seal_runtime_approval_challenge`. Its presentation arguments are
  the complete preview, and `preview_sha256` is the native digest. `approval-{change_set_id}` and
  `write-{change_set_id}` match `LinuxCodingPendingWrite::execute`
  (`coding_workspace_write.rs:339,349`), and the multi-file test asserts that every receipt carries
  `proposed_grant_id`. No grant exists before `decide_edit`.
- **Decision ordering.** A Narrow response, or any response that fails
  `verify_runtime_approval_response`, returns before `spent = true`; the eight-probe test confirms
  that a later correct response still commits. A matching response sets `spent` before the first
  `control.remaining_ms()`, so a panic, stop or stale result cannot reopen the handle (unwind and
  stop-after-inspection tests, plus my deny-while-stopped probe). Only `decide_edit` takes the edit,
  issues and consumes the grant, writes atomically and reconciles. That code is unchanged; its
  epoch and monotonic (`Instant` deadline) expiry, preimage, symlink and hardlink checks and lineage
  invalidation still apply.
- **`into_repository`** drops `edit` and keeps `edit_result` and `created.edits`. The test confirms
  that the old digest cannot be decided afterwards.
- **Honest labelling.** The new test module and the docs label creation provenance as SYNTHETIC,
  while the descriptors, native grants and atomic writes are real. None of them claims native Git
  creation, model coding, test execution, completion, scores or release readiness, and nothing
  claims a `RuntimeToolBoundary` implementation or service activation.
- **Delivery and evaluation integrity.** No row or sub-row is added or closed; the audit asserts
  that the TASKS ledger rows are unchanged and I confirmed it in the diff. No hidden, held-out,
  task, scorer, threshold, dependency, Cargo.lock or SBOM path is touched.
- **Privacy and IP.** The added lines contain no private host path, username, hostname, credential,
  personal data, sibling-project name or third-party branding. The copied predecessor report
  contains `/lane/…` sandbox paths, as about 130 existing reports at bc98651 already do. The
  predecessor report is byte-identical (`cmp`) to `/lane/reviews/bc98651997e9-local-coding-endpoint-write.md`.
- **Gate.** The failed ordinary gate is reported as FAIL everywhere. The data audit is not presented
  as a green gate.

## Findings

No critical, high or medium findings.

- **L1 (low, test coverage)**, `platforms/linux/src/coding_repository_endpoint_edit_tests.rs:509-531`
  together with `coding_repository_endpoint_edit.rs:148-153`.
  - No committed test reaches the handoff's protected-path refusal with a request that seals.
  - The exact-equality branch is unreachable for sealed requests, because the packet validator
    refuses exact overlap.
  - Case 3 is refused by the request-digest check, since the request is unsealable. Cases 18–21
    are refused by `WorkspacePath::new`.
  - The only reachable branch, an edited file inside a protected directory, is therefore never
    exercised, and deleting the protected clause would not fail any committed test.
  - My probe shows that the rule works today, so this is not a bypass. Mutable-file membership and
    exact human approval remain in force.
  - Fix: add a case with mutable `sub/x.py` and protected `sub` that seals and is refused, and keep
    the `su` prefix control. Same-row backlog.
- **L2 (low, scope semantics and wording)**, `coding_repository_endpoint_edit.rs:118-131`.
  - The comment says declarations are "never patterns", but only bare `*`/`**` components are
    rejected. `*.py` or `src/*.rs` seal and are treated literally: protected `*.py` does not protect
    `one.py`, as my probe shows.
  - No consumer in the repository reads these fields as globs, and the contract calls them
    candidate file declarations, so nothing can be bypassed today.
  - Fix: refuse any mutable or protected entry containing glob metacharacters (`*?[]{}`), or reword
    the comment and the guide to say "literal paths". Backlog.
- **L3 (low, state display)**, `coding_repository_endpoint_edit.rs:259-270`.
  - When the control is stopped after a matching response, `decide` returns before `decide_edit`.
  - `inspect()` therefore still shows the native `pending` preview, and `latest` is unchanged, even
    though the handle is spent and cannot act on it.
  - A UI that renders `inspect()` could offer a decision that can no longer be taken.
  - Fix: record a terminal `{"outcome":"stopped","effect":"none"}` in the result or the inspect
    projection once the handle is spent. Backlog.
- The predecessor's L1 and L2 remain same-row backlog as stated.
