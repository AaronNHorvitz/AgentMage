## Source analysis

- `local_chat.rs:222-264` `PrivateRequestWriter`: `Vec::with_capacity(MAX_REQUEST_BYTES)` followed by
  `extend_from_slice` only when `len + chunk <= MAX` can never reallocate. The refusal condition
  `chunk > MAX.saturating_sub(len)` accepts exactly the totals the old post-hoc `len > MAX` check
  accepted, so the wire contract is unchanged: exactly 256 KiB passes, one byte more fails (now
  tested with and without `stream_options`). A refused write appends nothing (atomic). serde_json
  calls `write_all`, and `write` always reports a full write or an error, so no short-write path
  exists. On error the `Zeroizing` owner drops and erases the whole capacity; on success
  `mem::take` moves the same allocation out and leaves an empty `Vec` behind.
