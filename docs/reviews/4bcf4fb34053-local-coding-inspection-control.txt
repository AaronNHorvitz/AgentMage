## Review of the requested points

- **Token propagation.** `inspect` builds an internal root token and delegates to `inspect_cancellable`.
  `inspect_cancellable` passes the caller's `&CancellationToken` through `inspection::inspect` to
  `capture_until` and to `inspect_with`. Both workers receive it as
  `SandboxCancellation::Observed(cancellation)`, and `validate_result` rechecks it after each worker.
  `run_owned` refuses to launch when the token is already cancelled or the deadline has passed
  (sandbox_supervision.rs:1059-1061). The constructor no longer creates its own token. Both workers
  share one thirty-second deadline, created once.
- **Checkpoints.**
  - `check_control` runs before either path is consulted (local_commit.rs:329). The new test proves this
    with an `AsRef<Path>` that panics if called.
  - Checks also run at entry to `verify_root_executable_checked`, before every 64-KiB executable read
    and after hashing (local_commit.rs:890, 916, 932).
  - In the capture, checks run at entry, before every bounded `pread` (now capped at 64 KiB per call),
    before sealing and after sealing (local_commit_inspection.rs:74, 119, 143, 146).
  - Further checks run after the evidence digest (inspection.rs:258) and after `PinnedCommitSigner::seal`,
    before `Ok` (local_commit.rs:367).
  - Every failure maps to `ArtifactDenied` and returns no signer.
- **Bounded reads.** A short read loops, a zero-length read is refused, and the size and metadata
  comparison after the read is unchanged. The test uses 2×64 KiB + 1 bytes, so it observes exactly
  6 checkpoints and compares all bytes and the digest.
- **Sealed descriptor cleanup.** When a check after sealing fails, the local `OwnedFd` is dropped and
  closed before `Self` is built. Duplicated worker payloads are moved into `dispatch`/`Launch` and dropped
  on every error path. No raw descriptor escapes. This rests on ownership semantics; no test counts
  descriptors (see L1).
- **Creation and expiry checks.**
  - Fields 6 and 7 (0-indexed [5] and [6]) must be ASCII digits only, which rejects `+1`, `-1` and
    non-numeric text.
  - Creation must parse as u64: an empty value and a value past 2^64 are refused.
  - A key is usable only if `created <= now`, the expiry is 0 or later than now, and the expiry is
    0 or later than the creation time.
  - `primary_usable` is reset on every `pub`, so a subkey cannot qualify under a future-dated, expired
    or malformed primary.
  - A malformed date on any record, not only the selected one, refuses the whole listing. This fails
    closed.
  - The test checks every case on the primary, on a subkey and on the primary of a selected subkey.
    Positive controls cover creation exactly at `now` and epoch-zero keys. The `listing` helper's
    `:1:` pattern is replaced for real: the `("101","")` negative case and the positive controls
    would fail if it were not.
- **Confinement.** The private-key and agent boundary is unchanged:
  - there is no new projection, socket or filter change, and no direct-inspection fallback in production;
  - the public-only claim is still not presented as signing availability;
  - the signing-pipe probe stays in the private bundle and is not product code.
- **Honest claims.** The evidence, guide and TASKS text say the gate is FAIL, that no row or sub-row is
  added and that neither parent closes. They state that individual filesystem, hash and seal calls are
  not interruptible. My run confirms the numbers they give.
- **Public content.** The diff and commit message contain no username, home path, hostname, credential

## Findings

No critical, high or medium findings.

- **L1 (low, test coverage) — local_commit.rs:916, 932, 367; local_commit_inspection.rs:258.** Several
  checkpoints are correct by inspection but no test exercises them:
  - the per-chunk and post-hash checks in `verify_root_executable_checked`;
  - the final `check_control` before `inspect_cancellable` returns a pin;
  - the check after the evidence digest in `inspect_with`.

  A cancellation raised during Export is already caught by `validate_result`, so the worker-order test
  cannot tell whether the later check exists. If any of these lines were deleted, all current tests
  would still pass.

  Fix: add a counting-closure test of `verify_root_executable_checked` against a root-owned file larger
  than 64 KiB, in the style of the capture test. Add a test seam that cancels after a successful
  `inspect_with` and before the pin is returned.
- **L2 (low, latency note) — local_commit_inspection.rs:175-178.** For each worker,
  `VerifierManifest::verify_executable` re-hashes systemd-run, systemctl, bwrap and gpg with no
  checkpoint during the hashing. This is bounded, and `run_owned` refuses before launch on cancellation
  or deadline, so no worker runs after cancellation. Cancellation latency still includes up to four
  full executable hashes.

  This matches the stated limitation that hashing is synchronous. Optionally thread the control check
  into `LinuxGitArtifact::verify` for this path.
