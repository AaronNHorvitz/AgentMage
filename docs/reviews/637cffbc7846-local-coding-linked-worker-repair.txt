## Disposition of prior findings

### H1 (high): resolved

- **Admission.** `LaunchOwner` gains a closed `LinkedGit(manifest, LinuxLinkedRepository)`
  variant (`sandbox_supervision.rs:29-32`). It admits only `agentmage-git-inspection-` units with
  exactly 2 projections, and only after `linked.revalidate()` succeeds (`:62-65`).
- **Ordinary Git and other owners.** Ordinary `Git` stays at exactly 1 (`:61`). Every
  `LaunchOwner` match is exhaustive, and no other owner changed.
- **Reachability.** Only `for_linked_worktree` sets `self.linked`, so only linked executors reach
  `LinkedGit` (`repository_safety.rs:942-948`).
- **Output limits.** `linked_inventory_limit` caps each linked query at
  `min(requested, sandbox::MAX_OUTPUT_BYTES)` = 4 MiB (`repository_safety.rs:1052-1054`, `:657`).
  `MAX_OBSERVATION_BYTES` is now defined as that same constant, with its value unchanged.
  `run_read_only` now prechecks against it (`:819`), so it can no longer accept a limit that
  `run_owned` refuses. Ordinary inventory keeps 32 MiB on its host-side path.
- **Overflow refuses.** `OutputLimitExceeded` maps to `OutputLimit` termination, or an incomplete
  stream maps to `ExecutionFailed`. Either way `observe_linked_inventory` returns
  `ObservationFailed` (`:661-664`), so no truncated map is published.
- **Regression.** `linked_supervisor_admits_exact_owner_projections_and_all_inventory_limits`
  calls the real `run_owned` with real projection descriptors from a verified binding. It passes
  in the complete gate and the focused run. It covers:
  - precancellation after admission for 1 KiB, the 32 MiB request (capped) and 4 MiB;
  - refusal of counts 0/1/3;
  - refusal of limit 0, of 4 MiB+1 and of the uncapped 32 MiB;
  - refusal of a command-prefixed unit;
  - refusal of ordinary `Git` with 2 projections, and acceptance of ordinary `Git` with 1;
  - refusal of a stale binding (rewritten `commondir`).

  Its inert artifacts are `#[cfg(test)]` only, and the command path is
  `/nonexistent/must-never-launch`. It starts no process.

### H2 (high): resolved at component level

- **New layout.** The worker now mounts only the held common descriptor at `/metadata/common`
  (fd 6 = the `git-common` `OpenFile`; `repository_safety.rs:880-885`, `:1056-1066`). It selects
  `--git-dir=/metadata/common/worktrees/<name>` (`:1068-1082`). `GIT_COMMON_DIR` is gone.
- **Name source.** `<name>` is the final component of the held per-worktree path. `verify()`
  requires that path to be exactly `<common>/worktrees/<name>` with `commondir` = `../..\n`
  (`linked_repository.rs:62-79`), so the `expect` cannot fire and no model input reaches it.
- **Revalidation.** The per-worktree descriptor is still held, and revalidation runs before
  projection, at admission, and after the run.
- **Probe results.** P1 shows guest Git 2.56.0 resolving shared HEAD, refs, the tree and all
  inventory classes under this exact layout. P2 shows the extra items the shared root contains
  (config includes, alternates, symlinks) staying inside the namespace.
- **What remains unverified.** A complete native-worker positive is not established in this
  lane. The new ignored native test exists and compiles, but stops at the T-301.1 trust refusal
  (command 3). This is disclosed and stays open.

### L2 (low, backlog): `LinkedGit` admission checks count and binding freshness, not projection identity

- `sandbox_supervision.rs:62-65` accepts any two descriptors once `linked.revalidate()` succeeds.
  It does not check that `projections[0]` is the held root (`matches_root`) or that
  `projections[1]` is the held common inode.
- Today the only caller, `linked_inspection_projections`, enforces both
  (`repository_safety.rs:1086-1097`), so this is not reachable. But the owner-bound admission is
  meant to be the last closed check before launch.
- Fix: in `accepts` (or in `run_owned` for `LinkedGit`), compare the dev/ino of the two
  projections with the binding's held root and common descriptors. Add the wrong-descriptor case
  to the admission regression.
