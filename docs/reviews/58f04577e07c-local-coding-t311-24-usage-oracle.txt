    - bytes only as lowercase even-length hex (linear regex);
    - integer frozensets only as sorted, unique, non-bool ints;
    - only exact list/tuple/dict-with-str-key types.

    capped at 128.
  - `RemoteFunction` and the proxy both validate the complete reply before `reset_mock()` and
    replay (worker lines 836–844). The new worker tests show the mock is untouched on invalid
    replies.
- **Replay target.**
  - Replay happens only into `module.unix_http_request`, and only when it is a `MagicMock`.
  - A non-mock transport sets the sticky protocol failure.
  - Candidate-chosen kwarg names, such as `self` or `""`, are replayed without crashing the
    trusted side (my probe `ctor-call`).
- **Candidate side.** Exceptions become the fixed `candidate_exception` tag; unsupported values
  and oversize frames become `adapter_policy`. Malformed trusted requests and duplicate or missing
  instance IDs are refused.
- **Equivalence to in-process semantics for the two frozen methods.**
  - Each test creates exactly one adapter under its own `@patch`.
  - Fixture changes are sent when the identity changes and are otherwise "unchanged".
  - Constructor-time MagicMock defaults map to the candidate's own default.

## Findings

No critical, high or medium finding.

### L1 (low, disclosed; carry before generated admission): identity-keyed caching false fail

- **Location:** `scripts/coding_eval_oracle_worker.py:836-838` (args rebuilt per request) and
  `:852-890` (`usage_result`). The disclosure is in `docs/guides/coding-evaluation-oracle.md:46`
  and coverage `object-identity-and-equality-subclasses`.
- **Reproduction:** probe `id-cache` above. The legacy grader passes; the oracle fails the first
  method with two transport calls.
- **Reasoning:** the task statement requires the existing canonical-content cache, so a correct
  solution is not affected. The disclosure is accurate. However, this is an active mis-grade,
  not an "ungraded" item.
- **Fix before generated admission:** pass a per-instance argument handle so that repeated
  trusted objects (`is` the same list) map to the same candidate-side object. Alternatively,
  record the case as a policy-category outcome rather than a test failure.

### L2 (low, latent; not reachable by the two selected methods): cross-instance history loss

- **Location:** `scripts/coding_eval_oracle_worker.py:842-844`.
- **Problem:** each proxy instance resets the shared trusted mock and replays only its own
  instance history. If one test created two adapters under one patch, the second instance's
  response would erase the first instance's recorded calls. Depending on the assertion, that
  could produce a false pass or a false fail.
- **Disclosure:** the guide discloses cross-instance post-response *mutations*, but not this
  call-history loss.
- **Fix:** keep the replay list keyed by mock and replay the union in call order. Or refuse with
  sticky `adapter_policy` when a second live instance shares a mock that already holds another
  instance's history. Add this to the disclosed limits before any new method is selected.

### L3 (low, latent): replay executes the mock's side effect or wrapped target

- **Location:** `scripts/coding_eval_oracle_worker.py:821` and `:844`.
- **Problem:** the guard accepts any `MagicMock`. A trusted mock configured with `side_effect=`
  or `wraps=` would be invoked on every cumulative replay with candidate-supplied arguments,
  repeatedly. Neither frozen method does this.
- **Fix:** refuse (sticky protocol/policy) when `transport.side_effect is not None` or the mock
  wraps a target, and test that refusal.

contrast and generated-policy accounting), PurePath/subclass, resource, collector and model-lab.
