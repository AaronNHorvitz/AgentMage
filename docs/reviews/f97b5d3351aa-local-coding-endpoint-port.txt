## Review

Model port and request binding. `execute` latches single use, checks control, then compares the port's
complete `EndpointModelRequest` (derived `PartialEq` over version, identity kind, selection, context, body
fingerprint, limits and verified tokens). Only after that does it consume InputBytes/ModelCalls
(`endpoint.rs:108-125`). A mismatch spends the phase with zero admitted calls; the committed test and
harness case 5 confirm this. The production adapter (`lib.rs:1054-1076`) moves the original
`PreparedEndpointChat`, whose private, immutable `binding` is computed in `prepare_chat` from the exact
encoded body (`local_chat_transport.rs:401-465`). The phase is framed from that same binding
(`lib.rs:1108`), so the comparison is sound for the real route. The adapter has no Debug/Clone. It reads
no credential, rebuilds no body and only borrows `op.cancel`. All three routes (live snapshot, workspace,
repair) reach the single `dispatch_coding_proposal` call site. In the unchanged repair route,
`prepare_repair` still runs before `consume_repair_feedback` (`coding_repair_api.rs:65-75`).

Stream binding. The kernel hashes and counts each fragment at the consumer boundary. It checks the
cumulative byte ceiling before delivery and polls control before and after each callback. Any refusal
latches and suppresses later callbacks (`endpoint.rs:129-158`). Once dispatch finishes, it requires the
descriptor's byte count and lowercase SHA-256 to equal its own (`endpoint.rs:168-177`). Result accounting
is still committed atomically on a ledger clone, only on success. It stores no plaintext buffer. The real
transport polls cancel/control before and after each text event (`local_chat_transport.rs:575-582`), so it
meets the trait's cooperative obligations. The transport codec enforces the same `MAX_TEXT_BYTES` that the
binding carries, so the kernel's overflow latch is defense-in-depth on the production path. A
dependency error takes precedence over a latched stream refusal; this is documented in the guide and was
confirmed by harness case 2. Every refused outcome maps to an error terminal event in the API and never
reaches `check_coding_proposal`, so provisional text never becomes a proposal.

Earlier tests. The six descriptor methods now go through `ClosurePort`, which emits
`"x" * response_text_bytes` after the closure returns. Their hashes were updated to match that synthetic
text. Every previous negative case still asserts the same refusal variant. Case 5 (101 bytes) is now
refused by the stream latch instead of the OutputBytes ledger. The ledger's ceiling equals the same
`response_text_limit_bytes`, so no boundary was weakened. The stronger check simply comes earlier.

## Findings

No critical, high or medium finding.

- **L1 (low, test coverage)**: `kernel/engine/src/runtime_loop/endpoint/tests.rs:525-560`
  (`endpoint_port_caps_text_before_delivery_and_latches_overflow_across_later_fragments`). The fragments
  after the overflow are `""` (invisible in the pushed `String`) and a 22-byte string that would overflow
  by itself. So a non-latching implementation that rechecks each fragment would pass this test too. The
  latch is the same `stream_failure.is_some()` guard that the control-stop test does prove, and my harness
  case 1 shows the overflow latch suppressing a fragment that would otherwise fit. Fix: after the
  overflowing fragment, emit a fragment that fits the remaining budget (for example
  `"x".repeat(98)` + `"é"` (refused) + `"x"`), and record deliveries as a `Vec<String>` so empty fragments
  are visible.
- **L2 (low, diagnostics)**: `kernel/engine/src/runtime_loop/endpoint.rs:116-118`. A prepared-request
  mismatch before dispatch returns `InvalidResult`, which the API reports as `runtime.model.result_invalid`
  (`platforms/local-api/src/lib.rs:1199`), although no result exists. This cannot happen on the
  production route (the port and the phase share one binding), so it has no security effect. Fix: add a
  distinct pre-dispatch variant (for example `RequestMismatch`) or document that `InvalidResult` covers
  request binding.

API-level pre-dispatch zero-attempt coverage) and the earlier retained lows.
