## Findings

No critical, high or medium findings.

- LOW (coverage, ownership-blocked): the production paths are refactored but have no native run.
  - Affected: `collect_inventory_until` (repository_inventory.rs:103),
    `collect_base_preimages_until` (repository_base.rs:51) and `verify_candidate_tree`
    (coding_repository_commit_review.rs:231).
  - Why: the native inventory tests
    (`repository_inventory_preserves_exact_git_states_and_nonregular_hints`,
    `repository_inventory_cancellation_fails_before_git_launch`) fail at Git artifact admission,
    before reaching the refactored code. The seam tests exercise the logic with synthetic workers,
    and I verified by reading that the production wrappers are single-line forwards with arguments
    identical to the parent.
  - Fix: run those native tests once executable ownership is mapped. This joins the carried
    native forwarding-coverage low.
- LOW (test robustness, disclosed): the new tests use real-time budgets.
  - Where: repository_inventory_deadline_tests.rs:32 and repository_base_tests.rs:456 (100 ms),
    and coding_repository_commit_review_tests.rs:1562 (250 ms).
  - Effect: the non-expiring success cases (`stop == None`) also run under the 100 ms deadline. A
    scheduler stall of more than 100 ms anywhere in the success path is a false failure. It can
    never be a false pass.
  - Fix: give the `None` cases a multi-second deadline, keep short deadlines only where expiry is
    intended, or add a test-only clock seam.
- LOW (test precision): the final post-parse `check()` in `collect_inventory_with`
  (repository_inventory.rs:217) has no test of its own.
  - Why: stop 7 expires during the last read and is caught by the post-read `check()` at :145.
    Removing :217 would not fail any test, although the test name says "final result".
  - Fix: add a seam case in which the deadline passes during parsing, or rename the test.
- LOW (consistency): when both cancellation and expiry hold, the two paths return different error
  codes. `check_budget` (coding_repository_commit_review.rs:282) tests cancellation first;
  `observe_commit_git_until` (:577 and :629) tests expiry first. Both fail closed. Fix: use one
  order.

The carried lows stay same-row backlog: privileged device-node substitution, real-time deadline
test robustness, the stale comment at local_commit_execution.rs:98, and native deadline-forwarding
coverage.
