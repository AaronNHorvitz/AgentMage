## M1 verification: process lifetime and reservation release

Design reviewed (`scripts/local_agent_fast_gate.py`):

- **`execute_checks`.** Creates a fresh `os.pipe()` per check. Python pipes are
  non-inheritable by default. Only the read end goes to the supervisor, via
  `pass_fds`. The gate keeps the write end. The supervisor starts with
  `start_new_session=True`.
- **`supervise`.** Starts the check with `process_group=0` and the default
  `close_fds=True`, so the check holds neither pipe end. It polls for EOF on the
  lifeline, its own SIGINT/TERM/HUP flag and the deadline. Its `finally` always runs
  `stop_check`.
- **`stop_check`.** Sends `killpg(TERM)`, waits up to 5 s for the leader, then
  `killpg(KILL)` and reaps. This also runs after a normal exit.
- **Gate handlers.** The gate handles SIGINT, SIGTERM and SIGHUP, stops starting
  checks, closes the write end and waits for the supervisor.

Builder tests (21, all pass): SIGTERM, SIGHUP and SIGINT to the gate with no next
check; SIGKILL of the gate's group; SIGTERM to the supervisor; normal exit with a
TERM-ignoring child; and a real `flock` inherited by the child that becomes
acquirable afterwards. The tests use pidfds for their own cleanup.

My independent probes ran the gate in its own session. Each check was
`bash slot.sh python3 -c …`, where `slot.sh` holds `flock` on fd 9. The check
double-forks a TERM-ignoring grandchild that is reparented away from the check
leader but stays in its group and inherits fd 9:

| Probe | Gate exit | Survivors | Lock |
| --- | --- | --- | --- |
| SIGKILL to the gate PID only | -9 | none | released |
| SIGTERM to the gate's process group | 1 | none | released |
| SIGTERM, then SIGKILL 50 ms later, to the gate's group | -9 | none | released |
| Check child calls `os.setsid()` (documented limit) | 1 | 1 | **held** |

The last row confirms the limit documented at
`docs/guides/local-agent-development.md:67-71`. Product code that starts new
sessions does so through `bwrap --new-session --die-with-parent`:
`platforms/linux/src/{sandbox,command_runner,repository_safety,research_sandbox,security_controls}.rs`
and `platforms/linux-inference/src/llama_server_driver.rs`. Those processes die with
their in-group `bwrap` parent, so this limit does not affect the product's own test
processes. Supervisor SIGKILL is likewise documented as a residual limit. The
reviewer brief accepts both as documented limits. The guide and the evidence say
plainly that this is development cleanup, not a sandbox, and no product confinement
code changed (diff exit 0 above).

M1 is resolved.

### L4 (low): the review-text check rejects the `INCONCLUSIVE` format and accepts verdicts that do not exist

Location: `scripts/local_agent_fast_gate.py:112`.

The reviewer template ends an inconclusive report with `Verdict: INCONCLUSIVE`
followed by a reason line. The check requires the last line to be one of PASS,
FINDINGS, FAIL or BLOCKED. Reproduction in a temporary root:

- A report ending `Verdict: INCONCLUSIVE` plus a reason line is refused with
  `review must end with its explicit verdict`.
- A report ending `Verdict: BLOCKED` is accepted.

So this report, for example, cannot be retained byte-for-byte without changing the
gate, while the gate accepts verdict strings that the review process never produces.
The check fails closed, so this is not a security issue.

Fix: accept exactly `{PASS, FINDINGS, INCONCLUSIVE}`. For INCONCLUSIVE, require the
verdict on the penultimate line and a non-empty reason on the last line. Add tests
for both, and a test that refuses FAIL and BLOCKED.

### L5 (low): the check's group is signalled after its leader has been reaped

Location: `scripts/local_agent_fast_gate.py:210` (`process.poll()` reaps) with `:172`
(`killpg(process.pid, …)`).

After a normal exit, the leader is reaped before `killpg` runs. If the group is
already empty, its ID could be reused by an unrelated new group leader in the
interval, and that group would receive TERM and KILL. The window is microseconds
across a 4M PID space, so this is theoretical, but it is avoidable.

Fix: observe exit with
`os.waitid(os.P_PID, pid, os.WEXITED | os.WNOHANG | os.WNOWAIT)`. The zombie leader
then keeps the PGID reserved until `stop_check` has signalled the group; reap
afterwards.
