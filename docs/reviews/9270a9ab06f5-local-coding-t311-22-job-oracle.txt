## Analysis against the inspection list

- **Full-response validation before replay.** `RemoteFunction.__call__` validates the complete job reply before it
  returns (`coding_eval_oracle_worker.py:257-266`, `valid_job_result` at `:408-415`): exact keys, a closed tag set,
  the codec for value and calls, ≤128 calls, and value None when a refusal tag is set. Only then does
  `job_proxies.call` (`:422-442`) replay. The builder test `test_job_wire_is_fully_validated_before_replay` shows the
  mock is untouched for nine malformed replies; I re-checked by reading the code.
- **No live replay target.** Replay requires `isinstance(module.signal_running_cli, mock.Mock)`. That check is made
  both when choosing `record` and again before the replay. Outside the test's patch, calls are discarded. My forge
  probe confirms this end to end.
- **Parser fidelity.** `job_namespace` keeps tagged Path, list and tuple values. Keys are restricted to
  `[a-z][a-z0-9_]{0,63}`. Unrepresentable defaults (for example `set_defaults(x=print)`) become adapter_policy.
  `parser_exit` maps only exit status 2 to SystemExit(2). Reference defaults (`follow_up=[]` and similar) pass.
- **Fixed refusal tags.** `harness`, `key` and `argument-type` become trusted local classes with the fixed message
  `oracle.job-refused` (`:435-441`). Any other candidate exception becomes the payload-free sticky
  candidate-exception flag (`export-valueerror` probe; builder `unexpected-exception`).
- **Finite directory.** `/tmp/[A-Za-z0-9_-]+` is recreated only in the candidate's private tmpfs (`:490-498`). An
  existing directory outside that rule is adapter policy. No host scratch bind was added.
- **Counts and profiles.** `CONTROL_PROFILES["dev-028"]` (failures 0, errors 1, 13/18 calls) is enforced by the
  unchanged `expected_base`. Only the aggregate pair assertions moved from 17 to 18.
- **Admission and integrity.** Generated snapshots are refused before any output directory exists or any worker is
  launched (builder test and unchanged `grade`). The collection fingerprint, hidden bytes, pins, selections,
  thresholds and the legacy evaluator are unchanged. dev-028 is a development-split task. The diff has no held-out
  content and no prompt, model or harness tuning.
- **Hygiene.** The committed diff contains no private host path, username, hostname, credential, private sibling
  project, other-product comparison or trademark branding. The `/lane` literal in a confinement assertion is an
  existing generic test pattern.
- **Delivery.** One sub-row level; the row ships a running, measured adapter.

## Findings

**M1 (medium) — the oracle never runs the candidate's no-live refusal, so a candidate that breaks it passes; the
coverage says it is graded.**

- Code: `scripts/coding_eval_oracle_worker.py:509-511` replaces the candidate's own `signal_running_cli` with a
  fixed `HarnessError("oracle.no-live-cli")` stub whenever the test's mock is absent.
- What the frozen method checks: hidden lines 369-371 do not stub that helper. They run the candidate's real
  `signal_running_cli` against an empty temporary directory and require HarnessError. The task statement also
  requires "no live run raises HarnessError". In the reference, that empty directory refuses at `read_run_record`
  before any process is looked up, so this check needs no process identity or signal delivery.
- Reproduction: `liveness-deleted` (helper returns None) and `liveness-crashes` (helper raises ValueError) both
  **PASS the independent oracle** (0 failures, 0 errors, 18 calls). The unchanged frozen method fails them in the
  legacy verifier, at line 370 ("HarnessError not raised") and line 371 (ValueError) respectively.
- Labelling: `coverage()` lists `unknown-control-and-no-live-refusals` under `graded`
  (`scripts/coding_eval_oracle.py:87`). The guide says "no-live refusal still reach[es] the original assertions"
  (`docs/guides/coding-evaluation-oracle.md:540`). Only the stub's refusal reaches them.
- Why medium: the oracle is meant to admit generated attempts later. As written, it passes candidates the frozen
  hidden method fails. This is undisclosed lenience on a clause the original asserts, not one of the stated
  ungraded limits (enum identity, base/keyword arguments, return values, process identity, delivery, bundle
  propagation and privacy). No score is produced today, so it is not high, but it blocks closing T-311.22.
- Concrete fix:
  1. For `record=False` calls, recreate the trusted temporary directory in the candidate's private `/tmp` with the
     existing `/tmp/[A-Za-z0-9_-]+` rule. Run the candidate's own `signal_running_cli` there, unstubbed. It runs in
     the same networkless, private-PID sandbox that already executes arbitrary candidate code, so the risk does
     not change.
  2. Use the existing closed tag for HarnessError and the sticky candidate-exception flag for anything else.
  3. Add `liveness-deleted` and `liveness-crashes` as variants that must fail with `test_failure` and
     `candidate_exception`.
  4. If the stub is kept instead, move no-live refusal to `not_graded` and state this false-pass path in the guide
     and evidence. That alone still leaves the oracle more lenient than the frozen method, so the repair is
     preferred.

**L1 (low, backlog before generated scoring) — correct candidates the original passes are refused.**

- Observed: `control-returns-enum` (an unasserted return value of type `signal.Signals`) and `pure-path-parser`
  (a PurePosixPath equal to the expected Path) are graded adapter_policy. `swallow-mock-typeerror` is graded
  test_failure. The legacy verifier passes all three.
- Causes:
  - Return values are transported and must be codec-representable (`coding_eval_oracle_worker.py:536`), although
    the guide says they are not asserted.
  - The candidate-side stub accepts calls with any signature (`:509`), whereas the original mock raises TypeError
    on a wrong arity.
- Fix: drop return values of `stop`/`control` from the reply, since they are unasserted. Run the stub with the
  original mock's `(base, number)` signature. Name the subclass/PurePath refusal next to the existing T-311.20 L1.

**L2 (low, test coverage) — one unit test checks a different branch from the one it names.**

- At `tests/test_coding_eval_oracle_worker.py:77-81`, the test is commented "A plain function is not an accepted
  replay target". It calls index `[3]` (export), which fails through the `oracle.unexpected-job-calls` branch.
- The `stop`/`control` path with a non-mock helper and a reply that carries calls has no unit test. My end-to-end
  forge probe shows that path behaves correctly.
- Fix: call `[2]` (control) with a plain-function helper, assert the call is not replayed, and keep the export case
  as its own check.
