## Analysis

- **Reachability and scoping.** `capture_applied_write_review` is now `pub(super)`, visible
  only inside `coding_repository`. Its only non-test callers are the view and
  `plan_reviewed_candidate_tree_with`. Sibling `apply_tests` also use it.
  `plan_reviewed_candidate_tree` is module-private. Neither is reachable outside the crate
  except through `LinuxCodingCommitReview`. The view's only field is private, it has no derives
  (no Clone or serialization), and the only way to build it is `consented_commit_review`
  (coding_repository_commit_review.rs:71-86). No HTTP, CLI or MCP route was added.
- **Order of checks.** `consented_commit_review` reads only in-memory `self.created`, then
  compares both caller digests with the retained `original` and `held` digests. Only after
  that does it call `verify_apply_roots`, the first filesystem access. So a mismatch returns
  `code.commit.read-scope` even when a root is missing, and the first new test checks exactly
  that for both roots and for absent, empty, foreign and swapped selections.
- **Strength of the digests.** `workspace_path_sha256` hashes the canonical path plus device
  and inode. `authorize_workspace_root` opens each component with `O_PATH|O_DIRECTORY|O_NOFOLLOW`.
  A replacement directory at the same path therefore gets a different digest, and a symlink
  substitute fails to open. Those cases match test 2's `code.apply.scope` /
  `code.command.scope` expectations. Equal digests still go through `verify_apply_roots`, and
  `capture_applied_write_review` calls it again at the start and end of every use. Planning
  also re-runs it before taking Git observations.
- **Foreign owner.** The proof's `root_sha256()` is compared with `created.held` (commit_review.rs:110),
  so a substituted `CreatedWorktree` yields `code.commit.write-provenance`, as test 3 shows.
  Replacing `created` is possible only inside the module, because the field is private.
- **Borrow claim.** Every effecting method on `LinuxCodingRepository` (`prepare_apply`,
  `prepare_validation`, `decide_*`, `prepare_edit`, and others) takes `&mut self`. The
  repository has no interior mutability: the only `Mutex` is in the runtime wrapper that owns
  the repository by value. While the view lives, the shared borrow does block owner effects.
  The documents correctly say external filesystem changes stay possible.
- **Honest claims.** The decision, evidence and guide say plainly that the digests correlate
  a selection and do not authenticate consent or grant anything. They also say Git/process
  observations are synthetic, native admission is unavailable, and candidate execution,
  provenance, product approval, durable recovery, model measurements and push stay open. The
  stated counts and timings match the bundle. The two superseded focused logs (2 pass / 1 fail
  each) are kept, and their explanation matches the final assertions: a worktree rename
  invalidates the completion seal, while an original-only rename leaves it intact. No product
  check or threshold changed. The diff touches only the 9 listed files.
- **Evaluation integrity.** No evaluation, hidden, held-out, scorer, prompt, threshold,
  scoreboard, dependency, SBOM or lifecycle change. TASKS row lines are byte-identical to the
  base (check.py and stage_check.py), and no row or sub-row was added.
- **Public content and IP.** The added lines contain no private host path, username, hostname,
