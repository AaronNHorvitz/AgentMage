### M2-R (medium): dev-002 statement says to preserve a value the hidden test requires changing; dev-003 omits a required rejection

**dev-002 (contradiction).**

- Location: `scripts/coding_eval.py:86`: "Preserve schema_version=2 and do not add model fields to
  the persisted run record."
- At base, `diagnose()` emits `"schema_version": 1` (base `scripts/coding_harness.py:630`). Only
  the run record is 2 (`RUN_RECORD_VERSION = 2`, base line 29).
- The frozen hidden test asserts `starting["schema_version"] == 2` on the diagnosis output
  (`tests/test_coding_harness_model_diagnostics.py:94` at reference 0898b05a). The reference
  changes `diagnose()` to `DIAGNOSIS_VERSION = 2`.
- Reproduction:
  1. `prepare --task dev-002`.
  2. Install the historical reference source, changing only `"schema_version": DIAGNOSIS_VERSION`
     back to its base value `1`. This candidate implements every stated contract item and
     "preserves" `schema_version`.
  3. Run `score` through `/tools/build-slot`.

  Result: exit 1, `test_failure`, 3 tests with 6 failures, all `AssertionError: 1 != 2` at that
  line. The unmodified reference scores exit 0.

**dev-003 (omission).**

- Location: `scripts/coding_eval.py:102-104`. The statement says to accept PASS, FINDINGS or
  INCONCLUSIVE with one reason and to reject *malformed* endings.
- The base also accepts `Verdict: FAIL` and `Verdict: BLOCKED`. Those are well-formed under the
  base rule, and the statement never says to stop accepting them.
- The hidden test requires both to raise (`tests/test_local_agent_fast_gate.py:160` at reference
  e88a9b42).
- Reproduction: the reference source with FAIL and BLOCKED kept in the accepted set gives `score`
  exit 1, 23 tests with 2 failures (`ValueError not raised` for `Verdict: FAIL` and for
  `Verdict: BLOCKED`).

**Impact.** dev-002 cannot be solved by following its statement: a faithful candidate fails every
lifecycle subtest. dev-003 penalises the minimal reading. The evidence's M2 paragraph
(`docs/evidence/t311-1-evaluator-review-repair-2026-11-03.md:31-35`) says the three statements
were extended with the output keys, codes and encodings the hidden tests require. That is not true
for dev-002. Any later model baseline would count these as coding failures when they are statement
defects.

The prior review missed both items. Its M2 list for dev-002 named the renamed and removed keys but
not the version change.

**Fix (before any model measurement, same pre-measurement correction class):**

1. Replace the dev-002 sentence with, for example: "diagnose() output sets schema_version to 2
   (was 1); the persisted run record keeps schema_version=2 and gains no model fields."
2. Add to dev-003: "Stop accepting Verdict: FAIL and Verdict: BLOCKED."
3. Re-pin the fingerprint, keep every other field identical, and correct the evidence paragraph.
4. Extend the regression beyond module attributes. At minimum, run every v2 statement through a
   "literal diff" check: each string or integer literal that the hidden test compares against and

   record a manual per-assertion audit in the evidence. Also cover `mock.patch("scripts.…")` string
   targets and nested new attributes (`alias.Class.new_method`), which the current AST walk skips.
