## Assessment of the claimed properties

- **Factory:** `Box::leak` is gone from coding_development_runtime.rs (the only remaining one is the
  test fixture's profile at linux_coding_runtime.rs:5950, as disclosed). The platform, profile and
  workspace are `Arc`s.
  - Failed construction uses `?` on owned values and drops them normally.
  - `refresh_repository_composition` (coding_development_runtime.rs:620-641) replaces the factory's
    `Arc`s. A live boundary keeps its own clone (`Arc::clone(&self.workspace).into()`, line 1569),
    so a run's binding is never swapped. This matches the previous behaviour with leaked `&'static`
    references.
- **Owned binding:** `bind_owned_development` (linux_coding.rs:369) runs the unchanged
  `bind_development` checks on the exact `Arc` targets (path hash, projection,
  `select_development_linux_workspace`, revalidate, `held_workspace_root`). It then keeps those
  same `Arc`s. `OwnedDevelopment` resolves through the same
  `resolve_development_linux_workspace_object` as `Development` (line 472), and that is the only
  `match` on the platform. No check is skipped or relaxed.
- **Prepared operations:** `prepare` stores `Arc::clone(&self.workspace)`, which is the binding's
  already-held root. Nothing reopens a path or constructs a lease. `revalidate` still checks the
  root, then the binding, then the root again. Write and create still need the live
  `owned_worktree` lease driver or the unowned path, exactly as before. The approval, grant,
  terminal-publication and ownership code is untouched.
- **Five registry borrows** (linux_coding_runtime.rs:1937, 2082, 2159, 2325, 2470):
  `self.workspace.clone()` is a reference copy (Borrowed) or an `Arc` clone (Shared) of the
  boundary's own handle. It cannot pick another binding or registry, and it lives through the
  `execute_effect_authority` call. The policy, transaction and driver arguments are unchanged.
- **Fixture:** the workspace is now an `Arc` and the profile stays the leaked static test profile,
  stored explicitly. `profile_for_test` returns that same object. The four captures
  (7415/7870/8214/8477) now `clone()` the handle.
- **New tests** (linux_coding_lifetime_tests.rs):
  - The weak-reference checks are specific. The profile and platform stay alive while only the
    owned binding holds them and die after it drops. The root stays alive and the descriptors stay
    above 0 while only the prepared read holds them, then both drop to zero.
  - Plan equivalence compares `plan_sha256` of borrowed and owned preparations of the same call.
  - Test 2's `assert_ne!` compares `GrantTarget` values, whose equality covers identity and
    preimage, not descriptor numbers. So it shows a real observation change, and the old operation
    refuses with `TargetDenied`.
  - The descriptor count is limited to the test's own unique directory (`/proc/self/fd` readlink
    prefix).
  - The test uses a real worker thread.
- **Privacy, IP and trademarks:** the added lines contain no private host path, username,
  credential or product branding. `/lane/...` paths appear only in the retained report, as in
  previously accepted reports. There is no new dependency and no `unsafe`, and the SBOM is
  unchanged.
- **Ledger:** TASKS.md rows are unchanged (audit). The prose adds only the retained PASS and a
  non-closing note.

- **L1 (low, evidence precision): the changed boundary paths have no executed test in this lane.**
  - Location: shells/host/src/linux_coding_runtime.rs:6010-6012, :11304.
  - The native-boundary fixture panics at `sandbox()` (line 6010) before it builds the handle at
    line 6012. So every boundary test that would exercise the changed code is among the 42 baseline
    failures. That covers `prepare` via the handle, the five registry clones, `into_parts`
    consumers, the write/create driver roots, and all four modified captures
    (`story_22_1_long_native_session_blocks_drift_and_preserves_exact_history`, and the three
    `story_22_2_linux_restart_*` tests at 7870/8214/8477).
  - Those changes are therefore checked only by compilation and Clippy plus static reasoning. The
    reasoning is sound: they are mechanical type changes, the borrow checker enforces them, and
    they change no authority logic.
  - The evidence does not say this. It describes the failures only as the unchanged baseline, and
    the factory-level release claim in the guide (coding-owned-runtime.md:176-181) is not observed.
  - Fix: state in the evidence that these boundary tests fail at sandbox-manifest construction
    before reaching the changed code. When a host that passes manifest verification is available,
    run the boundary suite there.
- **L2 (low, test strength/naming): the wrong-root refusal doesn't exercise partial-construction release.**
  - Location: shells/host/src/linux_coding_lifetime_tests.rs:250-268.
  - The wrong-root refusal fails at `verify_worktree_path` (linux_coding.rs:345) before any
    descriptor is opened. So it doesn't show that a partly built held workspace is released; Rust
    drop semantics are what guarantee that.
  - The test name says "refresh", but the loop does no refresh.
  - Fix: rename the test, or add a refusal after the descriptor is selected.

Both are backlog notes in the T-303/T-306 rows, not new rows.
