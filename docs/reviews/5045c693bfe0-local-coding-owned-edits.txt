## Review against the requested inspection points

- **Ownership and adoption.** Every owned-edit route checks `req.control` before doing anything
  (`coding_repository_api.rs:124`). `PrepareEdit` and `Decide` use `deny_unknown_fields` and reject
  duplicate keys; root, creation receipt and approval fields refuse (tests and my reading agree).
  The root comes only from `self.created`. `select_created_sources` and `verify_edit_scope` compare
  the root's canonical path/device/inode digest with the held handle
  (`coding_repository_edit.rs:20-34`), and the scratch tests confirm a foreign scope refuses.
  Test-only injection is reachable only through private-field access in a `#[cfg(test)]` module
  (`coding_repository_command.rs:336-338`).
- **Binding and consumption.**
  - The outer hash covers operation, root digest, creation receipt, the entire kernel
    `write_preview` (including `complete_diffs` and inner digests), times, retention and warning
    (`coding_repository_edit.rs:52-58`).
  - A digest mismatch refuses before consumption. A match takes the pending edit before denial,
    expiry, scope or creation checks.
  - The inner change-set and preview digests passed to `apply` come from the stored preview, not
    from the caller. `apply` also enforces its own monotonic deadline, and the API passes the
    server clock (`clock_ms()`).
- **Route separation.** A command digest refuses at edit decide and an edit digest at command
  decide, and neither consumes the other (native test).
- **Invalidation and the validation budget.** `self.command = None` runs immediately before
  dispatch, which clears both pending command and pending validation previews (validation is
  stored as `PendingCommand.validation`). `self.validation`, holding the template, spent attempts
  and latest receipt, is kept, so the native test's attempt count goes 1 → 1 → 2. A new successful
  creation clears the pending edit and the latest result (`coding_repository.rs:396-397`).
- **Preimage drift, root and management swaps, changed creation, denial and expiry, restart.**
  All are covered by committed tests and by my reproductions above. Restart loses all edit state
  and ownership, and no receipt restores it.
- **Prior low findings.**

## Findings

No critical, high or medium findings.

- **L1 (low, pre-acceptance).** The positive owned-edit path through the actual HTTP routes and
  CLI is never exercised against a held worktree. This covers `coding_repository_api.rs:48-94`
  and the `/edit/decide` arm at 178-186. All committed API tests end at
  `code.command.worktree-required`, because native creation is refused in this lane and the API
  crate cannot inject provenance. My scratch glue reproduction passes, so this is a coverage
  gap, not a defect. Fix before parent acceptance: an HTTP-level positive prepare→decide test
  once positive native creation is measured, or a narrowly `cfg(test)`-gated provenance seam
  usable from the API crate.
- **L2 (low, backlog; extends the open prior L4).** Edit routes return `code.command.scope` and
  `code.command.worktree-required` for root, management or ownership refusals, because
  `verify_created` is shared (`coding_repository_command.rs:86-108`). Fix: map these to
  `code.edit.*` in `verify_edit_scope`/`select_created_sources`.
- **L3 (low, backlog).** A decision consumed but refused before dispatch leaves `latest`
  unchanged. This happens on expiry, clock reversal, scope refusal or changed creation
  (`coding_repository_edit.rs:94-102`). After a lost reply, `inspect_edit` shows `pending: null`
  and the previous preview's result. The two can be told apart only by comparing
  `preview_sha256`. Fix: record
  `{"preview_sha256":digest,"outcome":"refused","error":code,"effect":"none"}` before returning
  these errors.

Prior open low findings are retained as stated by the builder: L4 shared error prefixes (see L2
above), L5 the same-user post-create identity window, and the missing native positive proof.
