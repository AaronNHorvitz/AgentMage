## Analysis

- **Bounded memory:** each stream uses the existing `Capture` with a 4 MiB limit
  (`LOCAL_COMMIT_CAPTURE_BYTES` equals `sandbox::MAX_OUTPUT_BYTES`, so `Capture::new` accepts it).
  Bytes past the limit are never retained, and overflow returns `OutputLimitExceeded` during
  the read, not after allocation. This replaces the unbounded `Command::output()` in `run_gpg`.
  An exact-limit capture passes and limit+1 on either stream fails (test).
- **Fairness:** each poll does at most 8×8 KiB reads per stream, followed by a sleep of at most
  10 ms. Cancellation and deadline are checked before and after every poll, including after the
  immediate child has been reaped. `yes` cannot starve either check (test).
- **Teardown:** `abort_and_reap` signals only the opaque owned `Child`, and only while it is
  still unreaped (std `Child::kill` on an unreaped child cannot hit a reused PID). It polls
  `try_wait` for at most 500 ms, with no blocking `wait`, no thread join and no PID or group
  lookup. If reaping fails, `CleanupUncertain` is returned and the `Control` (child and pipes)
  stays in the slot. On success the slot is taken, and partial output is dropped on failure.
- **Admission:** `try_lock` refuses both busy (WouldBlock) and poisoned owners. A retained
  slot refuses before spawn. Pre-cancelled or expired requests refuse before spawn. Spawn
  failure leaves the slot empty. The child sits in the slot before pipe initialisation, so a
  missing pipe still leads to bounded kill/reap (test).
- **Deadlines:** listing and export share one 30 s deadline created at the start of
  `inspect`. Signed creation and verification reuse `io.deadline()` from the
  `CommitIoSession`, the original session deadline. Failures after signing begins still
  map to `uncertain_commit_result`, so cleanup is never reported as verified. The control
  `CONTROL_BYTES` limit (8 KiB) is unchanged; `initialize()` delegates to
  `initialize_with_limit(CONTROL_BYTES)`.
- **Honest scope:** the evidence, guide, TASKS text and code comment all state that this is
  not signer confinement, descendant cleanup, offline proof or activation. The inherited-pipe
  test keeps the separate writer alive after the refusal, which shows that limit rather than
  hiding it. No row or sub-row is added or closed. TASKS row lines are byte-identical to the
  base. No evaluation, held-out, hidden-test, prompt, threshold, dependency, model or GPU change.
  The confinement boundaries for product tools (`run_owned` / closed supervisor) are untouched.

## Findings

No critical, high or medium findings.

- **L1 (low, test coverage)** `platforms/linux/src/local_commit.rs:774-795` and `:621-626`.
  No passing test runs the production wiring of `run_gpg` or `SignedGitRunner` through the new
  capture. The only native test (`native_signed_commit_verifies_exact_content_and_only_updates_task_branch`)
  is an inherited failure: in this environment `/usr/bin/gpg` is `nfsnobody`-owned, so
  `verify_root_executable` returns `ArtifactDenied` before any capture. The evidence labels the
  eight methods as component tests honestly, and my gpg probe shows prompt EOF, so this does not
  block. Fix: add a unit test that calls `run_gpg` (or a thin wrapper) on a fixture script for
  deadline, overflow and non-zero exit, asserting the `ArtifactDenied` mapping and an empty
  `LOCAL_COMMIT_CHILD`.
- **L2 (low, diagnostics)** `platforms/linux/src/sandbox_supervision.rs:449-455`. A retained,
  unresolved child returns `ExecutionFailed`, not `CleanupUncertain` (unlike
  `admission_snapshot_of`). Both callers then flatten every capture error, to `ExecutionFailed`
  in signed Git and to `ArtifactDenied` in inspection. A later signer inspection after an
  unreaped child therefore reports an artifact denial. This fails closed but misattributes the
  cause. Fix: return `CleanupUncertain` for a retained or poisoned owner and preserve that kind
  in the local-commit error mapping.
- **L3 (low, availability)** `platforms/linux/src/sandbox_supervision.rs:449-451`. A retained
  child is never re-polled, so a child that is only briefly unreapable (for example in D state
  for more than 500 ms) disables direct signer capture for the rest of the process. This matches
  the existing `OWNED_ATTEMPT` design and fails closed. Optional fix: try one nonblocking
  `try_wait` on the retained child before refusing, and clear the slot only on a positive reap.
