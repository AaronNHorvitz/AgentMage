## Assessment by area

- **Sealed assertion process.** The runtime compiles the original module first, then detaches
  `/adapter`, `/output` and `/proc`, checks that they are gone and that `/` is read-only, and only
  then launches the candidate bridge (seal.py:48-59, runtime.py:99-120). Results go only to
  pre-opened `xb` descriptors. The bridge uses `close_fds=True`, passes only the seccomp
  descriptor and an empty environment, and is PID 1 in a fresh PID namespace without network,
  capabilities or user namespaces.

  Host pass requires all of the following:
  - the oracle exit code is 0;
  - exactly one test per method, with no failures, errors, skips or unexpected successes;
  - calls > 0;
  - the method is sealed, with no open proc window;
  - every method is present.

  A forged summary print, an assertion monkeypatch or an early exit cannot pass (existing tests,
  confirmed in code).
- **Candidate namespace and typed graph.** The wire carries only JSON primitives, typed tokens
  and identities. Decoding never instantiates a candidate class in the oracle. Exceptions are
  restricted to builtin, API or trusted fixture categories without running constructors.
  TestCase and TestResult tokens refuse. Mock `assert*` and reset APIs cannot be overridden.
  Candidate requests into the oracle are limited to fixture callbacks, fixture classes and
  objects, and memory streams; they run at callback depth under an audit hook that blocks
  process, socket, ctypes, compile, exec and frame access. I found no route from candidate data
  to oracle code execution or to the result descriptors.

  Mock core fields (call history, return value, side effect) do synchronise from the candidate.
  That matches in-process semantics and is covered by the admission policy's disclosed
  `candidate-self-reported-observation-fidelity` and `deliberate-candidate-self-modification`
  limits.
- **Boolean/integer fidelity.** The fix is correct and minimal. I checked the other token kinds
  for Python-equality aliasing in the delta cache (float, bigint, bytes, path, tuple/set/frozenset,
  dict pairs) and found no remaining alias that would hide a type change.
- **Native exceptions.** `native_exception` keeps `SystemExit.code` and `StopIteration.value`
  without fixture constructors. A candidate cannot produce `SkipTest`, and skips fail the host
  check anyway.
- **Proc windows.** A window opens only when the oracle is single-threaded, not already in a
  window and not inside a callback, and it is detached and re-cloned in `finally`. The candidate's
  nested root has an empty `/proc` directory, so an oracle-side attach does not propagate.
- **Complete-set admission.**
  - The receipt must match every field: 160 attempts, 30 + 10 independent tasks, 104 + 104

  - Sources are re-checked at the end.

## Findings

No critical, high or medium finding. All five findings below are **low** backlog items.

- **L1 (low): undisclosed shared writable fixture filesystem**
  - **Where.** The candidate bridge and trusted native fixtures share the oracle's `/tmp`
    read-write: `nested_command` binds `--bind /tmp /tmp` (`scripts/coding_eval_gate_oracle.py:138`),
    used by `launch_bridge` (`scripts/coding_eval_worker_seal.py:122`).
  - **Reproduction.** Probe 2: candidate code rewrote a trusted fixture file, and the script a
    trusted native fixture executed, after the test created them. The hidden-side assertions
    observed the forged values; the controls did not.
  - **What it does not allow.** The candidate stays inside the per-method 64 MiB tmpfs, without
    results, assertions, procfs or network. Exploiting it needs a deliberately adversarial
    candidate that knows hidden fixture paths. In-process original semantics allow the same, and
    no control is affected.
  - **Why it is still a finding.** The worker guide (`docs/guides/coding-evaluation-worker-oracle.md:18-20`)
    describes the filesystem as sealed. Neither `coverage()['not_graded']`
    (`scripts/coding_eval_worker_oracle.py:192`) nor the admission limitations name this channel.
  - **Fix.** Before publishing held-out scores, add a `candidate-writable-temporary-fixtures`
    limitation to worker coverage and the guide. Longer term, give the bridge its own tmpfs,
    shared with the oracle only through explicitly passed paths, and run native fixtures from
    trusted read-only copies.
- **L2 (low): misattributed failure causes in the held-out path**
  - **Where.** The runtime hard-codes `adapter_policy_failed: False`
    (`scripts/coding_eval_worker_runtime.py:132`), while `Peer.answer`/`guard_class` set
    `failed = True` for both fixture-callback assertions and graph refusals
    (`scripts/coding_eval_worker_graph.py:869,894,940,946`).
  - **Consequence.** Candidate test failures inside callbacks, adapter-representation limits and
    true wire faults all become `cause: protocol`, and admission labels them `fail`, never
    `ungradable` (`scripts/coding_eval_admission.py:99-100`). Probe 3 shows a caught callback
    assertion reported as protocol with zero failures. The guides' statement that a policy
    refusal is ungradable does not hold for this path.
  - **Impact.** Pass counts and denominators are unaffected.
  - **Fix.** Before T-311.18 publishes failure causes, record separate flags for
    fixture-assertion, boundary-refusal and wire-fault in the method record. Map them to
    `test_failure`, `adapter_policy` (ungradable) and `protocol`.
- **L3 (low): stale guide text**
  - **Where.** `docs/guides/coding-evaluation.md:271` still says the independent oracle "runs
    nineteen" tasks. Lines 278 and 292-293 say generated scoring is disabled "until … separate
    aggregate worker quotas exist" and that L2 (aggregate quotas) "still block[s] enabling
    generated scoring".
  - **Problem.** That contradicts the new admission command.
  - **Fix.** Scope those sentences to this legacy scorer and point to the admission section's
    lane-quota disposition.
- **L4 (low): held-out generated entry never executed end-to-end**
  - **Where.** The `--split held-out` branch (`scripts/coding_eval_admission.py:86,96`) is never
    exercised. Only the purpose refusal is unit-tested (`tests/test_coding_eval_admission.py:67`),
    and the actual entry ran on development only.
  - **Mitigation.** It shares `worker_oracle._grade` with the verified held-out controls.
  - **Fix.** Add a synthetic-descriptor admission test through `split='held-out'` (mocked
    `held_out_tasks`, synthetic worker fixture). The first real use is the T-311.18 row-close
    scoreboard.
- **L5 (low): intermittent frozen dev-003 race**
  - **Observation.** The race reproduced once in my required fast gate (1 error in the dev-003
    reference) and not in 8 retained repeats or the suite run.
  - **Policy.** `docs/guides/coding-evaluation.md:187-199` counts it as a failed attempt with no
    retry, and admission does that. The same text requires "this label" on reports before
    generated scoring is enabled.
  - **Gap.** Admission rows and per-task reports carry no known-race label. It exists only in the
    receipt-bound `development-coverage.json`.
  - **Fix.** Before T-311.18 publishes dev-003 results, copy `known_races` into the attempt row or
    summary.
