## Findings

No critical, high or medium finding. The low findings below are backlog/admission items in the
same row, not new rows.

### L1 (low): descriptor and output location are documented but not enforced

scripts/coding_eval_suite.py:64-78 (`private_bytes`) and :214/:218 (`verify` output) accept any
path. docs/guides/coding-suite.md:21 says the descriptor stays outside the repository and the
editing workspace, but nothing refuses a copy or an `--output` inside the repository tree or a
model workspace. My probe accepted a mode-600 copy at an arbitrary location. That same code path
would accept one under the repository root.

The row-close run writes per-task held-out stdout/stderr, including verbose test names and
tracebacks. Those could then land in a tracked or model-visible tree.

Fix: before reading the descriptor or creating output, resolve both paths and refuse them if they
fall under `evaluation.ROOT` or any configured worktree or model-workspace root. Add synthetic
tests for both refusals.

### L2 (low): two input-check refusals are vacuous, and three refusals are untested

- **Vacuous check.** scripts/coding_eval_suite.py:144 can never fire, because
  `evaluation.projection` returns only `scripts/*.py`.
- **Exact-bytes leakage only.** The leakage test at :136-138 compares exact source bytes. It would
  not detect a future development base that descends from a held-out reference and so contains
  the held-out fix in a later form. This is safe today, because the chronology in item 6 holds and
  the development set is digest-pinned.
- **Untested refusals.** `held-out-parent`, `held-out-identity` and `hidden-input-exposed` have no
  test.

Fix: add an ancestry refusal (no development base or hidden revision may be a descendant of any
held-out reference) and synthetic tests for the three refusals.

### L3 (low): guide states the strict base rule for every pair in the row-close command

docs/guides/coding-suite.md:78-80 states the strict rule in a paragraph that covers all pairs: a
base must exit 1, with no skips or expected failures. Only `controls_valid`
(scripts/coding_eval_suite.py:201) applies that rule, and only to held-out pairs. The development
pairs inside the same `verify` keep the older rule at scripts/coding_eval.py:902, which does not
require exit 1 or zero skips.

Fix: apply `controls_valid` to the development rows in the suite summary, or say in the guide that
the strict rule is held-out-only.

### L4 (low): artifact labelling and one evidence claim without a retained log

The private artifact `final-unit.log`, and the `final-unit` label in validation-results.json, are
the **initial failed** run. The evidence table at
docs/evidence/t311-suite-freeze-checkpoint-2026-11-05.md:79 lists that artifact without saying so.

Line 53 also claims a lint after writing the record, but that lint has no retained output. My
fast gate linted all five Markdown files and passed, so the claim now holds independently.

Fix: label failed artifacts as initial or failed in future records, and retain the post-write lint
output.

### L5 (low, admission planning): held-out scope and the "row-close only" execution rule

The scope is disclosed honestly at coding-suite.md:28-34:
- all ten held-out tasks change one evaluator-protocol module;
- that module belongs to the grading machinery itself;
- the builder wrote that history within the last three days.

The remaining T-311.17 work includes held-out independent adapters, and that work runs into two
problems:
- **Execution rule.** Building those adapters means studying the held-out hidden tests and
  validating the adapters against held-out controls. Evidence line 33 and the guide say held-out
  execution is reserved for row closing.
- **Changing source module.** Continued admission work may modify the same module, and the
  repository's ordinary tests for it contain the held-out methods.

None of this is agent tuning, and no violation has occurred.

Fix: before the row-close request, record how adapter validation runs without extra held-out
executions, or state that such runs are counted and retained. Record that held-out scores measure
only this narrow protocol domain.
