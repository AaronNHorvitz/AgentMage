## Findings

### L1 (low): two statement clauses graded by the frozen methods are lenient in the oracle

`scripts/coding_eval_oracle_worker.py:217-220` reconstructs every helper result
as a JSON list. `coding_eval_oracle_worker.py:372-378` runs the dev-022 preamble
against the trusted base's `CASE_ROOTS`. As a result:

- A tuple-returning helper passes the oracle, although the statement says
  `-> list[str]` and the legacy grader fails it.
- A candidate with duplicate case roots passes the oracle, although the
  statement says "unique CASE_ROOTS c20" and the legacy grader fails it.

Both gaps are disclosed accurately: labels `argument-return-container-type` and
`candidate-case-root-uniqueness`, the guide, the evidence and real probes. Only
frozen controls are admitted, so no current number is affected. Unlike the
strict policies, these gaps would inflate a generated score.

Fix before generated scoring:

- Transport a fixed container tag (for example `"list": true` only when
  `type(result) is list`) and rebuild a non-list value as a tuple, so the
  original `assertEqual` decides.
- For dev-022, add one startup observation of the candidate's `CASE_ROOTS`
  string values, and install a dict rebuilt from them on the trusted module
  before the hidden method runs.

### L2 (low): adapter-policy refusals are reported as `cause: protocol`, the same cause as deliberate forgery

The following candidates pass the frozen methods under the legacy grader but
fail the oracle as `protocol`:

- integer truthy verification results;
- a callable or list in the parser namespace (the common `set_defaults(func=…)`
  idiom);
- a `SystemExit` code other than 2.

The causes are `coding_eval_oracle_worker.py:164-184` and `:242-245`, and the
classification at `coding_eval_oracle.py:255-256`. These behaviours are labelled
`adapter_policy` in each report's coverage, so they are disclosed. However, the
per-attempt `cause` cannot separate "adapter cannot transport this
statement-legal value" from "candidate corrupted the protocol". Decision 0153
requires failure causes in the recorded results.

Fix before generated scoring: send a fixed `adapter_policy` tag from the
candidate worker when a value is outside the bounded encoding, and report a
distinct cause. Alternatively, count such attempts separately from candidate
failures.
