## Review of the claims in scope

- **Dormant confinement.** The direct `GitRunner` temporary-index path is removed: `temporary_index` is gone
  from `GitRunner`. All four steps go through `run_worker`, which is the same closed supervisor path as the
  approved effects. It uses a manifest-verified systemd-run, systemctl, bwrap and Git, a seccomp policy over a
  withheld pipe, the `RepositoryGit` owner with three projections, the unit nonce, the deadline and bounded
  output. There is no direct-process retry or fallback. The only seam is a private `step_with` used by the tests.
- **Private index ownership.** `mkdirat(original.roots[2], "candidate-index-<id>", 0700)` runs relative to the held
  owned-root fd and refuses existing directories and symlinks, including dangling ones. The id charset excludes
  `/`, control characters and NUL, both in the platform code and in `valid_identifier`. The worker scope's owned
  root is the new directory only. The test asserts that `--bind-fd 7 <scratch>` is present and `<owned root>` is
  not. `validate_scratch` runs before and after every dispatch and admits only a single-link, owner-owned,
  non-group- or other-writable regular `index`.
- **Ordered exact steps.** The state machine (`initialized`, `next`, `blob`, `terminal`) admits only ReadTree,
  then the pairs (Hash file[i], Add file[i]), then WriteTree. Operation identity, the postimage SHA-256 and the
  64 MiB bound are checked before the memfd is created. Any error sets `terminal`. The plan's unique operation
  IDs and strictly sorted paths come from `validate_candidate_tree_plan`, and the builder also refuses duplicate
  postimages (`count != map.len()`).
- **Sealed input.** `sandbox::sealed_payload` provides a memfd with SEAL/SHRINK/GROW/WRITE seals, rewound to
  offset 0. The test asserts the seals, refuses a pwrite and checks offset 0. It replaces the
  `Stdio::null()` stdin. `run_owned` uses `PolicyWriter::Pipe` for this owner, so stdin is never taken for the
  filter.
- **Independent object IDs.** The hash output must equal `linux_git_blob_object_id(format, bytes)` plus a
  newline. The object format follows the parent object's length. The returned blob is the independently
  computed value. A forged ID is refused (tested).
- **Cleanup.** `cleanup_allowed` is cleared before dispatch and restored only from an `Ok` result's
  `output_complete`. `run_owned` returns `Err(CleanupUncertain)` when unit cleanup is uncertain, which keeps
  cleanup disabled. Root revalidation failure after dispatch also leaves it disabled. Cleanup lists the
  directory, refuses any entry other than a regular `index` / `index.lock`, unlinks those two relative to the
  held scratch fd, and removes the directory non-recursively relative to the held parent fd. Replaced-parent,
  replaced-scratch, unknown-file and symlinked-index cases are all retained (tested). There is no recursive
  delete anywhere.
- **Deadline.** A single session deadline (`PROCESS_TIMEOUT`, 30 s) is passed to each `run_owned` and checked
  before and after dispatch. It is covered by a test.
- **L1 and L2 from the base review.** L1 is clarified in the prior evidence. L2 is now documented in
  Decision 0189 and asserted in `worktree_effect_worker_projects_only_exact_metadata_and_owned_roots_writable`
  (the `--work-tree=` assertion). I also confirmed L2 empirically in my probe.
- **Honest labelling.** The evidence, decision, guide and README consistently say that the new tests use

## Findings

No critical, high or medium findings.

- **L1 (low, backlog):** `platforms/linux/src/repository_candidate.rs:67-78`.
  - **Problem:** if `original.revalidate()`, `LinuxRepositoryScope::verify` or the worker `capture` fails after
    the successful `mkdirat`, `new` returns `Err` without a session, so the empty `candidate-index-<id>` directory
    is left behind. That build id is then refused permanently. This fails closed, but it is retained scratch
    that is not one of the "unknown entries / changed roots / uncertain supervision" cases described in
    Decision 0190.
  - **Fix:** on those post-claim failures, `unlinkat(original.roots[2], directory, REMOVEDIR)` when roots still
    revalidate. Alternatively, document it as retained.
- **L2 (low, backlog):** `platforms/linux/src/repository_candidate.rs:75-78`.
  - **Problem:** the worker scope reopens the newly claimed directory by path. Its identity is not compared with
    a descriptor taken through `openat(original.roots[2], directory, O_DIRECTORY|O_NOFOLLOW)`. A same-uid host
    process could swap in another owner-owned 0700 directory between `mkdirat` and `capture`. NOFOLLOW and the
    ownership checks still apply, so this is not an escape from the guest, but the "held exclusively created
    directory" property is path-based for that window.
  - **Fix:** open the child relative to the held parent fd and require the same dev/ino in `capture`.
- **Note (not a finding):** the memfd stdin path through `systemd-run --pipe`, and every positive native worker
  run, are unexercised in this lane. The cause is the inherited executable-ownership and user-bus admission
  refusal, and the evidence discloses this accurately.
