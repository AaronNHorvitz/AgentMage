- **Held-directory, bounded, no-follow capture** (`:36-107`).
  - `verify_private_keyring` must return the same canonical path. The directory is opened
    `NOFOLLOW|DIRECTORY` and its dev/ino/uid/mode are revalidated before and after reading.
  - The database is opened `openat(held, name, NOFOLLOW|NONBLOCK)`. It must be a regular file owned by the
    user, with no group/other write, and size 1..=4 MiB. It is read completely with `pread`.
  - After the read, fstat and a no-follow `statat` re-check name, size, mode, uid, mtime and ctime. The bytes
    are then sealed into a memfd; seals SEAL/SHRINK/GROW/WRITE are asserted in the test.

    tests. The non-atomicity against concurrent same-user edits is disclosed.
- **Same sealed snapshot.** Each worker gets a fresh `dupfd` of the single memfd (`:187-188`). Export happens
  only after `signing_identity` succeeds over the listing. The evidence digest binds the version tag, database
  hash, listing hash, export hash and fingerprint (`:204-213`).
- **Exact attached/current fingerprint and primary** (`:246-302`).
  - Only an `fpr` immediately after its own `pub`/`sub` qualifies. It requires the lowercase own-key `s`

## Findings

No critical, high or medium finding.

- **L1 (low, backlog):** `platforms/linux/src/local_commit_inspection.rs:293-296`. Any key with a designated
  revoker is refused.
  - **Problem.** GnuPG prints `rvk` between `pub` and its `fpr` (real-GnuPG probe above). At that point
    `pending` is set, so `signing_identity` returns false. This fails closed, so it is not a confinement
    issue, but a valid public identity cannot be pinned.
  - **Fix.** Accept `rvk` while a `pub` is pending, without consuming `pending` and without treating its
    field 10 as the key fingerprint. Add a real-GnuPG case with a designated revoker and assert that the
    revoker's fingerprint alone never qualifies.
- **L2 (low, backlog):** `platforms/linux/src/local_commit_inspection.rs:222-226` and `:165`. The
  CleanupUncertain mapping from a `LinuxSandboxError`, in `result.outcome` or from `run_owned`, is not
  exercised.
  - **Problem.** Tests cover only a dispatch closure that returns a `LinuxLocalCommitError` directly. If
    either `capture_error(...)` were replaced by `denied()`, cleanup uncertainty would be silently
    reclassified and no test would notice. The verification module has the same pattern and it was accepted;
    the evidence discloses that the constructor was not widened.
  - **Fix.** Add a `#[cfg(test)]` crate-visible sandbox-error constructor, or reuse an existing test seam, and
    assert `CleanupUncertain` for `outcome: Err(CleanupUncertain)` in `validate_result`.
- **L3 (low, backlog):** `platforms/linux/src/local_commit_inspection.rs:58-68`. A keybox-daemon store is
  "unsupported" but not detected.
  - **Problem.** If the selected home uses `use-keyboxd` (`common.conf`, `public-keys.d/`) and still holds a
    stale `pubring.kbx` from before migration, capture pins the stale public material. A revocation or
    expiry recorded only in the daemon store is then missed.
  - **Impact.** Low: the keyring is user-selected, outside the repository, and the adapter is dormant.
  - **Fix.** Refuse capture when `public-keys.d` exists, or when `common.conf` enables `use-keyboxd`, with a
    test.

Inherited backlog (unchanged, still open): candidate initial-open failure coverage, and the earlier same-row
native, retained-child and fixture-teardown lows.
