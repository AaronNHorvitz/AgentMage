## Analysis

- **Collector** (`repository_base.rs:162-169`, `:116-122`):
  - The mode is taken from the `ls-tree` mode field of the exact base tree, read with
    `--no-replace-objects`.
  - Only `100644` and `100755` blobs produce a mode. Symlinks, gitlinks and trees are still refused
    before a mode is needed, and a blob without a mode fails closed (`ok_or_else(failed)`).
  - Index and worktree are not consulted, so a staged chmod cannot rewrite the base.
- **Planner check** (`coding_repository_commit_review.rs:297-317`):
  - For an existing base file, the candidate mode must equal `base.mode`. That mode is derived from
    the owner-executable bit of the live worktree file (`:258-275`).
  - A missing mode entry refuses (`is_none_or`). Operation IDs are strictly unique, so the
    `find` lookup is unambiguous.
  - New files keep the absence requirement and the exact `created_mode == permissions` check.
  - No caller-supplied mode, override, route, executor, grant or effect is added.
  - The check runs over every packet file before the group subset is filtered, so another group
    cannot evade it.
