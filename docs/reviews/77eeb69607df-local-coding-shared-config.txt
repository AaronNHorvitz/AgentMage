## Analysis

- **Approval cannot be bypassed.** `prepare_chat_shared` (`local_chat_transport.rs:489`) calls the
  ordinary `prepare_chat`, which runs `authorized()` (an exact endpoint equality check) before any
  encoding. It then moves the binding and the `Zeroizing` body into a `Shared` variant. A Rust move
  does not copy the heap buffer, so no unzeroized duplicate remains. `PreparedEndpointChat` has no
  Drop impl that the destructuring could skip. The execution paths reach the transport only through
  `Deref`, so there is no alternate dispatch logic. The test covers a wrong approval returning
  `Err(Approval)` with no socket.
- **No credential copy.** `LocalChatTransport` does not derive Clone. The `Arc` shares a single
  immutable instance (endpoint, optional key and limits, with no interior mutability). The only
  Clone-able object is `LocalChatApproval`, as before, and it holds no credential.
- **A request cannot redirect the run.** `for_coding_run_with_connection`
  (`coding_endpoint_context.rs:514`) still compares the sealed request's model selection with the
  retained transport's own selection. The owner's `entry()` still filters on the exact
  `request_sha256`. The new owner test shows that a request resealed with the same run id but a
  replacement destination is refused with `NotHeld`, leaves events unchanged and opens no connection
  on the replacement listener.
- **Release.** `release` sets `Held::Released` for both terminal and faulted slots
  (`coding_endpoint_owner.rs:242`). That drops the coordinator, and with it the shared connection.
  The weak-reference assertions confirm this for terminal runs. For faulted runs it follows from the
  same assignment. Spent identities remain, as before.
- **Local API.** The only change is storage: `Arc<LocalChatTransport>` and `Arc<LocalChatApproval>`
  inside the existing `Arc<Configuration>`. Every call site still auto-derefs to the same
  `prepare_chat`/`chat_with_usage`/`models` methods with the same approval. The settings handlers,
  consent and the operation lease are untouched.
- **Tool confinement** (workspace writes, command sandbox, network, confirmation) is not touched by
  this diff. No tool, permission, command or filesystem path changes. Escape surfaces that apply to
  this change are endpoint redirect, approval substitution, credential exposure in observations, and
  dispatch after a control stop or cancellation. The new socket tests exercise all of them, and I
  traced each one in the code. I wrote no further probes because no confinement code changed and the
  repository is read-only to me.
- **Evaluation integrity.** No evaluation, hidden or held-out test, scorer, threshold, ignore,
  dependency, model, GPU or scoreboard file is in the diff (final.py enforces exactly the 12 allowed
  paths). The `|` row lines in TASKS.md are unchanged (audit.py asserts this), so no row or sub-row is
  added or closed. Fixtures are labelled synthetic, and no score is claimed.
- **Honest labelling.** The guide (`docs/guides/runtime-endpoint-runs.md`, new section) and the
  evidence record both state that this is not a revocation policy. They also state that no HTTP
  route, filesystem or grant composition, recovery, edit/test/retry or score is established, and that
  the source gate still fails on T-301.1.
- **Delivery.** This is a single increment that runs and is measured, with no new sub-row and no
  plan-only change.

Forward-looking note, not a finding for this commit: once a service path constructs `Shared`, a
retained non-terminal run keeps the old transport and credential after settings are replaced or
cleared, because `release` refuses `StillRunning`. The HTTP composition must check current settings
revision and consent before each dispatch, and that check needs a socket test. Both the guide and the
evidence already record this as open.
