## Assessment of the requested points

**Bounded passive observer (prior L1).** `LinuxCodingCommandCancellation` now implements
`EffectCancellationObservation` (coding_repository_command.rs:70-78) and is passed whole into the
unchanged `CommandEffectDriver::new` (line 393-394, the only construction site). The kernel still
wraps it in `ScopedEffectCancellation` bound to the consumed permit's task/correlation identity, so
scope validation, cleanup and receipts stay with the kernel and runner. `observe_command_cancellation`
(lines 84-99) retries only `Unavailable`, at most 8 calls with `yield_now` between them, and then
returns `Unavailable` (fail closed). `InvalidSignal`/`ScopeMismatch`/`Ok` return immediately.
A poisoned mutex also yields `Unavailable` from `try_lock`, so it fails closed after 8 reads. The
table test (command_tests.rs:18-79) pins the call counts at 1/2/8/8/8/1/2. It never blocks and adds
no timeout. Correct.

**Control-only cancellation of repository and repair leases (prior L2).** `begin_scoped`
(lib.rs:781-797) sets `active_control_only` under the same `State` guard that publishes `active`,
so the requirement applies from admission, before any native handle is armed. Both repository
entry points use `begin_controlled`: coding_repository_api.rs:151, and coding_repair_api.rs:37,
which covers the GET preview and the POST proposal. `request_cancel` (lib.rs:222-230) returns 403
and records `cancel/denied` before calling anything, so no signal is latched and no attempt is spent.
Shutdown (lib.rs:364) still calls `cancel_active(true)` directly and is unaffected. With a
non-cancellable step the control token gets `Ok(false)`. `Operation::drop` alone clears the flag with
the lease (lib.rs:757-760). The real HTTP test (lib.rs:1725-1755) drives `handle()` over loopback
sockets. The client bearer gets 403 with the token uncancelled, the control bearer gets 200 with
the token cancelled, and the lease is retained. Correct.

**Terminal (cancellation reachability).** `coding_cli.rs:668` now selects the control token. `token()` only loads
files, so no prompt was added. The integration test runs the real `agentmage-code` binary against
a synthetic peer. It asserts that the request carries `Authorization: Bearer <control>`, that the
client token is absent and that the body is empty. As claimed, this covers the consumer only, not

## Findings

No critical, high or medium findings.

**L1 (low, backlog): status advertises a cancellation the client token cannot perform.**
`GET /v1/status` (lib.rs:1507) reports `"cancellable": state.active_cancellable`. During a
controlled repository/repair lease it reports `true` to a client-token caller, whose
`POST /v1/cancel` will now get 403. This is safe (no signal, denial recorded) but misleading to a
client-token UI. Fix: add `"cancel_requires_control": state.active_control_only` to status, or
report `cancellable` relative to the caller's token, and document it in local-chat-api.md.

**L2 (low, backlog): repair pre-encoding has no test of the call site.**
`repair_preflight_encodes_the_exact_combined_messages_and_refuses_wire_overflow`
(coding_repair_api.rs:148-183) tests `prepare_proposal_messages` directly. If someone changed
`prepare_repair`'s call (coding_repair_api.rs:140) back to `None`, every test would still pass. At
production caps (total ≤32768 bytes against `MAX_REQUEST_BYTES` 256 KiB) the two- and
three-message outcomes cannot differ over HTTP, so this is a regression guard, not a reachable
defect. Fix: factor the post-`select_created_sources` part of `prepare_repair` into a pure helper
that takes `(input, files, feedback)`, and assert that it refuses the oversized synthetic feedback.

**L3 (low, backlog): the bounded retry lowers, but cannot remove, the collision window.** If the
cancelling thread is preempted while holding the token's node mutex for longer than eight
`yield_now` calls, the poll still fails closed as `CancellationUnavailable`. That outcome is
documented and safe. The synthetic `CancelDuringExecution` executor (command_tests.rs:292-301)
still `.unwrap()`s each observation, so the cancellation test can still flake in principle, though
much less often. Fix: in the synthetic executor, treat `Err(Unavailable)` as "poll again" until the
deadline.

Observation (not a finding): the dated prior-batch evidence `docs/evidence/t303-command-cancellation-2026-11-06.md:30`
still describes the client/control cancel authentication as it was at d0bbe. It is historical, and
the current guides and this batch's evidence are accurate.

Environment note (not a repository finding): the node path given in the request is absent. The
hash-matched binary lives at `/lane/state/tmp/shared-node-v24.15.0/bin/node`.
