# AgentMage v0.4 Coding Acceptance and Recovery Bundle

## Status

**Draft and blocked. No package, coding workflow, interface parity, signing, or release approval is
asserted.**

## Candidate Scope

The proposed v0.4 delta composes deterministic repository comprehension, nine authority-free
declarative coding skills, evidence-backed planning, exact-preimage structured changes, owned Git
worktrees, separately granted trusted validation, complete review packets, optional signed local
commits, recovery, and a thin local CLI. Automatic remote publication and all hosted mutations are
excluded.

## Clean Acceptance Sequence

1. Verify exact package, source, dependency, policy, model, parser, skill, command, platform, and
   configuration manifests against independently distributed trust roots.
2. Confirm one admitted local model profile and exact model-family codec without network fallback.
3. Install in a clean supported operating-system image and verify package ownership, secure state,
   private IPC, platform sandboxing, cancellation, restart, and removal.
4. Run repository learning, diagnosis, bug fixing, feature work, test generation, review, rollback,
   and recovery on the complete fictional language corpus through native Chat and CLI.
5. Compare exact requests, kernel decisions, grants, receipts, citations, storage effects,
   cancellation, and terminal state across interfaces.
6. Attack worktree ownership, dirty state, stale preimages, project configuration, command
   injection, failed validation, unrelated changes, arbitrary shell, local commit, and every
   prohibited publication path.
7. Run accessibility, low-resource, offline, upgrade, downgrade, backup, restore, crash,
   concurrency, diagnostics, support, and uninstall campaigns.
8. Complete independent security, platform, accessibility, privacy, recovery, and release review.
9. Sign only the exact verified packages and gate decision after every dependency is current.

## Recovery and Downgrade

Stop new work after an uncertain stage. Preserve exact transaction, checkpoint, receipt, worktree,
candidate-tree, and branch identities without retaining unapproved content. Reconcile current
preimages, process termination, postimages, Git objects, refs, user index, remotes, and recovery
state. Never replay an effect or overwrite later user work. A rollback or downgrade requires fresh
review and authority against current state. Remove only AgentMage-owned worktrees, temporary
indexes, packages, state, sockets, caches, and model artifacts; preserve user repositories and
externally managed backups.

## Required Release Evidence

- current PASS decisions for Sprints 41 through 49 and every inherited dependency;
- an integrated coding coordinator and authenticated native Chat/CLI transport;
- exact parity across requests, policy, grants, receipts, evidence, storage, cancellation, and
  terminal outcomes;
- complete fictional multi-language, failure, exclusion, rollback, and recovery campaigns;
- a current admitted local model and deterministic-effect verification path;
- clean native acceptance on every declared release platform;
- complete accessibility, privacy, lifecycle, diagnostics, support, and removal evidence;
- completed manual fuzzing and independent boundary review; and
- independently verified signed packages and signed release decision.

None of these open requirements is converted to PASS by local contract tests or this draft.
