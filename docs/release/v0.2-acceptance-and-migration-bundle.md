# AgentMage v0.2 Acceptance and Migration Bundle

## Status

**Draft and blocked. No package, migration, downgrade, or release approval is asserted.**

## Candidate Scope

The candidate adds canonical knowledge inspection, plain-folder and Obsidian parsing/indexing,
deterministic retrieval, optional local semantic ranking, source-backed memory, encrypted
conversations and archives, redacted evidence bundles, task views and transition previews,
authority-free declarative skills, and eight read-only workflows.

## Migration Procedure

1. Verify the exact v0.1 source and installed package identity.
2. Build and verify a content-addressed canonical Markdown backup without applying changes.
3. Inspect the v0.2 layout migration preview by stable record identity.
4. Stop on duplicate destinations, unresolved links, changed source hashes, unsupported schemas,
   secrets, restricted content, or any proposed overwrite.
5. Install only an independently verified signed v0.2 candidate.
6. Rebuild all disposable lexical, Obsidian, and optional semantic indexes from current sources.
7. Compare record identities, canonical hashes, links, tasks, evidence, memory, and conversations.
8. Run offline, privacy, recovery, accessibility, and read-only invariance suites.

## Rollback Procedure

1. Stop AgentMage and retain the failed candidate evidence.
2. Verify the pre-upgrade backup and current destination snapshots.
3. Produce a restore preview; never overwrite a conflict.
4. Restore through a later separately approved file-operation boundary or manually outside
   AgentMage v0.2.
5. Reinstall the previously trusted package and rebuild disposable indexes.
6. Reconcile stable record identities and hashes before resuming work.

The current capability provides backup verification, restore preview, and layout-migration dry
runs only. It intentionally cannot apply migration or rollback writes.

## Required Acceptance Evidence

- exact source revision, clean tree, package hashes, signer, and trust root;
- complete local product, documentation, privacy, recovery, and zero-egress gates;
- native Chat workflow and accessibility evidence;
- clean upgrade, downgrade, and rollback on each supported platform;
- capability matrix, limitations, guides, support policy, and release notes;
- independent security, platform, accessibility, and release review; and
- signed release decision naming every accepted residual risk.
