# AgentMage v0.3 Acceptance and Recovery Bundle

## Status

**Draft and blocked. No package publication, migration, downgrade, signing, or release approval is
asserted.**

## Candidate Scope

The proposed v0.3 delta adds only separately approved controlled user-file writes: create, exact
patch, copy without overwrite, move without collision, trash-first delete, structured Markdown
update, and knowledge-record creation. Every operation requires exact preimages, complete preview,
single-use authority, fresh revalidation, postimage proof, receipts, privacy controls, and visible
recovery. Generic command execution, Git publication, network access, connectors, schedules, and
unattended mutation remain excluded.

## Upgrade Procedure

1. Verify the exact installed v0.2 package, configuration, store schema, workspace handles, and
   source revision.
2. Produce and verify encrypted operational-state and user-owned canonical-source backups without
   changing the source files.
3. Inspect the v0.3 package manifest, write-pack manifest, capability delta, signer, trust root,
   SBOM, provenance, and platform evidence.
4. Stop on dirty generated state, unknown staging, unresolved recovery, duplicate destination,
   changed source, unsupported schema, secret finding, protected path, or missing rollback proof.
5. Install only an independently verified package after the complete platform lane passes.
6. Keep the write profile disabled until configuration migration and startup evidence match the
   exact package and approved capability delta.
7. Rebuild disposable indexes from current canonical bytes.
8. Run read-only invariance, write transaction, privacy, crash, concurrency, accessibility,
   diagnostics, backup, restore, and uninstall acceptance.

## Downgrade And Restore

1. Stop new actions and preserve the exact failed transaction, checkpoint, receipt, and staging
   identities without retaining unapproved file content.
2. Reconcile every in-progress or uncertain write before package change; never replay it.
3. Preview restoration against fresh current preimages and preserve any later user conflict.
4. Restore only exact approved preimages through a fresh reviewed transaction or a documented
   manual recovery outside AgentMage.
5. Reinstall the previously trusted package and restore its compatible encrypted state.
6. Rebuild disposable indexes and compare canonical file, record, evidence, receipt, and task
   identities.
7. Confirm the downgraded profile is read-only and no write tool remains registered.

## Uninstall And Residue Check

Inventory packages, binaries, VSIX files, managed state, SQLCipher stores, keys, receipts, logs,
staging, backups, model artifacts, socket files, bookmarks or workspace handles, and user-owned
canonical files. Remove only product-owned artifacts. Never delete user-owned canonical files or
externally managed backups. Report physical-deletion limits for SSD and copy-on-write storage; do
not claim cryptographic erasure unless its exact key-scope assumptions were verified.

## Required Acceptance Evidence

- current PASS decisions for Sprints 35 through 39;
- exact package, source, dependency, model, policy, configuration, and write-pack manifests;
- create, patch, copy, move, delete, Markdown, and knowledge writes through every supported UI and
  platform with exact previews, grants, receipts, diffs, rollback, and privacy evidence;
- proof that write-disabled mode preserves v0.1 and v0.2 read-only behavior;
- prohibited generic shell, Git publication, network, connector, schedule, wildcard, bulk, and
  unattended-write results;
- clean upgrade, downgrade, backup, restore, uninstall, residue, and recovery campaigns;
- accessibility, diagnostics, support, and operator clean-run evidence;
- completed manual fuzzing and independent security, platform, accessibility, and release review;
- verified signed packages and a signed release decision naming every accepted residual risk.

None of those open items is converted to PASS by this draft.
