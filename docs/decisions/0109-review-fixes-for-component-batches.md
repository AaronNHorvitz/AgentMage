## Findings

An independent read-only review of `6a4359d2..28dd0e44` passed. It had two medium
and eleven low findings. R1: the hunk display escaped only control characters, so
it was weaker than the whole-file preview. R2: the two records cited as closure
evidence for AMR-04.1 and AMR-04.3 said that no task row closes. The low findings
cover these areas:

- Four module forms that the test-ownership scanner could exempt (R3).
- A codec validator that accepted a reduced source set (R4).
- A render overflow at a huge context value (R5).
- Hunk selection that did not itself check drift (R6).
- Contract wording for a displaced cancellation, and an untested `Exhausted` case (R7).
- Unbounded recoverability identities and text (R8).
- An accepted explicit null endpoint in a schema 1 plan (R9).
- Unconstrained query fields on visits (R10).
- A load-receipt cleanup that could not be retried (R11).
- Unreproducible record fields (R12).
- Four evidence cascades for four increments (R13).

## Decision

R1. The hunk display escapes each line as the whole-file preview's `{:?}` does:
control, format, line and paragraph separator, private-use, unassigned and non-ASCII
space characters, a leading combining mark, and backslash. Only tab and the two ASCII
quotes are shown as themselves. Correction, 2026-09-29: this fix used `str`'s
`escape_debug`, which escapes a grapheme-extending mark only at the start, so the
claim that it matched `{:?}` was inaccurate. [Decision 0113](0113-review-fixes-for-inspection-and-job-control.md)
(finding V2) escapes each character. Every displayed line starts with a marker, a header or
the missing-newline note, so no content can forge a line.

R2. Both records now name the row they closed, the closing commit and its
component-only scope, and each carries a dated correction. AMR-04.1 stays closed
because R1 is fixed in this batch, and its ledger row cites the correction.

R3. The scanner resolves children of a file loaded through `#[path]` or `include!`
beside that file, as the compiler does, and accepts raw identifiers. It treats three
forms as ambiguous: a `$` fragment or `mod` inside a `macro_rules!` body, any
attribute that names `path` other than the exact plain form, and a file whose
children depend on how it is loaded. Modules generated by procedural macros or build
scripts are outside a lexical check, and the Decision 0105 claim is narrowed to say so.
The exempted kernel set is unchanged at 14 files.

R4. When it validates the current tree, the codec validator requires the exact
current scan set and compares each digest with the file at the report's revision.

R5 and R6. Rendering uses saturating arithmetic for its context window. Selection
takes the current bytes and refuses drift before it uses any identity.

R7. `CancellationObserved` means that the run owner observed its own exact signal.
Only a `Cancelled` terminal establishes owned-descendant cleanup, and a `Failed` or
`Exhausted` terminal carries the deciding failure. A displaced signal before an
`Exhausted` terminal is now tested.

R8. Recoverability identities follow the change-record identifier rule. Created-file
paths follow the record path rule. The rendered declaration is capped at 64 KiB with an
explicit truncation line, and an empty session has its own summary. A write record's
seal is an unkeyed digest. Authenticity therefore comes from the canonical artifact
store and receipts that the caller owns, and the integration row records this.

R9. A research plan or scope decodes only from its canonical bytes. A committed
schema 1 literal pins the plan, policy and scope digests. The engine at `6a4359d2`
produced the same values.

R10. Decision 0106 now records the residual: a visit's query fields are not disclosed
queries. Before task-authorized issuance, AMR-03.2 must refuse non-empty query fields
on visits or require the plan to disclose them.

R11. When a load receipt fails validation, the controller keeps cleanup pending until
it gets a validated unload receipt. Legacy calls keep their error category. `unload`
may retry, the unvalidated tuple is never usable, and a new load refuses while
cleanup is pending.

R12. Retained logs, stage plans and results move to repository-relative paths with
root redaction. A committed tool reproduces the binding inventory and the stage and
log fields, with a check mode. The inventory reads both revisions from Git, so it can
be repeated after later commits.

R13. This batch groups these fixes with the next component increments and runs one
evidence pass.

## Verification boundary

Each source fix has a regression test. Each of these tests failed against the unfixed
source (R1, R3, R5, R9 and R11), or it covers a previously untested path (R7). No
model, GPU or native workflow was used. Independent re-review of this batch is
requested and remains open.
