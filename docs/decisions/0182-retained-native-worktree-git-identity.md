# Decision 0182: Retain the original worktree Git creation identity

| Field | Value |
| --- | --- |
| Status | Implementation detail under the accepted owner mission |
| Date | 2026-11-09 |
| Authority | Local agent mission; T-303/T-306; Decisions 0178–0181 |
| Scope | Historical creation provenance in the existing Linux repository owner |

Preserve the exact verified worktree-creation plan across its consuming native
dispatch. On success, correlate the canonical authority and specialized repository
receipts with that plan before retaining the created branch, immutable base and
receipt digests. Retain this nonserializable provenance only in the same live
repository owner, including its existing runtime handoff and return.

Expose a borrowed typed view after revalidating both held roots. Include an
authority-free historical description in the existing original-apply inspection
and exact diff preview. No new route or Git command is introduced. The description
explicitly disclaims current Git state verification and commit/publication
permission. Its branch and base describe the original creation, not current refs.

Synthetic test-created worktrees have no Git provenance. Reopening the canonical
authority store preserves receipts but cannot restore this owner, creation
provenance or execution. A path, terminal record, caller-supplied branch or saved
receipt cannot construct the typed view. Future candidate-tree and signed-commit
integration must independently verify current Git state, complete review-packet
provenance, preservation, signer and exact authority through existing contracts.
