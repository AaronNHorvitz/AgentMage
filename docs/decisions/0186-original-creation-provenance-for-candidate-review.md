Borrow the original filesystem approval from the kernel's opaque apply
authorization after grant consumption and its required checkpoint. Retain that
approval, the exact immutable creation plan and preceding write history before
native dispatch. Only checked successful native completion after publication
may return history with the new creation proof. Correlate transaction identity,
issued and consumed grant revisions, original approval binding, the complete
receipt chain, every destination, postimage and mode. Failed, uncertain,
unpublished or unsupported creation cannot restore preceding review proof.

Project nonempty UTF-8 source-code creation into the existing version 2 review
contract. A zero preimage denotes absence, distinct from an existing empty file.
The complete escaped diff starts from absence and retains the exact created
bytes. The original plan and operation hashes bind the creation mode and source
classification; original approval and application identities remain separate.
This projection is inert and creates no write or Git authority. Other already
supported native creation shapes preserve their transfer-lineage behavior but
cannot be relabeled as reviewed source.

Compose original creation and subsequent edits through the same bounded flat
history as existing-file retries. The original live owner must match every
path's first preimage, final postimage, fresh bytes and created mode, as well as
both held roots. An ordinary later edit cannot replace a missing original
creation proof. Candidate planning uses this complete original projection and
still requires sealed validation, current original/task Git observations and
the existing separate authority before any effect.

This changes neither terminal commands nor HTTP routes. Independent reviewer
and artifact provenance, candidate execution, approved Git effects, native/model
measurement and durable recovery remain open. T-303/T-306 remain open, with no
new row or sub-row and no self-approval.
