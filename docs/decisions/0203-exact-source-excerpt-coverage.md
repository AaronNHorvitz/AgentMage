# Decision 0203: Exact source excerpt coverage

| Field | Value |
| --- | --- |
| Status | Implementation detail under the accepted owner mission |
| Date | 2026-11-11 |
| Authority | Local agent mission; measure-first directive; T-303/T-306 |
| Scope | Effect-free repository context selection and proposal instruction |

The latest complete primary-model development measurement produced eight strict
edit refusals, the largest individual refusal cause. Inspecting their retained
development answers shows omitted boundary newlines, altered indentation,
ambiguous fragments and ineffective edits. These are proposal failures; their
task correctness remains unknown because native execution and grading admission
are blocked.

Supply parser-backed definitions as complete original lines. Merge overlapping
or touching selected ranges when the combined serialized message fits the
existing byte ceiling. A larger candidate, including a complete file, can replace
smaller retained ranges rather than being discarded for overlapping them.
Canonical path/offset order makes the delivered source easier to follow. Omitted
gaps remain omitted unless a larger candidate containing them fits. Existing
candidate, file, excerpt and serialized-message ceilings still apply.

Clarify the fixed proposal instruction: copy decoded source whitespace exactly,
include enough context to distinguish repeated fragments, and change every edit's
preimage. Preserve the strict checker unchanged. It must refuse ambiguous,
invisible, altered, overlapping, ineffective or stale preimages atomically; no
fuzzy matching, normalization or automatic repair is introduced.

Remeasure the development set after this batch. Keep partial-path proposal
acceptance separate from task passes, record changed context and output budgets,
and retain raw inputs/results privately for independent reproduction. Do not run
held-out tasks until a row closes. This decision creates no new row, permission,
tool execution, grading admission or release claim. T-303/T-306 remain open.
