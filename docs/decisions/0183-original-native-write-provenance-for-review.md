# Decision 0183: Original native write provenance for candidate review

| Field | Value |

| Date | 2026-11-09 |

| Scope | Existing-file review packets in the original Linux coding owner |

Retain the original approved shadow change set, write-approval binding and final
checked application-chain digest after the existing native transaction commits.
Correlate the issued grant revision, transaction, receipt chain and complete
verified operation/preimage/postimage set before retaining this process-only
proof. A serializable result or externally supplied receipt cannot construct it.

Project that proof through the existing kernel review change-set builder, using
caller-supplied purpose labels only. Require complete current edit lineage and
fresh source bytes under the same held roots. The native candidate planner must
compare the packet's entire change-set projection with this original projection
before any Git observation. Integrity-valid packets with substituted approval,
application, diff or change-set identities refuse.

Keep only the latest native prepared-edit transaction. It must cover the complete
existing-file lineage from first preimage to current postimage. Incomplete
cumulative coverage refuses; no aggregate approval is invented for retries.
Runtime writes and new-file creation do not yet retain this approval proof and
retire any preceding proof before native dispatch. Original apply also retires
it before dispatch. Denial and pre-dispatch expiry do not erase historical proof.
The same owner may carry it through an idle runtime handoff; restart cannot.

This authenticates write provenance only. Caller review findings, review
independence and artifact metadata still need provenance before candidate
execution. There is no candidate execution, commit, push, new approval, HTTP
route or terminal command. Exact native trust, permission and sandbox controls
remain in force. T-303/T-306 and measured model execution remain open.
