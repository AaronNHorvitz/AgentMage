# Decision 0178: Original diff review after terminal endpoint release

| Field | Value |
| --- | --- |
| Status | Implementation detail under the accepted owner mission |
| Date | 2026-11-09 |
| Authority | Local agent mission; T-303/T-306; Decisions 0156 and 0177 |
| Scope | Explicit development service continuation using the same original owner |

Offer explicit strict-edit and combined edit/test development variants that
retain the original repository after exact terminal release, on the same
loopback listener. Existing commands and library entry points keep their prior
behavior. No request or model field selects this service policy.

The existing owner must accept release before the original strict boundary can
be extracted. Its single-owner check refuses remaining preview, callback or
verifier references and poisoned state. Abandon pending native decisions without
effects or fabricated results. Hold the session lock throughout release and
publication, so no concurrent advance can retain or dispatch the old owner.
The original release drops the run, model connection and verifier. The HTTP
workers remain bounded and join at shutdown; there is no stopped-service restart.

Publish that same repository only to the three existing original-apply routes:
inspection, preparation and decision. Use their unchanged control authentication,
fresh explicit read consent, expected held-root identities, complete diff preview
and exact native approval. No creation, command, edit, new model run, attach,
endpoint settings or other manual route is enabled by this continuation.
Cancellation and the process stop latch are never reset. Release of a known
cancelled, failed or declined run establishes no passing test or task result.
Only successfully recorded edit lineage can become an apply preview.

Export canonical events before release; their original process-only retention
contract is unchanged. A lost release response requires inspection, never an
automatic repeat. Extraction or service errors can discard ownership. Process
termination cannot recreate it from a path or receipt. Native executable trust,
permissions, confinement and current source checks remain mandatory. No commit,
push, durable recovery, qualification, score or parent closure follows.
