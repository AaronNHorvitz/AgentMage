## Decision

Retain the closed research draft through the existing runtime artifact owner,
using a reserved media type. Recheck its complete sources under the canonical
owner's mutex before publication and every reconstruction. Never persist a checked
report as reusable evidence. Reopening supplies independently admitted native
identities and the current trusted clock; it recomputes the source table, accounting
head and cancellation or expiry disposition. It neither dispatches nor resets work.

Generic artifact publication cannot create this reserved format. Generic complete
reads and page reads cannot return its bytes, even while its sources remain live.
The canonical report reader is the content path. No preview is retained. Prevent
ordinary-media aliases of the same payload digest in either publication order,
using the existing artifact rows. These restrictions cover this typed format;
they are not a general information-flow or text-copy detector. Trusted composition
must not relabel derived text or publish a checked snapshot through another format.

Require private or restricted sensitivity, no effect receipt or producing operation,
and the original session, task, run and policy. The draft cannot lower any source
artifact's sensitivity. Retention classes must agree with every complete source
bundle member and be either session retention or explicit expiration; an expiration
cannot extend any source's deadline. Mixed classes and user holds are refused in
this first component rather than assigned an invented retention ordering. A source
release immediately prevents reconstructed content access. Physical collection
continues through the existing artifact lifecycle; this adds no deletion guarantee.

Publication retains the existing payload-before-metadata-before-event ordering.
The caller must record the exact full `ArtifactCreated` event through the existing
journal before the draft is readable. A crash before that event leaves an unreadable
artifact. Publication after a terminal run is refused. Reconstruction after a
terminal run is read-only and requires exactly one matching publication event.
There is no new database, event family, grant, completion receipt or execution loop.

## Verification boundary

Test source and draft release, expiry, corruption and missing bytes; generic read,
page and alias refusal; classification and retention restrictions; missing,
duplicate or substituted publication events; original context and native identities;
closed bounded decoding; cancellation, original deadline and restart. Preserve
canonical integrity poisoning and count/time work bounds. These are synthetic
component cases, separate from current native transport, provider, real-model,
manual-user, independent and release acceptance. Ordinary host research activation
and the Linux workflow milestone remain open.
