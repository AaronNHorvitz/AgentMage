Add an explicit catalog containing the two original native edit and command
contracts. Both definitions and argument validators are unchanged. New native
binding methods require that exact catalog; the existing single-effect methods
continue requiring their exact original single-effect catalogs. No arbitrary
catalog, subset, grant, executor, worker or manifest exception is introduced.
Trusted startup refuses the combined path if guidance disables either tool or
excludes any read scope, because the original confined test worker reads the
whole worktree. Other narrowing and resource ceilings remain binding.

Keep one original live repository inside the existing shared preview owner and
one cumulative endpoint coordinator. After an approved successful edit, the
trusted turn port asks only for a closed validation acknowledgement. It never
accepts a model-selected command. The original native owner prepares the
user-selected immutable validation definition, then requests its own fresh exact
protected approval. Native admission refusals remain refusals.

A failed validation stays held until the original classifier admits its exact
completed failure and consumes the original repair-feedback selection. Only
then may a consuming handoff return the same repository and exact consumed
feedback to the shared preview owner. Capture fresh selected source snapshots
and frame diagnostics as untrusted data for one strict repair proposal. Each
repair edit and subsequent test still requires its own exact approval. The
original parser, immutable validation series, prior-receipt linkage and maximum
three test attempts remain authoritative. No old preview, grant, selection,
clock, run or budget is reconstructed or renewed.

After a successful command, ordinary bounded completion context includes the
actual entire tool history. Only the caller's independent verifier can accept
the task; a process exit, parsed test result or model statement does not certify
current source or task success. Failure, uncertainty, cancellation, exhaustion,
invalid acknowledgement and lock poisoning cannot select another effect.

Expose this composition through an explicit trusted factory for the existing
local HTTP service. Existing authentication, observation access, per-advance
model-context consent, exact effect decisions, cancellation and release apply.
The controller must obtain consent covering the chosen sources, diagnostics and
actual tool observations that an advance can disclose to its selected endpoint.
No new wire field can supply a native owner, test definition or executor.
Executable selection, complete successful native/model workflow measurement,
durable recovery, approved Git and parent acceptance remain open. This record
adds no row or closure and does not qualify a coding model.

The existing coding verifier still rejects any non-success tool result,
including a prior failure followed by a full pass. This increment supplies no
replacement verifier or linked-pass supersession. That reviewed acceptance
integration remains open with the predecessor review's same-row low findings;
completion routing alone does not qualify a repair workflow.
