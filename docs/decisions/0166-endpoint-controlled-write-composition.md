# Decision 0166: Endpoint controlled-write composition

| Field | Value |
| --- | --- |
| Status | Implementation detail under the accepted owner mission |
| Date | 2026-11-08 |
| Authority | Local agent mission; T-303/T-306; Decision 0163 |
| Scope | Process-held shared coordinator and trusted host context |

Allow trusted hosts to compose the existing controlled-write runtime with the
configured endpoint transport. Reuse the original coordinator, scoped tool
boundary, exact approval validation, resource ledger, event publisher and
completion verifier. An endpoint selection changes model transport; it supplies
no effect authority and never impersonates an admitted native model profile.

Require every existing controlled-write budget, including full prepared-body
input coverage. Preserve catalog restrictions to workspace read/write and
bounded commands. Enforce the original tool-result and state-change rules,
uncertain-effect handling and verifier registry. Terminal sealing and verification
must accept the same process-held modes as composition, with original endpoint
claim and whole-envelope binding. Read-only mode never admits a write catalog.

The existing concrete context and retained owner may carry controlled requests
only with trusted original scoped permission/tool dependencies. The production
read-only startup, native file owner, authority policy and observation verifier
remain read-only. No worker manifest or sandbox admission changes. There is no
native write activation, journal hook, cursor resume, automatic effect replay,
new executor or permission system in this increment.

Synthetic coordinator effects and a loopback peer measure only shared runtime
and transport behavior. They do not establish successful native worktree
edits/tests, local-model coding, durable recovery, approved Git or a coding
score. T-303/T-306 stay open; no row is added or closed. Independent core review
is required.
