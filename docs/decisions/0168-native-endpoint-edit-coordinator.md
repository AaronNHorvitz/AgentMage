Adapt the original live endpoint edit handle to `RuntimeToolBoundary`. Retain
its complete sealed endpoint request, exact catalog definition, canonical call
and protected challenge. Native-family entry points refuse. The trusted caller
retains the original continuous run control and supplies its epoch clock.
Neither a model nor wire data constructs those dependencies.

Evaluation asks for the original exact decision. Resolution of Allow issues the
existing kernel write grant without writing files, and returns that grant's
actual binding digest. The original pending writer retains the grant privately.
Execution consumes it through the original single-use issuer, policy, preimage
checks and atomic transaction. Public direct application still issues and
consumes through that same path. No new permission system or writer is added.

Invalid scope, call, definition, challenge, response or evaluation is inert.
A matching stage retires before control or native dependencies, so denial,
stop, expiry, dependency error or unwind cannot reopen it. Execution observes
both the original control and the supplied cancellation probe before dispatch;
clock regression refuses. Atomic transactions remain non-interruptible after
admission. Returning the original owner drops any pending preview or grant.

Project the real terminal native operation-chain digest into the coordinator
result, with a descriptive receipt ID consisting of its transaction and sequence.
Retain the entire native chain and consumed-grant digest in the bounded output.
Committed, reconciled failure and uncertain outcomes keep their actual state
semantics. Output refusal after dispatch is uncertain and never restores replay.
These process-held receipts do not assert durable coordinator publication.

Synthetic creation and endpoint fixtures exercise real native writes and the
shared coordinator. They do not establish native Git creation, model generation,
test execution, verified task completion or a coding score. Controlled service
startup, general edit generation, tests/retries, durable recovery, approved Git
and measurements remain open. Native executable admission stays unchanged.
T-303/T-306 remain open; independent core review is required. No row is added
or closed.
