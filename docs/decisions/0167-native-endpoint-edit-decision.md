# Decision 0167: Native endpoint edit decision handoff

| Field | Value |
| --- | --- |
| Status | Implementation detail under the accepted owner mission |
| Date | 2026-11-08 |
| Authority | Local agent mission; T-303/T-306; Decision 0166 |
| Scope | Trusted library handoff of one original prepared native edit |

Connect an exact endpoint approval response to the existing native worktree edit
owner. Consume the live repository owner with its original prepared complete
diff; neither a path nor a caller-supplied creation receipt can adopt ownership.
Retain the original sealed controlled-write endpoint request and canonical call.
Require the original catalog, held workspace, native creation binding and exact
preview bytes. Every affected file must be explicitly mutable and outside the
request's protected paths. Trusted startup remains responsible for instruction
narrowing, original run admission and source/disclosure consent.

Use the existing protected challenge/response contracts, including the complete
native diff presentation and original writer's eventual approval/grant identities.
No grant is issued by construction or response validation. Only the original
native edit owner issues and consumes its existing single-use write grant during
dispatch, then performs and reconciles the original atomic transaction. No new
writer, permission system or fabricated runtime receipt is introduced.

Retain one non-cloneable decision handle. Invalid responses have no effect;
a matching decision spends the handle before observing the original run control
or invoking any native dependency. Denial, stop, error or unwind cannot reopen
it. The original epoch and monotonic preview expiry, preimage and link checks,
lineage invalidation and native result record remain authoritative. Atomic
transactions remain non-interruptible after admission. Return the original native
result, including its actual per-operation receipt chain, without asserting test
or task completion.

Returning the same live repository owner consumes the handle and drops its
pending edit. Preserve existing native results and successful edit lineage for
separately approved later work; never restore an old preview. This is in-process
continuation, not reconstruction or durable recovery.

This library boundary does not implement `RuntimeToolBoundary`, activate the
retained endpoint service, generate edits, run tests, certify completion, recover
a run or restore a grant. The coordinator's native edit/test adapter and trusted
controlled startup remain required. Tests use synthetic creation provenance with
real descriptors, native grants and atomic file writes; no native Git creation,
real model result or coding score is implied. T-303/T-306 remain open. Independent
core review is required; no row or sub-row is added or closed.
