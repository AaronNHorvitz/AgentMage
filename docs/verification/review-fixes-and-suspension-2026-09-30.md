## Change

The review fixes change the following:

- When a run has no job state, the CLI shows one closed reason for what it observed:
  the host offers none, the host did not answer, or the answer did not describe the
  run. Neither output format names a ledger any more.
- Each start rule of the host stands alone. A new run creates its job, so it never
  takes over an existing one. A run resumed after a restart starts a queued job,
  continues a running one and refuses every other phase.

The development host can now suspend a run and continue it:

- The runtime consults a suspension only right after a checkpoint commits, and
  only when no cancellation is observed there. It then stops, names the boundary
  and refuses to advance. A run without checkpoint ports never suspends.
- The host lets its worker stop only for a suspension the job ledger applied and
  the host has not withdrawn. It records the owner's observation and releases the
  run's composition. A request that could withdraw or cancel the suspension is
  decided after any stop the worker already committed to.
- A resumption, or a cancellation of the suspended job, continues the same run
  inside the host. The host closes the job's store handle, and the factory prepares
  the run bound to the boundary's cursor. The host checks that request against the
  one it derives itself and checks the restored history against what it presented.
  A cancelled job then ends at once with its own outcome.
- The IPC wire, now version 8, names the boundary in a suspended step. Every other
  step encodes as before.
- The CLI sends suspension and resumption as job control requests. It verifies the
  boundary, derives the resumed request itself and follows the run under it. The
  development CLI pauses on SIGUSR1 and resumes on SIGUSR2. The wrapper has `pause`
  and `resume` commands, and each answer, suspension and continuation is shown on
  standard error in both output formats.
