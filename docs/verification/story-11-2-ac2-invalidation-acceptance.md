# Story 11.2 AC2 invalidation acceptance

Story acceptance criterion `11.2.AC2` passes for the current durable runtime and encrypted
operational-store scope on Linux. One integrated resume test checkpoints a completed synthetic
read and then independently changes source, parser-output evidence, policy, exact model tuple, plan
revision, tool-catalog identity, and workspace/environment identity. Every changed request remains
contract-valid but is rejected as an invalid durable boundary before another model turn or tool
execution; the completed tool count remains exactly one.

Source lifecycle evidence independently proves that refresh invalidates the complete dependency
closure and that current extraction, section, cache-input, lexical-index, and context-disposition
views exclude stale sources. Parser identity, version, configuration, schema, policy, source, and
cache-key digests remain sealed in the source-cache record; changed parser output is represented by
changed authoritative evidence in the sealed work packet. Workflow evidence retains exact plan,
policy, tool-call, attempt, idempotency, receipt, and terminal identities, including immutable
uncertainty and single-attempt ordering.

The result uses synthetic data. It does not claim every later active parser/adapter integration,
cross-platform or installed-product execution, independent review, Story or Sprint completion,
packaging, or release readiness.
