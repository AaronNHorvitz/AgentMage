## Change

- The packet and each frame's metadata are accepted only as the exact canonical encoding of
  their decoded values: compact JSON in the declared member order. The worker refuses other
  packet bytes as invalid input, and the parent refuses other frame metadata.
- `PublicGetWorkerFailure` names the worker's eight closed failures, each with a stable code.
  The worker uses this engine type: it writes exactly its code and one newline to standard
  error and exits with status 5.
- The Linux parent reads such a report only as the failure's reason. The authority outcome of
  an attempt stays uncertain whatever the worker reports.
- The [contract document](../architecture/public-research-worker-contract-v1.md) states the
  roles, the request, the two frame versions, the failure report, the binding to the consumed
  permit, the consumer obligations and the dependency closure.
- `fixtures/public-research-worker/v1/` holds exact-byte fixtures that the engine's types
  build: two packets, three frames, the failure reports, one call-to-permit binding and a
  manifest. `scripts/public_research_worker_fixtures.py` compares them with what the engine
  builds, or regenerates them with `--write`.

The engine's contract tests check these properties:

- each fixture is byte for byte what the types build;
- each packet and frame decodes exactly;
- each of these is refused: a pretty-printed, reordered, spaced or escaped encoding of the same
  value, an added byte, an added member, a repeated member, and a number written another way;
- a frame decoded against the other packet is refused;
- each failure report decodes. Any other exit status or bytes are refused: no newline, a
  carriage return, a leading space, two lines, an extended code, upper case or an unknown code;
- the call binds its packet through the shared call validator, and changed argument bytes or a
  wrong digest are refused.

A Linux test checks that the parent takes a complete report under status 5 as the reason, and
keeps the generic reason for another status, a truncated capture, a missing newline or a signal.

Single mutations ran on the exact source tree before it was committed, nine in all:

- the packet's and the frame's exact-bytes checks;
- the report's exit status, a prefix-only match, a report without its newline and a changed
  code;
- the call validator's argument digest;
- in the Linux parent, a truncated report and an ignored report.

All seven engine mutations were caught. The two Linux mutations failed the intended test, but
the specification named that test under the wrong module path, so the first run recorded them
as not caught. A rerun with the corrected name caught both. The specification, results and rerun
are attached to the `batch26-source` stage.
