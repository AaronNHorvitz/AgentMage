## Change

Below each patch or creation challenge, the development CLI prints a hunk review of
the change the exact arguments make. The CLI reads the current file from inside its
disposable workspace and uses it only when its digest equals the preimage the
arguments bind. It plans the change with the host's own structured planner and
escapes the display under Decision 0107. A changed, missing or refused target, or
a change that is not bounded text, is reported instead of a misleading diff. Approval
still covers the whole call. After each run, the CLI prints the run's progress on
standard error: the terminal state, whether the runtime's verifier accepted the run,
and counts against the declared ceilings. It never reports independent review or
delivery as established.

AMR-04.2.2 is not implemented. Any denial currently ends a run as declined, so binding
a selection needs a runtime-proposed derived call or a follow-up run. That design
needs its own decision.
