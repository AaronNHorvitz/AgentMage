## Change

The review fixes change the following:

- A live runtime test decides a real control request through a durable ledger and
  then tests each job control completeness rule on its own. The history of a run
  resumed after a restart is not declared. A later decision recorded without a
  readable ledger head leaves the history undeclared (F1).
- The native preauthorized command test asserts its one entry: the reason
  `coding.preauthorized.succeeded`, the fresh grant, the preauthorization and
  receipt as evidence, and the issuance time. The native narrowed patch test
  asserts the narrowing refusal under the person's decision, followed by the
  derived write under its own grant (F2).
- The development CLI writes each run's result through one function over a writer
  pair. A test asserts that the export precedes the outcome, that the outcome stays
  the last line on standard output, and that an unavailable export leaves only a
  notice on standard error (F3).
- Each narrowing branch records its own refusal (N1). The effect digests are
  described precisely (N2). The testing guide names the range notice's reason
  correctly (N3).

AMR-05.9.2 connects the kernel router (AMR-05.1) to the development host:

- Before any model is built, the development runtime factory routes every model
  request of a composition through `route_gateway` in local-only mode. It offers
  exactly one route: the selected profile, class `strict_local`. The request allows
  nothing wider than strict-local, accepts no disclosure and carries no fallback or
  hybrid grant. If nothing is selected, composition fails before any model or tool
  is built.
- The router's receipt is declared unchanged. The host has its own type for it,
  which parses closed, with every member required. It has the same encoding, so the
  kernel digest recomputes over it; a test checks this. A one-entry route history
  records the selection under the person's decision, the exact run request, with
  the receipt and policy digests as evidence.
- Run declarations schema 3 carries the receipt and the route history over IPC wire
  version 10. As for the other parts, a run resumed from an event cursor declares
  neither.
- The development CLI keeps a receipt only if all of the following hold:
  - it names the run and its digest recomputes;
  - it describes a local-only selection of one eligible `strict_local` route;
  - it names no grant, provider or fallback;
  - its data classes are the declared ones.
- The CLI keeps a route history only when it replays and binds this run and the
  kept receipt. It shows both after each run, in text and JSON, and exports the
  route history with `--action-history-export routes:FROM:TO`.

AMR-05.9.3 connects the support bundle component (AMR-05.5) to the development CLI:

- `--support-bundle DIRECTORY` names an existing private directory. After the
  invocation ends, the CLI builds a content-free bundle from what it observed and
  previews a new file in that directory through the existing one-use diagnostic
  export workflow. The invocation may have ended with an outcome, a failure or a
  startup failure. The bundle holds the doctor report, component versions and
  evidence digests.
- The preview and a question go to standard error. Only the typed answer `yes`
  writes the file once. Any other answer, end of input or cancellation cancels the
  preview and writes nothing. `--approve-this-run` does not answer it, and a
  cancelled invocation is asked nothing. Nothing is uploaded, and the bundle never
  changes the exit code.
- The CLI does not probe the machine. Every doctor component it did not observe is
  reported missing.
