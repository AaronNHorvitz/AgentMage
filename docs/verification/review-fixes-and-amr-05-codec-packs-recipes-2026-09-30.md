## Change

The review fixes change the following:

- Replaying an action history refuses any kept entry that `append` could not
  have kept. That covers an identifier that was never redacted, a wrong
  redaction count, a malformed digest or evidence list, a reversed retention
  deadline and an effect without authorization.
- New tests isolate four rules: the issuer key a revocation list names, the
  export rescan, the identifier character set, and the previous link of an
  expired place.
- An expired place no longer keeps a deadline that no digest could bind.

Three AMR-05 components are new. None of them is used by a host, CLI or native
process yet.

- Offline documentation (CAP-22): versioned, licensed packs with sealed
  manifests, imported only from bytes already on the machine. They support
  explicit refresh, freshness inspection, retention of superseded versions,
  content-free deletion, and bounded fragments for the knowledge retrieval.
  The secret screen withholds flagged fragments. Nothing here uses the
  network.
- Language intelligence (CAP-26): a codec that frames and classifies a
  language server's JSON-RPC 2.0 messages and seals diagnostics, references and
  rename previews against the granted bytes. It keeps digests only and refuses
  file operations and overlapping edits. An empty answer is never presented as
  complete. It starts no process and applies no edit, and it claims no
  conformance to any server.
- Recipes (CAP-31): versioned, parameterized manifests with closed admission
  and rules for each kind. A recipe instantiates to a plan bound to the
  registered validations, with an exact digest. The plan only proposes; writes,
  commands and network access keep their ordinary approvals and grants.
