## Change

The review fixes:

- F1, in the types: the recipe parameter types `path` and `version`, the prerequisites
  `clean_worktree` and `locked_dependencies` and the rollback `revert_writes_only` have an empty
  member list instead of none. Their encoding is the tag alone, as before, so manifest seals, plan
  digests and the committed samples are unchanged. A member beside the tag is now refused wherever
  the types are decoded.
- F1, on the wire: every frame of the runtime transport is decoded exactly in both directions. The
  frame decodes into its types, and its re-encoding must equal the frame as received. A member the
  types do not name is refused at any position. The host answers such a request as a denied
  request; the client refuses such an answer as untrusted evidence. The new wire test adds a member
  at every object position of a prepare request with a recipe, a job control request, a shutdown,
  run declarations with every part, a job control answer, stored histories and a release. Three of
  those positions decode under the types alone: beside the tag-only `shutdown` operation, beside
  the tag-only `released` result, and inside a job control decision. Exact decoding refuses all
  three. The wire version stays 15, because no conforming frame changed.
- F2: the declared-plan test gains a resealed plan that differs only in its recipe identity, only
  in its version, only in its kind and only in its manifest digest. Each is refused.
- N2: the client keeps a declared plan only when each bound validation names a plain identity and
  a lowercase SHA-256 digest, and the registry digest is one too.
- N5: [LOCAL-TESTING](../LOCAL-TESTING.md) says that the plan's file bound counts each proposed
  path, approved or not.

AMR-06.1:

- [`docs/architecture/runtime-producer-contract-v1.md`](../architecture/runtime-producer-contract-v1.md)
  names roles only (Runtime, Coordinator, Memory, Host). It pins the versions, the transport, and
  for each record the members a consumer may rely on, what absence means, what the seal covers and
  the function that verifies it, plus the consumer's obligations.
- `fixtures/runtime-producer/v1/` holds eight records and a manifest of their digests:
  - a controlled-write coding run request held to the committed repair recipe sample, and that
    recipe;
  - run declarations with every part present and with every part absent;
  - a cancellation request, its answer and the job status after the owner stopped;
  - three stored, closed chains of an ended run.
- The host test module `runtime_producer_contract_tests` builds every fixture from the runtime's
  own types and functions and compares it byte for byte. It decodes each fixture exactly and
  verifies each as the client does. It refuses an added member at every object position, and it
  shows that a changed record is refused or dropped.
- `scripts/runtime_producer_fixtures.py` compares the fixtures, or with `--write` regenerates them,
  through an ignored test that only prints them. `tests/test_runtime_producer_contract.py` checks
  the manifest's digests and the document.
