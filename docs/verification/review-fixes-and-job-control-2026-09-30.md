## Change

The review fixes change the following:

- The store's writer authentication is stated as what it proves. No process without
  the store key can append, remove or reorder entries. A key holder is trusted as the
  owner.
- Every operational store connection turns recursive triggers on, and the runtime
  configuration check refuses a connection without them. A `REPLACE` of a ledger
  root, entry or head is now refused like a delete.
- New tests cover an append that names another head and a root whose first digest
  differs from the chain.
- The AMR-04.5 row and Decisions 0115 and 0116 point to the decisions that amended
  them.
- The lease tests that release and then acquire retry only `busy`, for at most two
  seconds.

The development host now drives job status and cancellation through the durable job
ledger:

- The host service records each run's job start before dispatch. It records the
  verified outcome as the job's terminal observation.
- The IPC wire, now version 7, has job status and job control operations and no
  direct cancellation. The host decides each request under a client scope that it
  derives from the authenticated peer. A client never names its scope.
- Only an applied cancellation stops work. Suspension, resumption and direct
  cancellation of a ledger-kept job are refused.
- The CLI cancels by reading the job status and sending a request that names the
  revision it observed. It retries a stale refusal a bounded number of times. It reads
  the job state before it releases the run, and shows the state and each control
  answer on standard error in both output formats.
