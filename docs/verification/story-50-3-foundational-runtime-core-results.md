# Story 50.3 Foundational Runtime Core Results

## Decision

The locally executable text/log and verified-workflow half of
`M-FOUNDATIONAL-RUNTIME-CORE` passes. This is an internal integration decision, not a product,
platform, model, parser, packaging, or release qualification.

The retained source-bound report is
[`report.json`](../../artifacts/sprints/sprint-50/story-50.3-foundational-runtime/report.json), with
the complete command output in
[`local-results.log`](../../artifacts/sprints/sprint-50/story-50.3-foundational-runtime/local-results.log).
Its mutation tests reject any attempt to turn an unavailable qualification into a pass.

## Integrated result

The Story 50.3 host fixture admits a dependency-ordered multi-file repository review, long-log
diagnosis, normalized structured-document comparison, and mixed-artifact planning workflow through
one `VerifiedWorkflowSupervisor`. The steps account for 2, 1, 2, and 3 exact prepared-source
manifests respectively. Each dependency-ready
step receives a fresh instance of the existing `ReusableRuntimeCoordinator`, consumes a current
prepared-source context, calls the production native artifact dispatcher, and returns a unique
tool call, grant, receipt, event chain, verifier result, and terminal outcome. The supervisor owns
ordering and retry eligibility; the common coordinator owns each attempt; the model, client, and
presentation sink own neither authority nor completion.

The fixture is intentionally deterministic and uses the admitted fake model. It proves the shared
composition seam and exact evidence lineage. It does not substitute for an installed client or a
qualified production model.

## Pressure, fault, recovery, and removal evidence

The core decision reuses current raw evidence instead of copying or summarizing an unbound pass:

- the bounded worker-backed runtime campaign processed 8,196 journal/publisher events, retained
  all 8,196 fast-client deliveries, handled seven saturation cycles, deliberately evicted one slow
  subscriber, and completed 16 exact reopens;
- measured ceilings were 1,024 queued events, 733,184 queued bytes, 53,996 KiB resident memory,
  and 10,813,336 retained disk bytes, with cleanup verified;
- the verified supervisor campaign covers dependency ordering, fresh transient retry, stale
  preflight, false completion, uncertainty, cancellation, resource exhaustion, interruption,
  restart without replay, and checkpoint tampering;
- eight clean-target component-removal builds independently exclude CLI, native Chat,
  workflow-caller, source-artifact, workflow-supervisor, combined source/workflow, combined
  foundational/client, and runtime-projection sources while retaining every applicable baseline
  and verifying the removed source units are absent from the compiler's emitted source set;
- every removal target passes its applicable test suite and strict Clippy, and the closed removal
  profile rejects undeclared features, packages, retained sources, or generated target residue.

These results are linked by the Story 50.3 evidence generator and are independently recomputed by
`tests/test_story_50_3_foundational_runtime_evidence.py`.

The same report consolidates current measurements for the 25 MiB text/log preparation boundary,
ingest throughput, extraction latency, first useful section, exact token allocation, peak resident
memory, retained-store growth, maximum queue depth, sixteen-cycle recovery, source cleanup,
delayed-store cancellation, and supervisor terminal diagnosis. Every measurement is paired with
its declared floor or ceiling, and validation fails closed if a bound is crossed. The underlying
fixtures also retain exact artifact-count/byte, event, output, memory, disk, process, checkpoint,
attempt, timeout, and cancellation boundary behavior. This remains local source/reference-host
evidence rather than installed-client or additional-platform qualification.

The companion security/fault report runs the inert prompt-injection corpus, active/archive-like
binary refusal, secret withholding, hostile/stale artifact results, approval and grant drift,
event-chain tampering, disconnect, uncertainty, false-completion, and retry defenses together. Its
100-seed no-unwind matrix covers source, context, proposal, preflight, approval, grant, worker,
receipt, artifact, verification, retry, recovery, checkpoint, and terminal boundaries with zero
effect replay. Structured active-document parsing is still unavailable; this result proves safe
refusal, not parser qualification.

Independent activation is recorded by
[`runtime-feature-activation.json`](../../architecture/runtime-feature-activation.json). Disabled
artifact ingress and retrieval register no native tool definitions, native participant and provider
compatibility use separate exact-boolean VS Code registration guards, and unavailable structured

The host rollout contract separately migrates an absent legacy setting to an explicit Disabled
generation, requires affirmative beta opt-in and limitation acknowledgement, gives rollback and
local emergency-disable state deterministic precedence, and keeps hidden retry, remote telemetry,
and network authority fixed false. Four product tests cover legacy migration, incomplete opt-in,
beta activation, complete monotonic rollback, verified and invalid emergency material, explicit
reenrollment, and the closed local post-release diagnostic shape. The post-release phase in this
campaign is a local contract rehearsal because AgentMage has not been released; an actual
post-release operator review remains unavailable and is not claimed.

## Explicit non-claims

This decision leaves all of the following open:

- production-model quality, grounding, latency, memory, and intervention evaluation, because no
  exact model/runtime/codec tuple is currently admitted;
- installed native Chat, CLI, and Verified Chat platform campaigns;
- DOCX, PDF/OCR, and XLSX parser qualification in their later owning sprints;
- Windows final-candidate validation, deferred macOS validation, and independent review;
- `M-FOUNDATIONAL-RUNTIME`, `G-V0.4`, packaging, signing, support, and release.

The core decision becomes stale when any bound source, runtime authority boundary, evidence report,
or declared limitation changes. Later parser or platform evidence must attach as separate exact
tuples and cannot inherit this local result.
