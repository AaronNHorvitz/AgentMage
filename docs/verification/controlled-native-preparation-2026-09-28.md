## Behavior and limits

Factory composition constructs an unloaded admitted candidate. The existing live
worker prepares it before context and exact token binding. Native manifest hashing,
load, readiness, serving checks, token binding, preflight and completion borrow the
coordinator's original run control. Local ceilings can shorten that budget. They
cannot renew it. Explicit controlled defaults refuse unsupported adapters before
legacy work. Legacy entry points retain their previous error categories.

A failed controlled preparation cannot be retried implicitly. Readiness checks the
startup deadline after a successful health reply as well as before the request.
Hashing checks control between bounded chunks. This remains cooperative: blocking
kernel calls are not preempted, and no hard wall-clock ceiling is established.
No idle approval timer, new worker, process owner, store, grant or wire field is added.

Native stop diagnostics do not authorize cancellation. The coordinator requires
its retained exact signal; foreign, failed or mismatched observations fail closed.
A port failure remains separate from a control stop. Actual returned stream results,
resource accounting and retained artifacts are preserved before later advancement.

Failed-start cleanup retains Decision 0095's exact ownership and lease proof.
Missing namespace or process ownership remains uncertain even when a CPU fixture
child was reaped. Failed-load unload receipts must match the exact profile and
adapter and report an empty runtime. Invalid receipts or unproved cleanup take
precedence over the original cancellation or expiry. No lease recovery is inferred.
