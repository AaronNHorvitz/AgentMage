## Change

- F2: a release whose run's effect record could not be closed still reported success, and the
  host forgot the run. Now the live service closes an ended run's stored chains (its effect
  record and its action history chains) when the client releases it. While a chain cannot be
  closed, the release is refused with `host.runtime.failed` and the run stays held. A later
  release, or the host's end, retries. The development CLI then prints `host.runtime.failed`
  and `cli.runtime.release_failed`, as for any refused release.
- F1: a run resumed after a restart keeps its chains open when its session cannot spawn or its
  job cannot begin. A test now shows both cases, and that a later host can still attach both
  chains.
- N6: a new run whose session cannot spawn closes its effect record empty. A test now shows it.
- N2: Decision 0143's Limits now say that a later host may also start a new run of the
  session, and that run's declaration is refused.
- D1: the Sprint 11 storage migration compatibility producer appended Cargo's output
  unredacted. It now replaces the checkout root with `<repository-root>`, and refuses retained
  output that names the checkout or a home directory, as its three siblings do since Decision
  0145.
