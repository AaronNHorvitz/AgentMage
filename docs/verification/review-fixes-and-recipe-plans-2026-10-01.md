## Change

The review fixes (Decision 0133, `e71970ed`):

- F1: the CLI parsing test gains a workspace scope beside a memory list, a documentation pack
  list, an ended-run read and a complete run. Each is refused only by the extension workspace rule.
- F2: a revocation list must name the identity under which the scope trusts its issuer key, as a
  package must name its signer's. A list that names another identity is refused as untrusted, and a
  stored list that does not match its trust statement is a store integrity failure. The
  accepted-list view shows the issuer identity. The extension sample gains `renamed.json`, signed by
  the trusted issuer key under another identity.
- N2: an installation time must name a day its month has.

Recipe plans (Decision 0133, `e71970ed` and `cd99ba03`):

- The CLI reads a recipe manifest from an absolute path without following a link. It admits the
  manifest with the closed parser, types each `--recipe-param NAME=VALUE` by its declared parameter
  and checks every value with the engine's new registry-free check. A recipe that needs a network
  grant is refused (exit 3), and any other invalid recipe or value is refused (exit 2). Nothing is
  launched before these checks pass. The CLI then shows the recipe on standard error. A recipe
  never goes with `--resume`, a session preauthorization or `--approve-this-run`.
- The prepare request carries the manifest and its typed values over IPC wire 15. A run without a
  recipe does not encode the field.
- The development host instantiates the plan against the workspace's validation templates. A
  declared validation kind with no template is refused with `host.runtime.recipe_denied`. The host
  binds the plan's digest into the run's constraints, and both host services refuse a request that
  binds a plan exactly when no recipe was sent, or none when one was.
- The tool boundary refuses each proposed write outside the plan's scope, or beyond its file
  bound, before any grant, session preauthorization or approval. It records the refusal as an
  unauthorized, denied entry of the run's action history. A write inside the plan goes to the
  ordinary approval. A run continued in the same host keeps its plan and admitted paths. A
  restarted host refuses to resume a run bound to a plan.
- Run declarations schema 4 carry the plan. The CLI keeps it only when it is the plan of the recipe
  it sent for this run, and shows it as text or a `recipe_plan` JSON row.
- The harness gains `recipe-sample`, which copies four committed synthetic manifests into a new
  private directory, and `start --recipe` with `--recipe-param`.

AMR-06 (Decision 0134, `eedf3604`): ten rows, of which AMR-06.1, pinning the runtime's
coordinator-facing producer contract as an unexecuted specification, is dependency-ready. The
others wait on pinned consumer contracts, network and account grants, the mediated network worker
or a native Linux host. No capability is implemented by it.
