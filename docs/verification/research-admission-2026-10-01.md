## Change

- `RuntimeResearchAdmission` binds three things:
  - a schema 2 plan that discloses through the network, decoded exactly from its canonical bytes;
  - the run's budget context: session, task, run and policy;
  - one public GET tool that declares a single network effect under a single-use network grant.

  Its digest covers the plan digest, the session, run and policy, and the tool definition's
  digest. It holds no grant and makes no I/O.
- The sealed request names the admission in exactly one constraint,
  `Research admission digest: <hex>`. The new constructor `new_with_research_admission` composes
  a durable read-only new run of the admission's own context. The catalog must hold the admitted
  tool once, beside ordinary read tools. Every other constructor refuses a request that names an
  admission, so the ordinary modes refuse network operations exactly as before.
- At start the coordinator does three things:
  1. publishes the plan as a run-level JSON report;
  2. flushes the journal;
  3. has the trusted `RuntimeResearchBudgetPort` open the budget for exactly that artifact.

  It continues only when the owner describes that plan, the admission's scope and an unspent
  first revision.
- Only the admitted tool may return a network result:
  - a success that changed state and is the six-member public GET completion, prepared through the
    borrowed builder under the call's receipt;
  - an uncertain attempt;
  - an outcome that changed nothing.
- The [coordinator architecture](../architecture/reusable-runtime-coordinator.md) describes the
  admission.
