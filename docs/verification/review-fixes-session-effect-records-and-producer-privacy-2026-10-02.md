## Change

- F1: a run's stored effect record could be closed as complete after it missed an entry. This
  happened when the store refused both the entry and the incomplete mark after it. A later run
  of the same session in the same host could then declare the session without that effect. Now
  every handle of the run shares what the host knows: whether an entry missed the store, and
  whether the store holds the mark. That includes the recorder, the handle the service closes
  and, across an in-host continuation, the run's next handle.
  - A refused mark stays pending, and each later append retries it first.
  - The service closes the chain only once the store holds the mark. Otherwise the chain stays
    open, so every later declaration of the session is refused.
  - Decision 0143's Limits sentence is corrected.
- F2: the three Sprint 11 store producers replace the checkout root with `<repository-root>` in
  the Cargo output they retain. They refuse retained output that names the checkout or a home
  directory. The content deduplication log committed in batch 29 named the checkout; its
  renewal here does not.
- F3: tests now show the service closing a run's effect record when the client releases the
  ended run, and when the service is dropped while it holds one.
- F5: a new run whose session cannot spawn, or whose job cannot begin, ran nothing, so its effect
  record and action history chains are closed empty. A run resumed after a restart keeps its
  chains open, so a later host can still resume it. Its chains are already marked incomplete.
- F4: the local testing guide names runtime producer contract version 3.
- N2: Decision 0144 states that an unreadable grant catalog fails the run's composition.
- N4: a resumed chain's session and task are checked before it is marked incomplete.
- N7: a catalog that holds one grant twice is refused. The test checks the factory's read and
  the owner's listing.
