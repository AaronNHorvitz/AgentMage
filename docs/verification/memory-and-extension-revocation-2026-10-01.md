## Change

Memory (Decision 0131, `025e3fd5`):

- Operational store migration 24 adds one table of owner states. Its triggers let a first state
  have only revision one, let each later state raise the revision by exactly one and refuse every
  deletion. The kernel store names its owners in a closed list and checks every digest at each
  open, load and export.
- The knowledge component encodes a memory catalog in the plaintext of its portable form and
  decodes it with every import rule checked again.
- The catalog host keeps one memory catalog. The person remembers an item that cites a kept
  documentation pack file; the existing candidate policy decides, and the invocation approves an
  eligible candidate. Items are listed with escaped text, revoked one at a time or by source within
  one workspace only, and deleted to a tombstone. IPC wire 13 carries the requests; the CLI's
  `--memory-*` operations and the harness `memory` subcommand reach the catalog host only.

The review fixes (Decision 0132, `709f8d7a`):

- F1: the CLI's pack reader applies the knowledge component's text rule to every file and refuses
  other text before any host is launched. A wire test shows the largest chunk of documentation text
  fits one frame and a chunk of other control characters would not.
- F2: an import is refused unless deletion records and kept versions together stay within the
  store's deletion bound, so retention, deletion and reads keep working when the history is full.
- F3: tests for a refused begin that discards a staged import, the host's own chunk bound and a
  version obtained after the last change.
- N3 corrects the store module's wording; N6 adds a head dated backwards alone.

Extensions (Decision 0132, `709f8d7a`):

- The catalog host keeps one extension catalog as the owner state `extension-catalog`, per
  workspace scope: trusted package signer and revocation issuer keys, the installed extensions and
  the revocation list the scope accepted last. Nothing crosses scopes.
- Every operation decodes the exact stored encoding and verifies every key, package and list again
  through the capability package component.
- An installation needs a trusted signer key of the scope, the license the person allows, the
  observed source digest, each dependency installed and active at its exact manifest, the host's
  contract versions, the signature and the scope's accepted list.
- A list must come from a trusted issuer of the scope, verify on its own, and be newer than, not
  forked from, the accepted list. The component marks revoked entries inactive, and an extension
  that depends on an inactive one goes inactive too.
- IPC wire 14 carries the requests. The CLI's `--extension-*` operations read files from absolute
  paths without following links. The harness gains `extension` and `extension-sample`. The
  committed synthetic sample's keys come from fixed, published seeds, and a unit test regenerates
  every sample file byte for byte.
