## Change

Review fixes:

- F1: the [producer contract](../architecture/runtime-producer-contract-v1.md) names the
  transport's four omitted members. The new one is an approval response's `selection`, which
  an `advance` request carries. The wire test refuses that request when `selection` is sent as
  `null`.
- F2: for the admitted tool, only a success carries output, evidence, an output kind or artifact
  candidates. An uncertain attempt, and a failure that changed nothing, carrying any of them is
  refused before anything is published.
- F3: the composition test adds a request of another task and one of another session. The
  budget test adds spent queries, spent bytes and an exhausted deadline.
- N1 and N2: Decision 0137 and the source comment say the plan digest covers the plan's whole
  canonical bytes. The AMR-03.2.2 row names reservation, grant consumption and dual-proof
  dispatch as the trusted port's obligations.

AMR-03.1.2.1 is a new engine test module. It composes the real coordinator, under the
AMR-03.2.2 admission, with the real owners:

- the encrypted store and its journal;
- the budget owner;
- grant issuance and consumption;
- the authority transaction with its start observer;
- the fresh-reservation dispatch proof;
- completion normalization through the coordinator's borrowed builder;
- the terminal commit;
- artifact publication;
- the canonical reader.

Only the native result is synthetic. It comes from a driver in `research_dispatch.rs`'s audited
test boundary, which checks both proofs and sends nothing. The payload store is in memory. The
trusted glue that implements the coordinator's ports over the owners is test code.

Composing them found one owner defect. The authority owner's terminal commit accepted any
sealed terminal. Suppose the glue handed completion a correctly sealed receipt under another
identity, with a transaction snapshot that named it. Completion accepted the agreeing
descriptions, and the owner committed a `ToolCompleted` that named a receipt it never issued.
The coordinator reported success, and the canonical reader refused the bundle. The owner now
commits a pending effect's terminal only when it names the start's call, turn and operation and
the receipt the owner issued. The journal already refuses a terminal that does not directly
follow the start in the same run, session and task. The store schema is unchanged.
