## Behavior and boundaries

The [API and terminal guide](../guides/coding-model-repair.md) specifies consent,
closed requests, diagnostics, byte reservations, budgets and recovery. Only the
native owner supplies the last normalized failed receipt and bounded output
excerpts. Native held-root and creation identity remain mandatory. The control
request cannot supply output, receipt bodies, roots or execution grants.
Source paths also require the existing workspace and endpoint-bound disclosure.
Failure disclosure separately binds the displayed feedback, receipt, endpoint
and settings revision. Unknown/duplicate/positional input, stale settings,
foreign workspaces, missing ownership and non-retryable failures refuse.

The request spends one process-local model selection per failed receipt before
network admission. A cancelled, failed, malformed or lost answer cannot restore
it. Invalid input and context/selection refusals do not spend it. This changes
no test attempt or immutable definition. After a separately approved edit and
test rerun, another failure can permit the next request, within the same three
test attempts. Edits do not reset either budget. A pass cannot request a repair.

The prompt adds a fixed untrusted-observation instruction and a separate JSON
user message. Its complete serialized bytes are reserved before ordinary source
selection. The ordinary proposal path's prompt, selection, request and context
event stay unchanged. The repair context reports exact combined message bytes,
the smaller source budget and exact feedback. The terminal checks these, accepts
only a complete checked proposal, then obtains separate read consent for an inert
owned diff. Exact write consent and fresh test approval remain independent.
No model output establishes success or grants an effect.

The retained channels are head/tail excerpts with raw-output hashes and explicit
lossy decoding/capture truncation. Failed-name selection is bounded and labelled.
Sensitive text can occur; the person sees exactly what will be disclosed. No new
secret-scanning claim is made. Successful tests retain no output excerpts.
Records, excerpts and spent model selections are process-only. Restart cannot
adopt a worktree from a receipt or replay an approval. Generation uses the existing
cancellation/operation lease and transport limits; it adds no cancellation of
native commands or write reconciliation.
