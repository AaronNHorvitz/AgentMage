# Selected-workspace coding MCP bridge

Decision 0161 adds `agentmage-mcp`, a bounded stdio interface to existing coding
HTTP routes. The [guide](../guides/coding-mcp.md) describes launch consent,
credential delegation, scope pinning and separate terminal approval. This is a
non-closing T-303/T-306 interface increment, not a new agent loop or model score.
Independent core review is required. The preceding commit remains immutable
while its separate review runs.

## Implemented boundary

The bridge loads only the ordinary client credential through the existing
descriptor-relative private-file checks. Trusted controls retain their separate
token. A delegated directory containing no control token is sufficient. Requests
cannot choose an HTTP route, credential, endpoint, workspace revision or approval.
Every tool checks the person-selected revision and random selection identity before using the
existing API, which checks the identity again before any source read;
file tools can narrow the already selected path set. The API still validates
source disclosure, drift, strict edits and operation budgets.

Six tools expose scope inspection, reads, literal search, one strict model
proposal, diff staging and pending-diff inspection. Staging changes only the
process-held proposal. The diff view excludes historical write records from
other scopes. Only the existing separate controls can approve a native write.
The workspace staging route does not establish transferable owned-worktree
lineage. Command execution, worktree ownership, commit/push, durable recovery,
documents and research are outside this interface increment.

The original stdio implementation uses the standard's 2025-06-18 wire profile
without an SDK or new dependency. It rejects duplicate object keys, batches,
invalid request IDs, premature tool calls and unknown tools/argument fields.
Notifications cannot dispatch tools. Oversized and unterminated frames end the
session. Replies have a separate byte bound. IDs cannot repeat and sessions have
a finite request count. HTTP calls are sequential, bounded and never retried;
there is no acknowledged in-flight MCP cancellation.

## Verification

The final source verification passed under one verified shared build reservation,
using two build jobs and four test threads. The unchanged fast-gate planner
selected `agentmage-local-api` and its full targets. Its six commands passed:
whitespace and untracked-file checks, four-file Markdown lint, formatting,
Clippy with warnings denied and complete source tests. The eight test targets
passed **118 tests, zero failures, zero ignores and zero filtered tests**.
Formatting took 0.20 seconds, Clippy 8.42 seconds and source tests 18.82 seconds;
the six commands totalled 28.79 seconds, excluding the shared reservation wait.
These are warm-cache measurements of this selected crate, not a workspace-wide
or native-host qualification. The deferred host executable-trust blocker is
unchanged.

Before the full gate, four protocol methods passed (28 other library methods
filtered only in this focused run), and the complete terminal target passed all
14 methods without skips. All eight new methods also passed in the unfiltered
full gate. The executable/API component used a delegated directory with no
control token: it read an approved file, refused an unselected file, staged a
complete diff and returned that pending preview. Files remained unchanged.
The separate existing controlling-terminal approval then applied the exact
native write and preserved the unrelated file. The MCP subprocess portion of
that component took 0.038004 seconds; that timer excludes the later terminal
approval and is not an owned worktree or model-workflow measurement.

Additional cases exercised the real API with a synthetic local model server,
using the real terminal source-disclosure approval first. The proposal was
complete and inert, with no pending write automatically staged. A new service
reused a numeric revision but had a different random selection identity; the
bridge refused the old pin. All four file-operation routes refused a stale
identity at the actual API owner before source use. Existing revision-only
clients passed the unchanged compatibility tests.

The first focused run passed all four protocol cases and 13 terminal cases,
but one new setup sent a GET body the API correctly refused. The test was fixed
to use the real terminal consent flow, without changing the handler, assertion,
threshold or existing tests. Both raw runs are retained in private lane scratch
and named in the independent review request. Two earlier redundant owned slot
waiters were cancelled before running checks. No source changed after the final
source freeze; final prose received separate lint and hygiene checks.

Tests use synthetic sources and a local socket model stub. They do not execute
a real model or an owned repository coding campaign. No GPU reservation, task
input, hidden test, held-out task, threshold, dependency output or status-model
promotion is part of this change. Parent coding measurements and acceptance
remain open.
