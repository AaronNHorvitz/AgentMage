## Change

The new [suite runner](../../scripts/coding_eval_suite.py) binds the original
30 development definitions and a separate private ten-task held-out descriptor.
It checks all source, hidden-test and fixture pins and refuses a held-out
reference already present in a development editing projection. The development
fingerprint, all 89 original development methods and every old test/fixture pin
remain unchanged. The held-out descriptor pins 52 complete original methods
from ten distinct historical changes. No original hidden test is edited.

All ten held-out tasks are Python evaluation-protocol repairs in the same
worker module. This deliberately limited tooling coverage does not establish
application-coding quality. Original code/tests come from this repository's own
history; no external dataset or dependency is added. Statements and public API
signatures were audited before the final freeze and before any control/model
attempt. The initial draft commitment and final commitment are retained
privately; source/test pins and method selections did not change in that audit.

[Operational instructions](../guides/coding-suite.md) describe the commitment,
private storage, reproducibility and output boundary. `check` runs no held-out
assertion. `verify --purpose row-close` assembles all development, independent
development and held-out historical controls with private per-task logs and an
aggregate printable summary. It accepts only frozen control IDs/kinds, never
generated bytes or test overrides. That full command has **not** run in this
increment: held-out execution stays reserved for row closing. A synthetic unit
contract exercises its complete orchestration without loading a held-out test.

## Observed verification

The shared build reservation was used for full selected unit tests, the real
input check and both fast-gate runs. Three small host refusal spot checks passed
in 0.002 seconds while the reservation was queued; they are not a full gate.
A superseded initial queued reservation was cancelled before executing tests.

The initial selected unit run executed 15 tests in 0.010 seconds: 14 passed and
one errored because a newly written synthetic leakage fixture omitted pin
fields required by the checker. Its fast gate also failed. The old snapshot and
both failed logs remain retained. Only that synthetic runner test fixture was
corrected; no frozen or hidden task/test changed.

The final scoped fast gate passed, including all 15 runner tests in 0.009
seconds, Python checks, whitespace and Markdown checks. The real input check
passed in 2.084201 seconds: 30 development tasks, ten held-out tasks, 52 held-out
methods, zero held-out methods executed, zero model attempts and null model
score. Checkpoint Markdown and the ledger were linted again after writing this
record. Neither command uses a GPU. No full repository policy scan, native
platform qualification or long acceptance gate is claimed.
