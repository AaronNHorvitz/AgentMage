## Behavior and authority

The [command guide](../guides/coding-commands.md#sandbox-and-results) describes
status, requesting cancellation from another terminal, receipts and recovery.
The exact pending command preview supplies an opaque cloneable handle bound
to its digest and unique command attempt. The native owner refuses a foreign
handle before consuming consent. The API publishes the matching handle under
its existing operation lease, then releases the service mutex before native
execution. A prior cancellation or shutdown observed at handoff is latched
before that handle is passed to the driver. Model data cannot create or select
one of these handles, approve an action or reset its signal. User and shutdown
reasons remain distinct; repeated requests preserve the first signal.

`POST /v1/cancel` keeps its existing client/control authentication and empty-body
contract. Its acknowledgement means requested, not stopped. Both explicit
cancellation and orderly shutdown use the same forwarding path. The operation
keeps its lease through execution, descendant cleanup and receipt processing;
competing effects, settings and scope replacement remain excluded. Completion
clears the handle before another operation can begin. An old handle cannot
cancel a fresh attempt. Preparation, worktree creation and writes remain
non-interruptible and cannot acknowledge live cancellation.

The unchanged kernel command driver observes the exact task/correlation signal
before launch and through the existing confined runner. After dispatch admission,
a pre-launch cancellation consumes the exact authority and records cancellation
without entering the executor. A live cancellation requires verified descendant
cleanup for a completed command receipt. Unknown cleanup stays canonical
uncertainty with no invented command result. Output remains bounded untrusted
bytes. No sandbox, executable trust, timeout or resource check is weakened.

Validation uses the same path. A dispatched cancellation spends an attempt,
never passes, and cannot select failed-test repair or rerun eligibility. Denial
spends no authority or test attempt. Cancellation cannot restore an approval,
make a command repeatable or claim the repository is unchanged. Canonical
content-free receipts survive reopening; process-only ownership and previews do
not. Abrupt termination and lost replies still require manual inspection.
