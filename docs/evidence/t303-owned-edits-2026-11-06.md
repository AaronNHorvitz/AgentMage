## Behavior and limitations

The [API and terminal guide](../guides/coding-owned-edits.md) describes the closed
request and approval shapes. All owned-edit routes require the control token.
The request supplies exact relative paths, all complete expected source hashes,
the task, message-byte budget, strict answer and explicit read consent. It cannot
supply a root or creation receipt. Only the native owner selects the held created
root; foreign scopes, replaced roots/management directories and changed creation
provenance refuse. Selected-workspace routes retain their prior independent scope.

Both edit routes now use the same complete-source hash and strict-fragment
checker. The owned preview additionally hashes the creation receipt, held root,
complete inner kernel diff and hashes, creation/expiry times and warnings. A
fresh exact outer-preview decision consumes it once. Denial does not write;
failed preparation preserves the existing preview. The existing native driver
rechecks changed-file identities and preimages around replacement and reconciles
partial failures. It refuses unselected paths, metadata, links and new files.

Dispatch invalidates pending command/validation approvals. It preserves the
immutable validation definition, spent attempts and prior result; writing cannot
reset their budget. Validation still describes one command envelope and claims
neither current-source nor full-suite correctness. `propose-worktree` connects
the unchanged complete model-proposal path to this owned preparation with separate
read consent, followed by a later exact diff approval. It does not automatically
write, test or retry. No prompt, context selection or model setting changes.

The owner records dispatch and retains the latest native write result before
reply. Those records are process-only, using the existing writer rather than
claiming canonical durable write integration. Restart loses ownership and edit
state; no receipt or caller path restores it. A post-dispatch boundary failure
reports uncertainty. A lost reply or crash requires manual inspection, never
an automatic effect retry. Cancellation cannot interrupt a consumed native write
transaction midway through reconciliation.

Native-owner tests use explicit synthetic creation provenance and real fixture
file writes. These do not demonstrate native Git worktree creation. Native
creation and commands remain subject to the unchanged executable-trust refusal
in this lane. Terminal tests use a synthetic HTTP peer, including its successful
