## Running behavior

The [independent oracle](../guides/coding-evaluation-oracle.md) now runs four
existing frozen development tasks in separate candidate/assertion namespaces.
The added dev-010 and dev-012 functions classify Rust source text supplied as
JSON; they do not read a shared fixture tree or run Rust. Returned paths must
be unique members of the input mapping. One literal ambiguity tag reconstructs
only the frozen module's own exception with a fixed message. No candidate
exception name, argument, traceback, executable expression or class executes in
the assertion process. All seven selected original methods remain unchanged.

Before loading hidden assertions, the oracle requires an exact startup frame
sent after the candidate module imports. Missing/malformed startup retains a
zero-assertion infrastructure record. A failed namespace launch or import can
no longer count as a successful failing-base control. The verifier additionally
requires exact historical base failure/error/call profiles and reference call
counts; an arbitrary protocol failure cannot validate a control.

| Task | Base methods / failures / errors | Base calls | Passing reference methods / calls |

| dev-012 | 4 / 10 / 0 | 12 | 4 / 14 |
| dev-015 | 1 / 1 / 0 | 3 | 1 / 4 |
| dev-029 | 1 / 0 / 1 | 1 | 1 / 6 |

The ten failures in dev-012 include subtests. Dev-029 deliberately lacks the
function in its base; after successful import it records a protocol failure.
Its failing oracle can exit 120 during broken-pipe shutdown after writing counts;
that remains failure, alongside exit 1. Every reference exits normally with no
failure, error, skip, expected failure or unexpected success. These are four
historical controls, seven regression methods and 28 reference calls, not model
attempts or unseen tasks.

The 31-test suite includes actual separate-process forgery and launch probes.
Replacing only each base's candidate command with a failing system executable
makes all four pairs invalid while their real references still pass: zero
assertions, zero calls and infrastructure failure for every affected base.
An import error or false startup frame also runs no hidden assertion. Path
probes cannot patch trusted assertions, supply foreign paths or replace correct
returns with universal ambiguity. Unit checks refuse duplicate/foreign paths,
arbitrary exception envelopes, wrong startup types/fields and retries after
protocol failure. The expected ambiguity can be followed by a normal call.
Existing interruption, timeout, output, cleanup and generated-refusal checks pass.

An initial queued gate ran before expansion expectations were complete and
failed three checks. Its old two-task expectation and unpinned new profiles were
corrected; its launch-fault helper was also corrected to distinguish a task's
base from another task's identical reference source. The command's stdout was
not saved as a standalone raw log; a private observation records the failure.
All subsequent measured commands retain raw logs. An initial audit helper used
the Rust reference instead of its distinct hidden revision; the corrected audit
checks the existing hidden-revision and corpus pins without changing inputs.
