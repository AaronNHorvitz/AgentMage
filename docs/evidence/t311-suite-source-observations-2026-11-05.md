candidate bytes, rather than accepting a candidate claim of invariance.

non-inheritable. Trusted fixture Git children write diagnostics to their bounded
log, keeping the request pipe valid. The diagnosis method retains complete
owned-non-model-child lifecycle fixtures; it performs no model inference.

## Limits

Diagnosis uses trusted process-argument observations. It does not establish the
candidate's ownership, setup or reservation implementation. The identity adapter
checks source identities through real temporary Git files and inert FIFO nodes;
other harness functions and acceptance helpers remain trusted baseline helpers,
with no claim to grade their candidate implementations. Model-choice
membership/order, unasserted closure fields, attachments, effects outside the
retention target, exact exception subclasses and concurrent fixture mutations
remain ungraded. The guide and reports disclose these limits. Candidate code
never executes in the trusted assertion interpreter.

The ordinary worker unit module remains deferred intact to the row-closing
batch because it overlaps frozen held-out selections. Preliminary development
checks use the separate adapter module; this is not the complete ordinary fast
gate. Remaining independent adapters and accounting/admission obligations stay
in T-311.17. Parent T-311 and the T-311.18 baseline stay open.
