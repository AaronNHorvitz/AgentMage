## Running behavior

The independent [T-311.24 core review](../reviews/58f04577e07c-local-coding-t311-24-usage-oracle.txt)
is retained byte-identically with **Verdict: PASS** for its exact commit; only
that row closed. This batch addresses its low findings L1-L3 without selecting
another task or changing an original hidden method.

Oracle v24 sends a bounded message-root handle per candidate adapter instance.
Repeated use of the same message list retains its candidate-side list identity;
equal but distinct lists receive distinct handles. Positional and keyword calls
share that registry. Updated trusted contents replace the saved root in place.
Handles are exact integers in the existing call budget; constructors and non-list
arguments cannot supply one. Typed values remain inert and size-bounded.

Replay accepts only an exclusively owned inert transport mock. Sharing a mock
between two adapters is a sticky adapter-policy refusal, including when its
history is empty. Unowned existing history, transport replacement, side effects
and wrapped targets are refused before sending another request or erasing any
history. The target is checked again after validating the complete response,
before cumulative replay. Refusal stays sticky after a caller catches it or
resets mock history. This does not run a transport or model.

The [guide](../guides/coding-evaluation-oracle.md) distinguishes root identity
from unsupported nested identity, equality subclasses and propagation of candidate
message mutations to trusted inputs. Those remaining limitations can change
verdicts and require disposition before generated admission. Shared transports
are refused rather than merging their histories. The unchanged selected methods
never require a shared transport or effectful mock.
