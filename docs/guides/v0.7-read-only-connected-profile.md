# v0.7 Read-Only Connected Profile Guide

The v0.7 candidate remains blocked and unreleased. Its local contracts define a temporary,
user-initiated connected profile for exact GET/HEAD reads; exact GitHub host/account/app,
installation, repository, read permissions, SSO, expiry, credential reference, and transport
binding; immutable hosted evidence; read-only triage; and local-only pull-request review packets.

Before any request, show destination, purpose, scope, expected data, byte/time limits, credential
reference, and cache partition/retention and require exact approval. Treat every returned value as
untrusted, sensitivity-labeled content. Retain immutable source, freshness, permission/coverage,
and receipt identities. Partial, stale, rate-limited, revoked, cancelled, or uncertain outcomes
cannot silently retry or claim completeness. End every operation by invalidating derived credential
material and restoring strict-local mode. Cache persistence must be encrypted, partitioned by
account/workspace, bounded, visible, and deletable.

No executor, account, credential derivation, cache writer, background worker, hosted write, or
release approval exists in the current product. Disabling or removing connected packs therefore
leaves the existing strict-local registration surface unchanged. Native packet, credential,
provider, cache-cleanup, offline-return, cross-platform, and signed release evidence is still
required before this candidate can be enabled or described as supported.
