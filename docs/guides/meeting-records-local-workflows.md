# Meeting Records Local Workflows

## Preparation Draft

1. Select already-approved local source records.
2. Record the purpose, participants, topics, decision needs, preparation, and expected outputs.
3. Leave invitation and attendance unknown unless an exact source confirms each state separately.
4. Seal the local draft and review its sources and limitations.
5. Use a separately authorized provider workflow for any invitation or calendar operation.

```markdown
# Meeting Draft

## Purpose

## Participants and Observed States

## Topics

## Decision Needs

## Preparation

## Expected Outputs

## Unknowns, Limitations, and Sources
```

## Source-Preserving Cleanup

Keep each verbatim note or transcript segment unchanged. Put cleanup text beside the source rather
than replacing it. Retain supplied UTC timestamps, label speaker attribution with its evidence state
and confidence, and mark unclear language with exact source offsets. Missing time or attribution
stays missing or unknown.

```markdown
# Source-Preserving Cleanup

## Verbatim Segments

## Cleanup Proposals

## Timestamps and Attribution

## Unclear Language

## Sources
```

## Minutes Review

Separate confirmed decisions from proposals. Review every action, question, risk, and next-meeting
item against its cited source. A missing owner or date must be displayed as unknown. Sealing minutes
does not assign an owner, create a commitment, notify anyone, or add a calendar event.

```markdown
# Meeting Minutes Draft

## Confirmed Decisions

## Proposed Decisions

## Actions, Owners, and Dates

## Questions and Risks

## Next Meeting

## Unknowns and Sources
```

## Closeout and Recurring Continuity

Closeout reports counts from exact sealed minutes. It highlights unknown action owners and dates and
the number of open continuity items. Recurring continuity preserves open actions, questions, and
risks until an exact later source updates them. A missing item is not treated as complete.

The follow-up is a local draft only. Review recipients, claims, names, dates, attachments, privacy,
and source evidence in the separately controlled correspondence workflow before any provider action.

## Refusal Expectations

Reject or return an explicit limitation when a request would:

- infer acceptance from attendance, attendance from acceptance, or either state from silence;
- replace or silently normalize the verbatim source;
- invent a speaker, timestamp, owner, date, decision, action, or completion state;
- promote a proposed decision to confirmed without exact evidence;
- use a meeting record to invite, assign, notify, send, schedule, or mutate a source;
- broaden local source, privacy, network, workspace, platform, or completion scope.
